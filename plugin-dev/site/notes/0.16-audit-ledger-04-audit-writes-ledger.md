# 04 — audit-run writes the ledger

Phase 04. `audit-run` stops writing a gitignored `report.md` and writes the committed record
instead: every ERROR and WARN except `platform`, and every `definition` NOTE, becomes an issue
(new, or a sighting of an existing one, decided through `issues.py candidates`); the report is
`audits/runs/<date>-<id8>.md` from the template; the `audits/` files go in one commit; the
eval log shrinks to the ids by outcome and a link. It closes the "report can't be found from
another chat" gap. Prior issues are phase 7: here the report's **Prior issues** section says
`none`.

## Decisions

- **The workspace `report.md` is no longer written.** The run report under `audits/runs/` is
  the report. Reason: two copies of the same findings; the committed one is the one another
  chat can find.
- **Matching is the skill's judgment over `candidates`' list**: same `rule_file` and `fault`,
  then the quoted rule text compared by eye; a different quote is a different issue. Reason:
  line numbers drift, the quote does not (design).
- **The audits commit stages only `audits/`**: `git add audits && git commit -m "<msg>" --
  audits`. Reason: the checkout may hold other work.
- **A plugin directory outside a git checkout** (a cache copy, a fixture) still gets its
  `audits/` files written; the skill prints the commit message it would have used and says
  the commit was skipped. Reason: the record is the files; the commit is how they travel.
- **Finding ids in the report** stay `E<n>`, `W<n>`, `N<n>` within the report; the issue id
  sits beside them in the heading. Reason: the design's heading form.
- **In phase 4 the user is still offered the edits** for `definition` faults at HEAD, as today;
  phase 6 replaces that offer with "type `/plugin-dev:fix-issues run:<id8>`". Reason: no skill
  names a command that does not exist yet.

## Specification

### `skills/audit-run/SKILL.md`

- After the `T` line: `` `I` is `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/issues.py` (the ledger: `templates/audits/issue.md` is the shape of what it writes). ``
- §5 **The report**, steps 1–3 as today, then:

  4. **Issues.** Each finding that is an ERROR or WARN with a fault other than `platform`, or
     a `definition` NOTE, becomes an issue. For each: `I candidates --rule-file <rule file>
     --fault <fault>`. If a listed issue's `rule_quote` is the same rule as this finding's
     (the same sentence, whatever its line number now), it is the same issue: `I seen <ID>
     --session <id8> --version <version> --date <today> --unit <unit|seg-n|cross> --step
     <step> --evidence "<short quote>" --report audits/runs/<date>-<id8>.md --finding-id
     <E1|W1|N1>`. Otherwise `I new …` with the same Found in fields plus `--title` (the
     finding's one line), `--fault`, `--severity`, `--check` (the auditor's check word),
     `--applies-to` (`agent:<type>` for a unit, `driver:<command skill>` for a segment,
     `cross` plus the agents named for a cross finding), `--rule-file`, `--rule-line`,
     `--rule-quote` (from the finding's `Rule:`; `none` for a cross contradiction),
     `--found-version`, `--found-session`, `--found-date`, `--finding`. Record each finding's
     issue id and whether it was new or seen. Other NOTEs get no issue.
  5. **The run report.** Write `audits/runs/<YYYY-MM-DD>-<id8>.md` from
     `${CLAUDE_PLUGIN_ROOT}/templates/audits/run-report.md`: its headings in its order, each
     E and W heading and each `definition` N line carrying the issue id and `(new)` or
     `(seen)`, the **Totals** line with `issues: <n> new, <n> seen again · prior: 0 held, 0
     recurred, 0 not exercised, 0 not testable`, and **Prior issues** as the empty table and
     `none: no issue had a fix in the code that ran`.
  6. **Commit the ledger.** `I check` must print `ok`. Then `git add audits && git commit -m
     "<P> audits: <id8> — <n> new, <n> seen, 0 checked" -- audits`. This is the one commit
     this skill makes itself.

- §6 **Log it, then report**: the entry keeps its name and **Tested against**, **What was
  tested** and **Method**; **Results** becomes "the issue ids by outcome: new `<ids>`, seen
  again `<ids>`; prior: none"; **Verdict** as today; and a last line `Report:
  audits/runs/<date>-<id8>.md`. The findings table is not repeated. The chat summary's first
  line adds the issue counts and the report path; "Offer to open it" became the run-flow line
  in phase 1.
- **What this skill never does**: "The report and the eval log are its only writes" → "The run
  report, the issue files and `INDEX.md` (through `issues.py`) and the eval log are its only
  writes"; "Commit anything except what `log-eval` commits" → "Commit anything except the one
  `audits/` commit and what `log-eval` commits".

### `contracts.yml`

Appended under `headings:`:

```yaml
  - name: audit-run names only issue-file sections the issue template defines
    # templates/audits/issue.md is the one list; issues.py writes from it, and the skills
    # name its sections when they say who writes what. fix-issues and bump-version are
    # added as readers in phase 6 of 0.16-audit-ledger.
    owner: templates/audits/issue.md
    owner_form: markdown
    readers:
      - file: skills/audit-run/SKILL.md
        cites: ['Finding', 'Found in', 'Checks']

  - name: audit-run names only run-report sections the report template defines
    owner: templates/audits/run-report.md
    owner_form: markdown
    readers:
      - file: skills/audit-run/SKILL.md
        cites: ['Errors', 'Warnings', 'Notes', 'Prior issues', 'Audited', 'Not audited',
                'Dropped on spot-check']
```
