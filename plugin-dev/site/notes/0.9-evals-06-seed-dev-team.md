# 06 — seed dev-team's eval sets (suggested)

Phase 6 — accepted suggestion. `dev-team` has four dated eval logs but no sets, so its next
change starts with nothing to rerun. This phase turns each behavioral log into a committed
set under `dev-team/evals/sets/`, and gives `dev-team` the gitignored workspace. It touches
another plugin, deliberately and only there; `dev-team`'s behavior does not change, so it gets
no version bump. Removing this phase removes `dev-team/evals/sets/` and nothing else.

## Decisions

- **Which logs become sets** (read each first; the list is from `main` on 2026-09-19):
  - `2026-09-16-implementer-security-review-trigger.md` → `evals/sets/implementer.json`
    (an agent; does it invoke the security-review skill when it should).
  - `2026-09-17-documenter-interface-heading-contract.md` → `evals/sets/documenter.json`.
  - `2026-09-18-probe-doc-headings-claim.md` → `evals/sets/researcher.json`.
  - `2026-09-17-cross-file-contract-sweep.md` → no set: it is mechanical and already
    enforced by `dev-team/contracts.yml` through `check-contracts`. Say so in the log.
- **Cases become evals** one for one where the log lists cases; prompts and expectations are
  reconstructed from its Method and Results, quoted where the log quotes. A case the log
  describes too thinly to reconstruct is left out and named in the phase's log.
- **Targets are agents,** so `target_path` is `agents/<name>.md` and the eval-kinds proxy
  note applies (a general-purpose subagent given the agent's prompt).
- **The 0.5 overhaul branch** (`dev-team-0.5-overhaul`) may rename or reshape these agents.
  The sets target `main`; reconciling them is that branch's job at merge, noted in its
  ledger if it is readable from here, otherwise in this phase's log.

## Deviations

1. **`evals/sets/files/<target>/` holds fixture inputs, not harness sheets.** The note's Files
   table says that directory is "new, only if a case needs a harness sheet". None of these
   three targets can ask the user anything — the researcher and the documenter say so in their
   own prompts, and the implementer's questions are decisions, not interviews — so no case
   needs a sheet and every eval's `harness` is `null`. What the cases do need is input
   documents, and those went in the same place: `files/documenter/repo/` (a one-package
   fixture repo: `docs/architecture.md`, a package contract, a template-conformant
   `interface.md`, one section README, one section without one, a decisions ledger, and the
   `cli.py` whose entry point the documenter confirms exists), `files/documenter/
   interface-missing-shapes.md` (the same `interface.md` with `## Shapes provided` cut), and
   `files/researcher/readmissions.csv` (246 synthetic rows, seeded, with the properties the
   expectations name: personal columns, a leaking column, a near-constant column, six exact
   duplicates, a `systolic` column whose `n/a` values make pandas load it as object).

2. **The agent proxy has no Skill tool for this plugin's skills, so "invoke" becomes "read".**
   The original implementer log's whole instrument was reading the stream-json transcript for
   a real `Skill` call with `"skill":"security-review"`. A general-purpose subagent given
   `agents/implementer.md` cannot make that call: `dev-team` is not loaded in the session that
   runs it, so its skills are not registered. Every prompt in `implementer.json` and
   `researcher.json` therefore states the substitution — the skill library is a directory of
   `SKILL.md` files, and invoking a skill means reading its `SKILL.md` in full and recording
   that in `transcript.md` before the work it bears on. The discrimination the original tested
   survives (the agent still has to decide *which* skill applies, from descriptions alone,
   with 21 skills in the library); the mechanism does not. Every result from these sets says
   `proxy`, as `eval-kinds.md` **Baselines** requires.

3. **The sets say `baseline: previous`; P6-B1 ran with `--baseline none`.** The note's Evals
   table gives P6-B1 a baseline of `none`, and that is how it ran. The committed field is
   `previous`, because the reason these sets exist is dev-team's *next* change: `previous`
   compares the edited agent against the version before the edit, which is the regression
   question. Today that comparison is empty — this branch does not touch `dev-team`, so
   `previous` resolves to a snapshot identical to the working tree — so the run overrode it
   with `--baseline none`, the contrast the note asked for.

4. **`documenter.json` is not one eval per case in its log.** That log's seven cases are
   heading-existence checks, and they are now `contracts.yml`'s `interface.md headings` claim,
   run by `check-contracts` — the same reason the note gives for granting
   `2026-09-17-cross-file-contract-sweep.md` no set. Reconstructing them as evals would
   duplicate a mechanical check with a model. What the set carries instead is the run that log
   named as unfinished and worth doing "before the next release that touches `documenter.md`":
   whether the heading contract changes what a documenter run actually produces. Its two evals
   are that run — the `data-daily` command reaching the package README through the **CLI
   commands** heading, and an absent heading becoming a **Known gaps** entry with nothing
   substituted for it.

5. **`researcher.json` has one eval, and the `api` kind is left out.** The probe log is a
   `contract_sweep.py` run: its cases are claim rows, mechanical and already claimed in
   `contracts.yml`. Its own **What this does not do** names the behavioral gap and the cheapest
   test of it — "a dataset probe that writes a `.sample.json` of real rows in violation of the
   statistics-only rule" — and that, together with the heading question it raises in the same
   paragraph, is the single eval. An `api`-kind probe needs a live credential and real vendor
   calls; no harness here can give it one, so it is left out under the note's rule for a case
   that cannot be reconstructed.

6. **`dev-team-0.5-overhaul` was not readable from here.** The note asks for the reconciliation
   to be recorded in that branch's ledger "if it is readable from here, otherwise in this
   phase's log". No such branch exists in this repository — `git branch -a` lists `main`, this
   branch and three `claude/*` session branches, and `dev-team/site/notes/` holds no 0.5 plan —
   so there is no ledger to write in, and the reconciliation note is in this phase's eval log
   instead.
