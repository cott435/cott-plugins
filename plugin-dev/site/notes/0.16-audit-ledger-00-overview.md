# plugin-dev 0.16-audit-ledger — overview

Branch: `plugin-dev-0.16-audit-ledger`. Release at the end: `0.16.0` — proposed to `bump-version`
in the last phase (a change: a minor bump). Nothing here bumps or tags anything. Date:
2026-10-07.

This is the index of the phase notes. Each numbered note after this one is one phase, done
in the order listed under **Phases**, one chat and one commit each, by
`/plugin-dev:run-phase 0.16-audit-ledger`. Nothing in a later phase is required by an earlier
one, so the branch is mergeable at any phase boundary.

The why, the workflows and their charts, the decisions and the non-goals are in
`0.16-audit-ledger-design.md`, approved before this was written. This note does not repeat
them; it says what the design turns into, file by file and phase by phase.

## What changes, at a glance

- Agents: 1 → 2. `run-auditor` (changed) takes a `Prior issues:` input and writes `P` lines;
  `run-narrator` (new, `claude-sonnet-5-5`, tools Read and Write) writes a short account of one
  unit, each line citing its steps.
- Workflow skills: 5 → 7. `+run-flow` (model-invocable), `+fix-issues` (typed), `~audit-run`
  (writes a committed ledger and checks prior fixes), `~bump-version` (stamps `fixed_in`).
- Knowledge skills: unchanged.
- Scripts: `trace.py` and `flow.py` move from `skills/audit-run/scripts/` to
  `skills/run-flow/scripts/` and grow (full-step JSON, unit pages, agent views, cross-session
  views, coverage selection, issue marks, narration); `scripts/issues.py` is new.
- Templates: `templates/audits/issue.md` and `templates/audits/run-report.md` are new; the run
  report moves out of `audit-run`'s body.
- Config: `contracts.yml` gains three `headings` claims (issue template, report template, the
  P verdict words); `site/site.yml` gains `fix-issues`; `VERSIONING.md` records
  `run-narrator`'s model.
- One-time data: `dev-team/audits/` is seeded from the ca48b249 audit (27 issues, the index, the
  converted report).
- Every new skill lands in the files the plugin's `CLAUDE.md` names, in the same commit, and
  its checks run before that commit: a row in the README's **The skills** table, and for a
  typed skill a line in `site/site.yml`'s `workflow_skills_order`.

## Breaking changes to list in `CHANGELOG.md`

1. `trace.py` and `flow.py` live at `skills/run-flow/scripts/`; anyone running them by hand
   from `skills/audit-run/scripts/` must use the new path. The README and the workflow page say
   so.
2. An audit now makes one more commit, `audits/`, in the checkout it runs in, and its report is
   `audits/runs/<date>-<id8>.md` (committed) rather than `evals/workspace/audit/<id8>/report.md`.
3. The audit's eval log is short: the issue ids by outcome and a link to the run report, not the
   full findings table. Existing logs are not changed.
