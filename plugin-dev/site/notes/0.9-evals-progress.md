## Standing facts

- Run every phase in Claude Code from the worktree's repo root with the plugin loaded from
  its working copy (`claude --plugin-dir ./plugin-dev`) — this plan changes the very skills
  that run it, so the installed plugin-dev (0.8.0) runs phase 1, and each later phase runs on
  the branch's own copy once `--plugin-dir` points at it.
- Every phase: edits → this plugin's `CLAUDE.md` rules → `check-contracts` → `build-site` →
  the phase's evals (from phase 2 on, through `run-evals`, stopping for review when a row is
  behavioral) logged with `log-eval` → one commit `plugin-dev 0.9-evals (phase N): …` → this
  file, in that commit.
- `evals/workspace/` is gitignored from phase 1 on; before that, keep workspaces out of the
  repo.
- Deviations from a note go under a `## Deviations` heading at the end of that note, in the
  same commit.
