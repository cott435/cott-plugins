# 09 — release

Phase 09. The end-to-end check of the whole loop on the fixture, the documentation that
describes only what now exists, the CHANGELOG's unreleased section, and the 0.16.0 proposal
in chat. `bump-version` runs only on a yes; this phase writes nothing it owns.

## Decisions

- **The end-to-end eval is the audit-run set run whole**, mechanical and behavioral, plus
  run-flow's and run-auditor's sets: eval 5 makes the ledger, eval 6 checks a fix against a
  rerun, and run-flow 1–3 draw it. No new eval is written; the loop is what the sets already
  prove in sequence. Reason: a test that exists only in this phase is a test nobody reruns.
- **`site/workflows/audit-a-run.md` keeps its file name** (`site.yml`'s `workflows_order` and
  the README link name it) and its title becomes "Checking a run, fixing it, and checking the
  fix". Reason: What must not break lists the README and site lists.
- **The CHANGELOG entry is written under `## [Unreleased]`** in the Added / Changed / Fixed
  grouping; `bump-version` renames the heading. Reason: this phase does not know the SHA of the
  bump.

## Specification

### `README.md`

- **The rest of the bundle** gains `| `agents/run-narrator.md` | The second agent: with `run-flow --explain`, writes a short account of one unit, each line citing its steps. Never judges. |` and `| `audits/` (in each audited plugin) | The committed ledger an audit writes: `issues/<ID>.md`, `INDEX.md`, `runs/<date>-<id8>.md`. Written only through `scripts/issues.py`. |`.
- **Workflows**, the audit paragraph, ends: "What it finds is filed as issues under the
  plugin's `audits/`, with ids that stay. `/plugin-dev:fix-issues` fixes them from any chat and
  records how a rerun will show each fix; the next `/plugin-dev:audit-run` of a rerun reports
  each one held, recurred, not exercised or not testable, and `/plugin-dev:run-flow` draws any
  run with every agent one click from its full record."

### `site/workflows/audit-a-run.md`

Sections after the existing worked example, in this order: **Fix what it found** (typing
`/plugin-dev:fix-issues run:<id8>`, the plan and the yes, the worktree, the checks, the Fix
attempt and its `Verify:` line, the merge and the bump questions), **Audit the rerun** (rerun
the workflow after `/plugin/update`; `/plugin-dev:audit-run <new chat>`; the **Prior issues**
table; what each verdict means; `not testable` and the stale cache), **See what an agent did**
(`/plugin-dev:run-flow <id8> --agent profiler`, `--explain`). The mermaid chart at the top
gains the issues, fix-issues and the rerun arrow. **Where things go** lists: the workspace
(never committed), the run report, the issues and index, the eval log, the transcripts.

### `CHANGELOG.md`

```markdown
## [Unreleased]

### Added
- **`run-flow`**: draws any run from its transcripts as a page in the browser pane; every agent on the chart opens to its full record (prompt, every step with full input and output, each Write's content and each Edit's old and new text, commits, hand-back). `--agent <type>` lists every run of one agent type across one chat or several (`--sessions`, `--branch`). `--explain` adds a short narration per unit from the new `run-narrator` agent (Sonnet 5.5).
- **A committed issue ledger**: every audit files its ERROR and WARN findings (and `definition` NOTEs) as issues under the audited plugin's `audits/issues/` with ids that stay (`DT-031`), an index, and the run report under `audits/runs/`. `scripts/issues.py` is the only writer; status is derived, never stored.
- **`fix-issues`**: fixes ledger issues from any chat on a worktree branch, records a Fix attempt with a `Verify:` line in each, and proposes the merge and the bump.
- **Rerun audits check prior fixes**: `run-auditor` takes the fixed issues that apply to its piece and reports each held, recurred or not exercised with a step; `audit-run` tests whether the fix was in the code that ran, widens the selection for coverage, spot-checks every verdict, and writes a Checks line per issue. The chart marks held and recurred on the boxes.
- `dev-team/audits/` seeded from the ca48b249 audit: 27 issues.

### Changed
- `trace.py` and `flow.py` live at `skills/run-flow/scripts/`; `audit-run` runs them from there. Running them by hand from the old path no longer works.
- An audit makes one more commit (`audits/`) in the checkout it runs in, and its eval log is short: the issue ids by outcome and a link to the run report.
- `bump-version` stamps `fixed_in` on the issues a release carries, when the plugin has `audits/`.
```
