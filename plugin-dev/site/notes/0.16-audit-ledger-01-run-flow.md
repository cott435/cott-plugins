# 01 — run-flow

Phase 01. The trace scripts move out of `audit-run` into a new, model-invocable `run-flow`
skill, and every agent on the chart becomes a page: `trace.py build` writes a full-step
`units/U<nn>.json` beside each clipped `units/U<nn>.md`, and `flow.py` renders
`units/U<nn>.html` from the JSON and makes each box on `flow.html` link to it. After this
phase a user can ask "show me the run" or type `/plugin-dev:run-flow <chat>` from a plugin
directory and get the run's chart in the browser pane, each agent one click from exactly what it
did. It closes the gap the design opens with: seeing what one agent did no longer means reading
a clipped markdown trace by hand. The agent view across sessions is phase 2; narration is
phase 8.

## Decisions

- **The description and argument-hint describe only what ships here** (the chart and the unit
  pages). Phase 2 extends both for the agent view and phase 8 for `--explain`, each rerunning
  the trigger set as a regression row. Reason: no phase ships a flag that prints "not yet".
- **Serving.** A local page opens in the browser pane only when it is served, so the skill
  starts `python3 -m http.server` on a free port, bound to `127.0.0.1`, in the background, and
  opens `http://127.0.0.1:<port>/flow.html`. Where there is no browser pane (a headless or
  terminal session), it prints the URL and the file path instead. Reason: audit-run already
  says this is how a local page opens; the skill does it rather than describing it.
- **`units/U<nn>.json` mirrors the `.md`'s step numbering exactly**: the same events, the same
  ids, hooks attached to their call rather than numbered. Reason: a step id in an issue or a
  report must point at the same step on the page as in the trace an auditor read.
- **Commit details come from the project when it exists.** For each commit a unit made,
  `trace.py build` records the message and files with `git -C <project> show --stat
  --format=%s <sha>`; when the project is gone, the message comes from the `[branch sha] msg`
  line in the Bash output and the file list is empty. Reason: the pages claim nothing the
  transcript or the project does not show.
- **The old location is not kept.** Nothing is left at `skills/audit-run/scripts/`. Reason: two
  copies drift; the README and the workflow page name the new path.
- **Files whose only mention of `trace.py` carries no path are not edited** for the move:
  `agents/run-auditor.md` line 28 ("the directory `trace.py` wrote") and
  `evals/fixtures/audit-run/make_session.py`'s docstring. The design lists both under build
  step 1; `grep -n "audit-run/scripts"` finds neither. Confirm with the grep in **Done when**.

## Specification

### `skills/run-flow/SKILL.md`

Component reference: `plugin-anatomy` `references/skills.md` (frontmatter keys, the
scoped-description rule, **How to test it**). Frontmatter, verbatim:

```yaml
---
name: run-flow
description: Draw what a plugin's workflow run actually did, from its session transcripts, as a page in the browser pane - the run's flow chart (waves of agents, one column per section, each review coloured by its verdict) with every agent clickable through to its full record, which is the prompt it was sent, every step with its full input and output, each Write's content and each Edit's old and new text, its commits with their files, and what it handed back. Use when someone asks what a run or an agent did in some chat ("what did the profiler do in that chat?", "show me the run", "open the flow for session 1493ed56", "which agents ran in the architecture migration chat?"), or to rebuild a run's chart after an audit. Use only inside a plugin's own subdirectory (one containing .claude-plugin/plugin.json), or from the marketplace repo that holds it with --plugin naming the plugin. Not for judging a run against the plugin's files (that is audit-run), and not for reading ordinary chat history or a project's own logs.
argument-hint: "[chat title words | session-id | latest] [--plugin NAME]"
---
```

Body headings, in this order, with the rules each holds:

- `# Seeing a run` — one paragraph: a run is what a plugin actually did; this skill draws it
  from the transcripts and judges nothing; `audit-run` judges. Then: `T` is
  `python3 ${CLAUDE_SKILL_DIR}/scripts/trace.py`.
- `## 1. The plugin and the session`
  1. The plugin. `.claude-plugin/plugin.json` in the working directory: its `name` is **P** and
     the plugin directory is `.`. Otherwise, if `.claude-plugin/marketplace.json` is in the
     working directory and `--plugin NAME` was given: **P** is NAME and the plugin directory is
     that plugin's `source` in `marketplace.json`. Otherwise stop and say where this skill runs.
  2. The session: everything in the arguments before the first flag. Resolve it exactly as
     `audit-run` does in its §1 step 2: a `.jsonl` path, an id or unique prefix, `latest`, or
     title words through `T build`; with nothing, `T find --plugin P`, and one
     `AskUserQuestion` when several match (at most four options, newest first, the label the
     chat's title in quotes). Forks are picked the same way.
  3. The workspace is `<plugin dir>/evals/workspace/audit/<first 8 chars of the session id>/`.
     When the plugin directory is inside a git checkout, check that its `.gitignore` covers
     `evals/workspace/` and add the line (and the file, when there is none) if not; outside a
     git checkout there is nothing to ignore, so say so and go on.
- `## 2. Build` — `T build <session> --plugin P --out <workspace>`. A rebuild of a session that
  grew appends units and steps without renumbering. Print the script's summary lines.
- `## 3. Serve and open` — find a free port
  (`python3 -c "import socket; s=socket.socket(); s.bind(('127.0.0.1',0)); print(s.getsockname()[1])"`),
  run `python3 -m http.server <port> --bind 127.0.0.1 --directory <workspace>` in the
  background, open `http://127.0.0.1:<port>/flow.html` in the browser pane; with no browser
  pane, print that URL and the path to `flow.html`. Then two lines to the user: the run (**P**,
  version, command(s), units and waves) and the URL; and that each box opens the agent's page
  and `audit-run` is how a run is judged.
- `## What this skill never does` — judge the run or say whether an agent followed its
  definition; edit the plugin, the project or the transcripts; commit anything; write anywhere
  but the workspace, plus a `.gitignore` line when one is missing.

### `trace.py`

- Docstring: the usage block adds, under `build`, "`DIR/units/U<nn>.json` (every step with its
  full input and output, for the pages and the narrator; the `.md` stays clipped for
  auditors)". The module path in the first line of **Where it runs** is
  `skills/run-flow/scripts/`.
- `build` writes, per unit, `units/U<nn>.json`:

```json
{
  "unit": "U01", "agent_id": "…", "type": "toy:writer", "description": "…",
  "spawner": "driver", "spawn_step": "D3", "definition": "…", "version": "0.1.0",
  "models": ["…"], "first_ts": "…", "last_ts": "…", "finished": true,
  "prompt": "<the whole prompt>",
  "steps": [
    {"step": "U01.S1", "kind": "call", "ts": "…", "tool": "Write", "input": {"file_path": "…", "content": "…"},
     "output": "<the whole result text>", "error": false,
     "hooks": [{"hook": "…", "blocked": true, "text": "…"}],
     "commits": [{"sha": "abc1234", "confirmed": true, "message": "…", "files": ["…"]}],
     "write": {"path": "…", "content": "…"},
     "edit": null},
    {"step": "U01.S2", "kind": "say", "ts": "…", "text": "<the whole text>"}
  ],
  "return": "<the whole return>",
  "step_count": 2
}
```

  - `steps` holds every event `render_events` numbers, in the same order with the same
    `step` ids; `kind` is the event kind (`call`, `say`, `think`, `command`, `user`,
    `skill-body`, `notify`, `handback`, `hook`, `system`). A hook shown under its call in the
    `.md` is in that call's `hooks`, not a step; a hook event with no call of its own (a
    blocked tool call that never ran) stays a step, as in the `.md`. Text fields are whole, never clipped.
  - For a `call`: `tool`, `input` (the whole input), `output` (the whole result), `error`,
    `hooks`, `commits` (from `commits_of`, each with `confirmed` false for a `?sha`; `message`
    and `files` from `git -C <project> show --stat --format=%s <sha>` when the project exists,
    else the message from the `[branch sha] msg` line and `files: []`), `write` (`path`,
    `content`) for `Write`, `edit` (`path`, `old`, `new`) for `Edit`, else `null`.
  - `step_count` is `len(steps)`, and equals the number of lines in `units/U<nn>.md` that begin
    `` - `U<nn>.S ``.
- Each unit in `index.json` gains `"json": "units/U<nn>.json"` and `"step_count": <n>`. Nothing
  existing changes. `run.md`, `driver/`, `units/U<nn>.md` and `units/U<nn>.system.md` are
  byte-for-byte what the old location wrote for the same transcript (the `.md` format is what
  auditors read and must not change).

### `flow.py`

- `write_html(out)` also writes `units/U<nn>.html` for every unit that has a `units/U<nn>.json`,
  from the JSON only. Sections, as `<h2>` in this order: a header block (type, description,
  spawner and spawn step, model, start, duration in minutes, tool calls, errors, hook blocks,
  skills invoked), `Prompt`, `Steps`, `Commits`, `Returned`. Each step is one block with an
  `id="S<n>"` anchor, its step id, its kind or tool, the one-line summary the `.md` shows, and
  a `<details>` holding the full input and the full output; a `Write` step shows its full
  content in a `<pre>`; an `Edit` step shows two labelled `<pre>` blocks, `old` and `new`; a
  hook block is shown under its call. `Commits` lists each commit's sha, message and files,
  marked `unconfirmed` when `confirmed` is false. `Returned` is the whole return in a `<pre>`.
  A link at the top returns to `../flow.html`. No scripts, no network, as `flow.html`.
- Every unit box in the SVG is wrapped in `<a href="units/U<nn>.html">`. Under the chart,
  `flow.html` gains `<h2>Units</h2>` with one row per unit: unit (linked), type, section,
  description, start, duration, tool calls, errors, commits, first line of the return.
- `audit_errors` and the badges are unchanged.
