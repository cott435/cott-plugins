## Deviations

**P7-L1's pass bar cannot be met as written.** The note says
`claude --plugin-dir ./plugin-dev -p "List the skills you have from plugin-dev"` "names all
eight". It names six. `plan-phases` and `run-phase` are `disable-model-invocation: true`,
and `-p` omits typed skills from the model's skill list. A control run against the installed
0.8.0 bundle — seven skills, the same two typed — lists exactly its five automatic ones, so
this is platform behaviour, not a registration failure on this branch. Both typed skills
were then invoked directly and both loaded and behaved correctly, so all eight register.
What the bar should have said: "names all six automatic skills, and both typed skills
invoke". Recorded in `evals/2026-09-20-release-checks-0.9.0.md`.

**P7-T1's ±0.05 band is tighter than the measurement's repeatability.** `check-contracts`
scored 0.90 against phase 2's 1.00 with a `SKILL.md` that is byte-identical to phase 2's
commit (`git diff 29b317b HEAD` on that file is empty), same set, same method, same model.
Both misses are the pair that already scored 0/3 before phase 2's rewrite. At
`--runs-per-query 3` a 20-query rate moves about 0.10 between identical runs, so the bar can
fail on sampling alone — which is what happened. The other four held (1.00, 1.00, 1.00,
0.95) and every skill kept 10/10 on its should-not-trigger queries, so the guard never
moved. No description was changed. Recorded in `evals/2026-09-20-trigger-rates-rerun.md`.

**A skill defect was found by the end-to-end run and fixed here, beyond the note's Files.**
Both `with_skill` `run-phase` executors independently hit a contradiction between two of
this plugin's own skills: `run-evals`' step 7 requires a weak expectation the graders flag
to be rewritten in the set "in this change", while `run-phase`'s "only this phase's edits"
forbids touching a set outside the note's Files. Both resolved it in `run-phase`'s favour
and demoted the fix to a `*noticed:*` line. On the user's decision this phase edited
`skills/run-phase/SKILL.md` — not in the note's Files table — adding the exception to
**Only this phase's edits** and matching wording to **Stop for review**. `check-contracts`
(4/4) and `build-site` were rerun after the edit.

**The end-to-end run did not include a blind comparison.** Note 05's ledger row says the
rerun does not need to redo it, and `evals/sets/run-phase.json` and `plan-phases.json` both
separated the configurations on assertions, so the condition that triggers a blind
comparison automatically — both sides passing everything, or within 10 points — was not met.

**Phase 4's review-stop Deviation is only half-resolved.** `run-phase` eval 1 did separate
the versions this time (7/7 vs 5/7, where phase 4 got 7/7 vs 7/7), but its grader confirmed
the review-stop assertion still cannot fail for a run that skips the gate on its own
initiative: the fixture's ledger Standing facts and the note's Done-when both mandate the
stop, so an executor stops whichever skill version it read. The baseline failed that
assertion only on the incidental "viewer or results table" clause. The fix is to the
fixture, and is not made here.

**`CLAUDE.md`'s bullet count.** The file said "two things need extra care" above what were
already four bullets; adding the `run-evals` bullet made it five, so the lead-in now reads
"a few things". Not in the note's Specification, but caused by the bullet the note requires.
