# 08 — run-narrator

Phase 08. The optional reading aid: with `--explain`, `run-flow` spawns one `run-narrator`
per finished unit, which writes `explain/U<nn>.md`, five to ten plain lines on what the unit
did, each citing its step range; `flow.py` puts the narration at the top of the unit page,
drops any line citing a step the unit does not have, and marks it out of date when the step
count changed. The design accepted this as a suggestion ("81 raw steps are slow to read");
nothing in the core depends on it.

## Decisions

- **The agent reads the clipped `.md` first and the `.json` only for a step whose clipped
  output hides what it did.** Reason: a Sonnet run over a whole JSON of full outputs costs
  what the design's cost table does not allow.
- **Narration runs only for units with no explain file, or whose file's header count differs
  from `step_count`.** Reason: the design's warm-run rule.
- **More than 12 units to narrate: ask first** with `AskUserQuestion`, options `Narrate all
  <n>` and `Only the first 12`. Reason: the design's cost row.
- **Narrators run in the foreground, all in one message.** Reason: the skill re-renders after
  they return.
- **The description gains one clause** and the trigger set two queries; T8.1 reruns it.
- **A unit with fewer than five steps gets one line per step**, never more lines than steps.
  The design's "5–10 lines" is for the units it was written about (dozens of steps); with no
  overlap allowed, a two-step unit cannot have five lines. Reason: the eval writer found every
  flow-session fixture unit has two steps.
- **The return's `<Output path>` is the path exactly as given** in the spawn block, and the
  never-list applies to the whole file, header included.

## Specification

### `agents/run-narrator.md`

Component reference: `plugin-anatomy` `references/agents.md` (frontmatter, `model` takes a
full id, no `AskUserQuestion`, the `.md`-name refusal does not apply to `U01.md`). Frontmatter,
verbatim:

```yaml
---
name: run-narrator
description: Writes a short plain-English account of what one spawned agent did in a traced workflow run - five to ten lines, each citing the step ids it covers - from that unit's trace in the audit workspace. Never judges whether the agent followed its definition; that is run-auditor's job. Spawned by run-flow with --explain, one per finished unit.
tools: Read, Write
model: claude-sonnet-5-5
color: cyan
---
```

Body:

- One paragraph: you turn one agent's trace into a short account a person can read in a
  minute; every line points at the steps it describes, which are one click away, so the
  account claims nothing the steps do not show.
- `## Inputs` — the spawn prompt is `Field: value` lines: **Unit** (`U<nn>`), **Trace**
  (`<workspace>/units/U<nn>.md`), **Full** (`<workspace>/units/U<nn>.json`), **Output**
  (`<workspace>/explain/U<nn>.md`).
- `## What to do` — read the Trace whole: the prompt, the steps, the hand-back. Read the Full
  file only for a step whose clipped output hides what happened (an `…[N chars]` that cuts a
  result you need to describe). Then write Output in exactly this shape:

```markdown
U<nn> · <type> · steps 1–<n>

S1–S3 · <what the agent did across these steps, one line>
S4 · <…>
…
```

  The header's `<n>` is the number of steps in the Trace. Five to ten lines (one per step,
  and no more, when the unit has fewer than five steps), in step order, whose ranges together
  cover `S1` through `S<n>` with no gap and no overlap. Each line says
  what was done and what it produced, in the agent's own terms (files, commands, counts the
  steps show). Create `explain/` if it is missing.
- `## Never` — say whether a step followed the agent's definition, or use the words should,
  must, violated, correctly, wrongly; state a result or a count the cited steps do not show;
  mention a step past `<n>`; write anything but Output.
- `## Return` — exactly one line: `Explained: U<nn> · <k> lines · <Output path>`, the path
  exactly as the spawn block gave it.

### `flow.py`

- A unit page reads `explain/U<nn>.md` when it exists. It parses the header's `steps
  1–<n>`; when `<n>` differs from the unit's `step_count`, the block is headed `Narration out
  of date: written for <n> steps, the unit now has <m>`. Each line's range (`S<a>–S<b>` or
  `S<a>`) becomes links to the step anchors; a line whose range names a step above
  `step_count`, or that does not start with a range, is not shown, and the block ends with
  `<k> line(s) dropped: they cite steps this unit does not have` when any was. The block sits
  above **Prompt**, headed **What it did**.
- `flow.html`'s units table gains a `Narrated` column: `yes`, `stale`, or `—`.

### `skills/run-flow/SKILL.md`

- `description`: after the agent-view clause add "With --explain, a short plain-English
  account of each agent, each line linked to its steps, sits at the top of its page." Trigger
  phrases gain `"explain what each agent did in that run"`, `"walk me through what the
  implementer did in chat 5976c083"`.
- `argument-hint`: append ` [--explain]`.
- `## 2b. Explain (with --explain)` — the units to narrate (Decisions); the cap question; spawn
  `plugin-dev:run-narrator` per unit, foreground, one message, each with the four input lines
  above, every path absolute; when all have returned, `T flow <workspace>` to re-render. A
  narrator whose return is not its one `Explained:` line is respawned once, then skipped with a
  note in the summary.
- `## What this skill never does` gains: pass `--explain` on its own; the user asks for an
  explanation.

### `VERSIONING.md`, **Model decisions**

A paragraph after run-auditor's: `run-narrator` (spawned by `run-flow --explain`) is on
`claude-sonnet-5-5`, a full id because an alias moves (`plugin-anatomy`,
`references/agents.md`, **Model names**). It writes a reading aid whose every line links to the
steps it cites, so a cheaper model is enough and the cost of a 12-unit run stays under a
million tokens.
