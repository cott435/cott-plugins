# dev-team 2.7-data-loop — overview

Branch: `dev-team-2.7-data-loop`. Release at the end: `2.7.0` (minor) — proposed to
`bump-version` in the last phase. Nothing here bumps or tags anything. Date: 2026-10-03.

This is the index of the phase notes. Each numbered note after this one is one phase, done
in the order listed under **Phases**, one chat and one commit each, by
`/plugin-dev:run-phase 2.7-data-loop`. Nothing in a later phase is required by an earlier one,
so the branch is mergeable at any phase boundary.

The why, the workflows and their charts, the decisions and the non-goals are in
`2.7-data-loop-design.md`, approved before this was written. This note does not repeat them; it
says what the design turns into, file by file and phase by phase.

## What changes, at a glance

- Agents: 8 → 9. `+ profiler`. The eight existing agent files do not change by one line.
- Workflow skills: 12 → 12. `~ run-package` (the PROBE spawn for a `stage:` source, one
  **Asking** bullet, `profiler <n>` in the summary), `~ status` (its `argument-hint` and one
  paragraph for `--profile`).
- Knowledge skills: 9 → 10. `+ data-quality`; `~ planning-templates` (one new reference,
  `data-profile.md`, and small edits to three others).
- Scripts: `~ skills/status/scripts/status.py` (a `stage:` source at PROBE, `--profile`, the
  round cap, two run-gate checks). Hooks: `~ hooks/guard_writes.py` (the profiler's row, the
  size guard). `contracts.yml`: new claims in the phase that makes each one true.
- Every new skill lands in the files `dev-team/CLAUDE.md` names (`README.md`'s **Contents**
  tree and its knowledge-scope table), in the same commit, and `check-contracts` runs before
  that commit.

## Rules every phase follows

- **The line budget** (design, **What must not break**). "Lines added" is net growth:
  `git diff --numstat dev-team-v2.6.0 -- <file>` added minus deleted. The budget per file, and
  the share each phase may spend:

  | File | Budget | Phase shares |
  |---|---|---|
  | the eight existing `agents/*.md` | 0 (no diff at all) | — |
  | `skills/run-package/SKILL.md` | 10 | phase 2: 5 · phase 6: 5 |
  | `skills/planning-templates/references/package-contract.md` | 6 | phase 4: 6 |
  | `skills/planning-templates/SKILL.md` | 1 | phase 1: 1 |
  | `skills/planning-templates/references/decisions-inbox.md` | 2 | phase 1: 2 |
  | `skills/planning-templates/references/deviations-entry.md` | 2 | phase 5: 2 |

  A phase that cannot fit its share stops and says so in its `## Deviations`; the text moves
  into `agents/profiler.md`, `skills/data-quality/SKILL.md` or `data-profile.md`.
- **No `stage:` source, no change.** After every phase that edits `status.py`,
  `python3 evals/fixtures/state-cases/check.py` passes with no pre-2.7 `case.json` edited.
- **Notes are swept by `check-contracts`.** A note that quotes a forbidden pattern rewords it.

`check-contracts`, `build-site`, then the phase's evals logged with `log-eval`, then the
commit.

Phases 3 and 4 may pair in one chat, and so may 6 and 7. Nothing else pairs: phases 1, 2 and 5
each carry a behavioral run that stops for review.

**P0.1 (platform-fact).** Assumed: `uv run --with duckdb python <script>` inside a uv workspace
leaves `pyproject.toml` and `uv.lock` unchanged. Test, run first by `run-phase`: in a
`mktemp -d` directory, `uv init --name probe`, `uv lock`, `git init`, commit everything; write
`q.py` holding `import duckdb; print(duckdb.sql("select 1").fetchall())`; run
`uv run --with duckdb python q.py`; pass when it prints `[(1,)]` and `git status --porcelain --
pyproject.toml uv.lock` prints nothing. The result is logged with `log-eval` and written back
to `plugin-dev`'s `skills/plugin-anatomy/references/edge-cases.md` as a row under **Works
locally, breaks installed** (`[proven: <log>]`), since it is a tool fact the design rests on.
If it fails, phase 1 stops: the profile program's engine is a decision to reopen.

## Deviations

- **P0.1's write-back (phase 0).** The note said: write the result back to `plugin-dev`'s
  `skills/plugin-anatomy/references/edge-cases.md` as a row under **Works locally, breaks
  installed**. What was done: the result is logged
  (`evals/2026-10-03-2.7-data-loop-platform-facts.md`, a pass) and the write-back is a
  *noticed:* line in the ledger's phase-0 row instead. Why: `run-phase` makes a platform-fact
  write-back to another plugin's file a *noticed: write back to plugin-anatomy* line, done
  afterwards as a small change to `plugin-dev`, never an edit inside this plugin's phase
  commit. The fact held, so no later note's assumption changes.
