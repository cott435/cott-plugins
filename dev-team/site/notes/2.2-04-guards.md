# 04 — guards

Phase 4. Turns two instructions into hooks. `guard_writes.py` learns the 2.2 paths for every
role and, for an implementer whose spawn prompt carries `Section:`, confines it to its own
section's files; `guard_bash.py`, new, refuses a dev-team agent's shell command that writes a
repo file by redirect, `sed -i`, `tee` or `python -c … open(…, 'w')`, letting `locked.py` through.
The gap it closes: in the audited run two implementers wrote every file through the shell and
met no hook (E4), and under parallelism a write into a sibling's section is the failure that
corrupts a run.

## Decisions

- **The section scope is a closed allowlist**, per the design's guard row, plus `.dev-team/tmp/**`
  (the design's scratch location, written with the Write tool) and the old ledger locations
  (status edits, per **What must not break**). `docs/decisions.md` is *not* in it: the
  implementer writes the inbox. Reason: the design.
- **Redirect targets allowed**: `/dev/null`, and a path under `.dev-team/tmp/` (relative, or
  absolute under `cwd`). Everything else refused. Reason: the design's Decisions taken,
  *Shell scratch* (planning).
- **`tee` is refused whatever its target**; `sed -i` whatever its file. Reason: the design lists
  both bare; the one legitimate shared edit runs through `locked.py`, which is exempt.
- **`locked.py` detection**: the first simple command's first three tokens, after leading
  `NAME=value` assignments, include one ending in `/locked.py` or equal to `locked.py`. Reason:
  `python3 <path>/locked.py …` is the documented form.
- **Fail open on a parse the guard cannot make** (`shlex` raises, or an empty command): exit
  0 with the rule on stderr. Reason: the design says so; a guard that crashes fails open anyway
  (hooks.md), so saying the rule is the most it can do.
- **Scope**: `agent_type` starts with `dev-team:` and `<cwd>/docs/architecture.md` exists. The
  main thread, `pair` and `Explore` are never guarded. Reason: "every dev-team role", and the
  hooks-scope rule.

### `guard_writes.py` — the section scope

When `agent_type == "dev-team:implementer"` and `status.cached_section(event)` returns
`(pkg, section)`: import `status` as the gate does, `status.set_root(cwd)`, and allow exactly:

- the section's `path` from `status._row(pkg, section)` and everything under it;
- `<package root rel>/tests/unit/<section>/**`;
- `**/tests/fixtures/**`;
- `docs/packages/<pkg>/deviations/<section>.md`, `docs/deviations/<pkg>/<section>.md`,
  `docs/deviations.md`;
- `docs/packages/<pkg>/decisions/<section>.md`;
- `.dev-team/tmp/**`; `.dev-team/stop/<pkg>/<section>` (the marker is written with the Write tool); `.claude/agent-memory/**`;
- for `section == "surface"` also `docs/packages/<pkg>/interface.md`, `docs/api/<pkg>.md`,
  `pyproject.toml`, `mkdocs.yml`.

Never `**/tests/intent/**`. A row `status._row` cannot find (the section is not in the
contract) → the role-wide rule. Refusal text:
`dev-team write guard: dev-team:implementer (data/ingest) may not write <path>. Its section's files: <the list above, comma-separated> (and .claude/agent-memory/**). Shared edits — pyproject.toml, uv.lock, .gitignore — go through locked.py.`

`cached_section` returning `None` (scaffold, unreadable transcript, no `Section:`): today's
role-wide rule, with the updated globs.

### `hooks/guard_bash.py`

Docstring:

> PreToolUse hook on Bash: a dev-team agent never writes a repo file from the shell.
>
> Input: the hook JSON on stdin (`cwd`, `agent_type`, `tool_input.command`). Exit 0 unless
> `<cwd>/docs/architecture.md` exists and `agent_type` starts with `dev-team:`. Refused, exit
> 2 with the rule on stderr: a redirect (`>`, `>>`, `1>`, `&>`, `>|`) whose target is not
> `/dev/null` and not under `.dev-team/tmp/`; `sed -i`; `tee`; `python -c` / `python3 -c`
> whose code calls `open(…, "w"|"a"|"x")` or `write_text(`. `2>&1`, `>&2` and `<` are not
> writes. Allowed whatever it does: a command whose program is `locked.py`
> (`python3 …/locked.py <name> -- <cmd>`), the one way an implementer edits `pyproject.toml`,
> `uv.lock` or `.gitignore`. A command the guard cannot parse (`shlex` fails) is let through
> with the rule on stderr: a guard fails open, and saying why is the most it can do. Malformed
> stdin: exit 0.

Implementation: split the command on `;`, `&&`, `||`, `|` (outside quotes, via a small tokenizer
over `shlex.shlex(punctuation_chars=True)`); for each simple command: strip leading `NAME=value`
tokens; exempt if any of its first three tokens ends with `locked.py`; else scan its tokens for
a redirect operator (`>`, `>>`, `1>`, `1>>`, `&>`, `>|`, and a token starting with those glued
to a target) and take the target (next token, or the glued remainder); `2>&1`/`>&2`/`>&1`
skipped; target allowed when it is `/dev/null` or `os.path.realpath(join(cwd, target))` starts
with `realpath(cwd)/.dev-team/tmp`; `sed` with an `-i`/`--in-place` token; `tee` as program;
`python`/`python3`/`uv run python` with `-c` whose next token matches
`open\([^)]*['"][wax]` or `write_text\(`. Refusal stderr:
`dev-team bash guard: <agent_type> may not write a repo file from the shell (<what>: <token>). Use the Write or Edit tool; a shared edit goes through locked.py; scratch goes under .dev-team/tmp/ or to /dev/null.`
