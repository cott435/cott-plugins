# 10 — docs and release

Phase 10. The last phase: the documents a user reads are brought level with what phases 1 to
9 built, the changelog's unreleased section is written, and the release is proposed. Phases
2, 3 and 5 already rewrote the rows of `README.md`'s **The states** as they changed them;
everything else in the README, `site/flow.md` and `site/workflows/` still describes 2.3: an
implementer that amends its report, a package that ships when `surface` is DONE, a write
guard that lets `surface` write sibling code, guards that are off until
`docs/architecture.md` exists, a tester that reads the TDD skill. There is no end-to-end
eval here: the design's proof bar leaves the whole loop to real projects and their audits
(`evals/sets/run-package.json` eval 4 is not run). The phase ends with a bump proposal in
chat, MINOR, `2.4.0`. `bump-version` decides on a yes; this phase bumps nothing.

## Decisions

- **`CHANGELOG.md` gains a `## [Unreleased]` section above `## [2.3.0]`.** `bump-version`
  renames it when it runs.
- **The unreleased section also records `1e81553`,** the audit fixes merged after 2.3.0 with
  no changelog line: 2.4 is the first release that carries them, and phases 6 to 9 are the
  first runs that test them.
- **The end-to-end eval row of the plan template is deleted** for the reason above.
