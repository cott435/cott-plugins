# 05 — the gate's checks

Phase 05. Three faults in what the stop gate checks, and one in what `status.py` calls
shipped. A package shipped while its own surface check failed, because grouped and dotted
name cells in sibling READMEs were found only at `surface`, by an agent that may not edit
them, and `shipped: yes` never looked at the check (open item 15). A rewritten `assert` was
reported as a removed one, so every section a signature change touched failed all three
attempts (item 16). An `xfail` whose decorator `ruff format` wrapped failed the Guarded grep
(item 18). And ruff 0.15's location lines were dropped from FAIL text (2.2 ledger, phase 3).
This phase gives `status.py` a per-section name check that the gate runs for every section,
makes `shipped: yes` need the package-wide check, counts asserts per file, reads an
`xfail(` call to its closing bracket, and keeps the ` --> path:line` lines. It runs before
the implementer's phase so that phase can describe checks that exist; until then a README
with a bad name cell fails its gate with a FAIL line that states the rule.

## Decisions

- **`--section` is a second flag beside `--surface`,** as the design writes it: `status.py
  --surface <pkg> --section <s>`. `--section surface` is refused: the package-wide check is
  the `surface` section's.
- **"Named by the contract" is a whole-word match in the body of *Public surface
  (intent)*.** That heading is prose or a table, as the architect chose; no column is
  assumed. A contract with no such item skips that half of the check.
- **A cell with a file hint fails.** `` `load_trades` (`__init__.py`) `` passed since 2.2
  phase 12; the design's rule is the identifier alone. The package-wide check reports such a
  cell and still takes every backticked identifier in it as a name, so one bad cell is one
  reason, not three.
- **`surface names` is the label,** distinct from the package-wide `surface`, so a reader of
  the record can tell which check a line is.
- **Assert counts are per file and per kind.** Lines starting `assert ` and lines holding
  `pytest.raises` are counted separately; a file fails when it lost more of a kind than it
  gained. A moved assert, a rewritten one and a split one all pass; a dropped one fails.
- **An `xfail(` call is read across consecutive added lines of one file, at most twenty.** A
  call whose later lines were not added in this diff is judged on the lines that were: the
  earlier review already saw the rest.
- **`next:` for a package whose only fault is the check** is the line the user approved in
  planning; the driver's own question about it arrives in phase 9.
- **`--repo` says `building (<n>/<n> DONE, surface check FAIL)`** for such a package, so the
  documenter's Known gaps do not call it shipped.

## Specification

### `status.py`

**`_name_cells(row) -> tuple[list[str], str | None]`** replaces `_name_cell` for the READMEs:
the backticked spans of the row's `name` cell that are Python identifiers, and a reason when
the cell is not exactly one backticked identifier (`^\s*`[A-Za-z_]\w*`\s*$`), else `None`.
`interface.md`'s **Public names** rows keep `_name_cell`.

**`surface_names(pkg, section) -> tuple[str, list[str]]`**, the per-section check:

- `n/a` when the section's README does not exist.
- For every row of the README's **Entry points and interfaces** table: a cell that is not
  exactly one backticked identifier gives the reason `<cell as written>: name cell is not
  one backticked identifier`.
- For every row whose `Public` cell starts `yes`: each identifier that does not appear as a
  whole word in the body of the contract's **Public surface (intent)** item gives `<name>:
  Public: yes, not in the contract's Public surface (intent)`. Skipped when the contract has
  no such item.

`main`: `--section <s>` is valid only with `--surface <pkg>`; alone it prints `--section
needs --surface <pkg>` and exits 2; with `surface` it prints `--section surface is the
package-wide check: status.py --surface <pkg>` and exits 2. It prints

```
surface names <pkg>/<s>: PASS
```

or `surface names <pkg>/<s>: FAIL` followed by one `  - <reason>` line each, or `surface
names <pkg>/<s>: n/a (no README)`, and exits 1 on FAIL only.

**`surface_check`** (package-wide): for each section README row it uses `_name_cells`; a
reason becomes the fail line `<pkg>/<section> README: <reason>`, and every identifier the
cell holds joins the `Public: yes` names, so a grouped cell no longer hides its second name.

**`shipped_line(pkg, table) -> str`**, used by `package_report`:

- no `surface` row → `shipped: no (no surface row)`;
- `surface` not DONE → `shipped: no (surface <STATE>)`;
- DONE and `surface_check(pkg)[0] == "PASS"` → `shipped: yes`;
- DONE otherwise → `shipped: no (surface check FAIL)`.

`surface_check` runs only when the `surface` row is DONE. `repo_report` prints `<pkg>:
shipped` only on `shipped: yes`, and `<pkg>: building (<n>/<n> DONE, surface check FAIL)` for
the last case.

**`next_command`**: when every row is DONE and the package's line is `shipped: no (surface
check FAIL)`, before the `_to_sync` branch:

```
correct the README rows status.py --surface <pkg> names, then /dev-team:run-package <pkg>
```

The docstring: the usage line gains `[--section <s>]` after `--surface <pkg>`; "Shipped: the
`surface` section is DONE." becomes "Shipped: the `surface` section is DONE and
`--surface <pkg>` passes; otherwise the block prints `shipped: no (surface <STATE>)` or
`shipped: no (surface check FAIL)`."; and one sentence on `--surface <pkg> --section <s>`
with its two reasons and its output line.

### `hooks/gate_on_stop.py`

**`check_surface_names(pkg, section)`** runs `status.py --surface <pkg> --section
<section>` and returns `PASS surface names <pkg>/<section>` on exit 0, else `FAIL surface
names: <its output lines joined with ' | '>`. `run_checks` adds it for every section but
`surface`, which keeps `check_surface`; `run_checks_legacy` adds it for each non-`surface`
target.

**`check_guarded`**, removed asserts. Per `.py` test file that still exists, count the
diff's `-` lines and `+` lines whose stripped text starts `assert `, and separately those
holding `pytest.raises`. A kind with more removed than added is one hit at the first removed
line of that kind:

```
FAIL guarded removed assert at <path>:<n> (<r> removed, <a> added)
```

and `removed pytest.raises` likewise. The comment above it says why: a signature change
rewrites every assert that calls the function, and a rewrite is not a removal.

**`check_guarded`, `xfail`.** For an added line matching `xfail`: when the text from `xfail`
on holds an opening `(` that the line does not close, join the following added lines of the
same file with consecutive line numbers, at most twenty, until the brackets balance, and
search the joined text for `D<n>` (`DECISION`). Otherwise the line alone, as now. A hit is
reported at the first line.

**`_tail`.** A located line is one that, stripped, matches `(?:-->\s*)?[\w./-]+\.\w+:\d+`;
the ` --> ` prefix is kept in the text.

The docstring's step 5 says: the per-section name check for every section but `surface`;
"a test file that lost more `assert` lines than it gained, or more `pytest.raises`"; and "An
`xfail` cites a decision when a `D<n>` not followed by a digit appears anywhere in its call,
read to the closing bracket".

## Deviations

- **The state-case README template.** The note changed `build.py`'s `surface` build and the
  contract only. `build.py`'s section README wrote its name cell bare (`| load_trades |`), which
  the one-name rule fails, so `shipped` would have printed `shipped: no (surface check FAIL)`.
  The template now writes `` `{name}` `` and `` `{name}(path)` ``. The `surface` build already
  wrote what `surface-pass` writes and was left as it was.
- **The hook-event build's README.** The note said the built README's name cells already
  held one identifier each. It had no **Entry points and interfaces** table at all, so
  `gate-surface-names-grouped-fail` had no row to change. `build.py` now writes one row,
  `` `load_trades` ``, `Public: yes`, and the contract a **Public surface (intent)** item naming
  it, so every `data/ingest` record carries `PASS surface names data/ingest`.
- **`gate-assert-rewritten-pass`'s rewrite** is `load_trades(csv_file)` to
  `load_trades(str(csv_file))`, not `load_trades(Source(p))`: the fixture has no `Source`, and
  the unit suite has to stay green for the case to show the Guarded line alone. Like the other
  two assert cases, it puts a round-1 review at `{RUN_SHA}`. Without one the diff starts at the
  empty tree and no line is ever removed.
- **`gate-tail-ruff-arrow`'s command** builds the path from two strings
  (`'…/ingest/__init__' + '.py:3:1'`). The FAIL line echoes the command, so with the path
  written whole the case passed against the 2.3 gate too.
- **`--surface <pkg> --section <s>` with a section the contract lacks** prints `no section <s>
  in <contract>` and exits 2, as `--inputs` and `--fields` do. The note did not say.
