# 04 — Design against the paths

Phase 4. The designer designs `surface` from the contract right after PLAN, beside the sections
it depends on, and writes into every section's §4 a skeleton for each entry point a **Call
paths** entry names, adding no frame the path does not list; the tester builds the early
surface's fakes from **Section interfaces**; the driver sends every role the dependency READMEs
`status.py --fields` says exist; the implementer builds the surface's pipelines from the
design's skeletons; `project-structure` §1 says the surface's design exists from PLAN. One
`contracts.yml` claim forbids the old order from being written anywhere an agent reads. It
closes the design's second workflow: every section is built to a path that already reads well.

## Decisions

- **A private phase stays off the path.** The design allows "a private phase the style guide
  allows" in a skeleton. A phase that itself made the effect call, or called the next frame,
  would be a frame the contract does not list, so the rule written here is: every call that
  leads to the effect is the path's next frame or the effect itself, and a private phase is a
  call that returns before the path continues (a transformation, a validation). This is what
  makes `frames to effect: <n>` equal the contract's count without a second count.
- **The spec-change's Clause is the Call paths line.** A frame the path lacks is raised as
  `spec-change:contract` with **Clause** the command's **Call paths** line, **Said** the path
  quoted, **Found** the step the design cannot take without the frame, so the architect at PLAN
  reads the exact line to change.
- **The driver copies one line for three roles.** The designer, tester and reviewer rows for
  **Dependency READMEs** all read `the dependency readmes: line of status.py --fields`; the
  designer keeps the `own:` prefix rule in `delta` and `document` modes. One source, so the
  three never disagree about what exists.
- **The forbid claim is scoped to agents and skills here.** `README.md`, `site/flow.md` and
  `site/workflows/*.md` still say the surface is designed from every sibling README until phase
  7 rewrites them; the claim's `files:` widens to them there.

## Specification

### `designer.md`

Lines 15–20, replace the paragraph with:

> You may be running beside other designers, one per ready section, spawned in one message.
> None of them designs a section yours depends on, with one exception: the `surface` section is
> designed right after PLAN, beside the very sections it depends on, from the contract alone.
> The contracts, and the shipped READMEs of the sections you depend on where they exist, are
> the only ground you share. Every convention you invent on your own is one the other sections
> will have invented differently, so prefer what the documents give you, and when you must go
> beyond them, say so where the next reader looks rather than deciding quietly.

Hard rules, the **Read what your prompt names** bullet: "a sibling you depend on is described by
its shipped README, and one you do not depend on is not yours to design against" becomes "a
sibling you depend on is described by its shipped README — or, before it ships, by the
contract's **Section interfaces** — and one you do not depend on is not yours to design
against".

**Inputs** item 5 gains, after "*May be `none`.*": "The driver sends only the READMEs that exist
(`status.py --fields`), so `surface`, designed before its siblings are built, is sent `none`."

The surface paragraph (the one beginning "**The `surface` section**, in every mode") becomes:

> **The `surface` section**, in every mode: its design is written right after PLAN, before any
> sibling is built, from the contract — **Pipelines** for the steps, **Call paths** for the
> frames each step is, **Section interfaces** for every name a step calls, **Public surface
> (intent)** for the public names — so every other section is designed to pipelines that already
> exist on paper. Where a sibling's README is in `Dependency READMEs:` it outranks the contract
> for that sibling's names, as for any section; where none is, the contract's signature is the
> one you design to, and the implementer reconciles it against the README when the surface is
> built, last. Its §4 is one fenced skeleton per **Pipelines** entry, in `pipelines.md`'s shape,
> each step a frame of the command's **Call paths** entry. A name §6 of the contract promises
> and neither a README nor **Section interfaces** provides is a spec-change, never a name you
> design into existence.

Template item 4 **Workflow / pipeline**, appended after "The implementer builds the path you
write, and the paths review follows it from the command.":

> When the contract has **Call paths**, add for every entry point of this section that a path
> names — a frame `<section>.<name>` — and, for the `surface` section, for every pipeline
> (never for a command function, which makes one call), a fenced skeleton: the signature on its
> first line, then each step as a call statement under a one-line comment, then a last line
> `frames to effect: <n>`, where `<n>` is the contract's count from this frame to the path's
> effect (1 when this frame makes the effect call itself); when the frame is on several paths
> with different counts, one line lists each with its kind: `frames to effect: 2 (vendor
> call), 1 (file write)`. Every call that leads on to an effect is the path's next frame, or
> the effect; a step that reaches no effect (a pure transformation a **Pipelines** entry
> names) is written as a step and is no frame; a call to a private phase of this section is
> allowed only off the path — it returns before the path continues. A step's callee is named
> as the contract names it (`ingest.download_bars`); its module is added only when a shipped
> README gives it. Cite above the block every command whose **Call paths** entry names the
> frame. A frame a path does not list and the design cannot do without is a `spec-change:
> contract` (**Spec-change**), never a frame you add: a frame added quietly is how depth grows,
> and the architect decides it before code exists. A contract without **Call paths** has no
> skeletons to write.

**Spec-change**, the opening sentence: after "or when a probe doc contradicts the section's
row" add ", or when a **Call paths** entry cannot be met as written — a frame it names that
**Section interfaces** does not define, or a step this section cannot take without a frame the
path does not list". Step 2's `Clause:` parenthesis becomes "(the contract row or heading it
cites; for a path, the command's **Call paths** line)".
