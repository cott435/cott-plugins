# 02 — the shape slice

Phase 02. The stop gate gains the first check that pushes back when a function is split for
the linter's sake: `status.py --shape <pkg> --section <s>` fails a private helper the run
added that has one call site in the package and three statements or fewer, and the gate
copies its lines into the section's record. `python-style-guide` "Function shape" already
forbids that helper ("Do not extract a single-use helper whose name merely restates a few
lines of code"); until now nothing checked it, and 416 of the 691 private helpers in `quant`'s
`data` package are called from one place. Options bags, the two `MEASURED` lines and the
adopted-code base arrive in phase 05, once the style guide states the bag rule (phase 03) and
the resolver exists (phase 04).

## Decisions

- **The diff parser moves into `status.py`.** `--shape` needs the lines a run added, and
  `gate_on_stop.py` holds the only parser of them (`diff_lines`). The gate's docstring says
  "The parsers are status.py's, imported; there is no copy of any of them here", and
  `status.py` cannot import the gate. So `EMPTY_TREE`, `_untracked`, `diff_lines` and
  `review_base` move to `status.py` unchanged, and the gate calls `status.diff_lines` and the
  rest. The existing `hook-events` cases prove the move changed nothing.
- **`--shape` computes its own base.** The gate runs it as a command, with no base argument:
  the base is `status.review_base(pkg, section)`, the newest review round's `Commit:` when it
  is an ancestor of `HEAD`, else the empty tree. That is the Guarded base, so a helper the
  last review saw is never failed.
- **A call site is counted by name, and the count errs toward more.** The reference rules
  below over-count rather than resolve types, so the check never fails a helper that has a
  second caller it could not see. A reference that is not a call (the helper passed by name
  as a callback, stored in a mapping, used as a decorator) exempts the helper: that is the
  design's "a function passed by name to a library as a callback".
- **An overridden method is exempt.** A private method name defined in more than one class of
  the package is called through `self` from a base class by construction; the design's
  exemption list ("these have one call site by construction") covers it in spirit.
- **Both gate paths run it.** `run_checks` (the section from the transcript) and
  `run_checks_legacy` (the fallback and `--report`, which `/dev-team:pair` runs at wrap-up),
  beside `check_surface_names` in each.
- **The retry text explains the line, in the gate.** `implementer.md` is not edited until
  phase 08, so the gate's own message says what a `FAIL shape` line asks for.
- **No `quant` run in the pass bar.** The design's slice is "run on one section of `quant`'s
  `data` package"; that repo is not on this machine (`~/dev` has no `quant`). The slice is
  proven on the two fixture suites, and **Done when** ends with the command to run there by
  hand.

## Specification

### `status.py --shape <pkg> --section <s>`

Usage line (the docstring's second usage line gains it):

```
                          [--shape <pkg> --section <s>]
```

The docstring's new paragraph goes after the **Gate record.** paragraph and before
**Scaffold.**, so it lies outside every span `contracts.yml` reads in this file (the state
names end at `Ready:`, the evidence list ends at `**Gate record.**`, the `--inputs` reader
span starts later). It uses dashes, not a numbered bold list:

```
**Shape.** `--shape <pkg> --section <s>` prints the section's shape check, the lines the stop
gate copies into its record. It judges the functions and methods defined in the section's
non-test code (its path, nested sections excluded) whose `def` line the run added: a line
`git diff -U0 <base>` adds under the section's code, or any line of an untracked file, where
<base> is the newest review round's `Commit:` when it is an ancestor of `HEAD`, else the empty
tree.

- `FAIL shape: <file>:<line> trivial-helper <name>` — a private function or method (`_name`,
  not a dunder) with three statements or fewer, the docstring not counted, that is referenced
  exactly once in the package's non-test code, by a call. Exempt: a function decorated
  `property`, `cached_property` or `<name>.setter`/`.getter`/`.deleter`; a method whose name is
  defined in more than one class of the package; a helper referenced anywhere other than as
  the function of a call (passed by name, stored, used as a decorator).
- `PASS shape <pkg>/<s>` — when no FAIL line was printed.

Exit 1 on a FAIL line, else 0; 2 on a missing `--section` or a section the contract lacks.
```

Rules, as code will have them:

- **Files judged.** Every `.py` under the section's path (`_paths(pkg, section)["code"]`:
  the path, nested sections excluded) that is not a test file. A test file has a `tests`
  directory in its path, or a name starting `test_` or ending `_test.py`.
- **Files searched for references.** Every non-test `.py` under the package's source root:
  the `surface` row's path when the contract has one (as `surface_check` resolves `top`),
  else `<package root>/src/<pkg>`.
- **Statements.** The number of `ast.stmt` nodes inside the function, found with `ast.walk`,
  less the function itself and less a leading docstring expression. Nested statements count.
- **References to `_name`.**
  - A module-level function: every `ast.Name` load of `_name` in its own module; every
    `ast.Name` load of it in another searched file that has `from … import _name`; every
    `ast.Attribute` load whose `attr` is `_name` in any searched file.
  - A method (a `def` directly in a class body): every `ast.Attribute` load whose `attr` is
    `_name` in any searched file.
  - A function nested in another function: every `ast.Name` load of `_name` inside the
    enclosing function.
  - An `import` statement is not a reference.
- **Trivial single-use.** Exactly one reference, and that reference is the `func` of an
  `ast.Call`. Zero references is not this rule's business.
- **Added.** The `def` line's number (`node.lineno`) is among the file's added lines:
  `diff_lines(review_base(pkg, section), <the section's code pathspec>)`, sign `+`.
- **Output.** FAIL lines sorted by file, then line; `<file>` repo-relative, posix. A file
  that does not parse is skipped.

Flag handling: `--section` is accepted with `--surface` or with `--shape`. `--shape` with no
package or no `--section` prints `--shape needs a package and --section a section: status.py
--shape <pkg> --section <s>` and returns 2. A section the contract lacks prints `no section
<s> in docs/packages/<pkg>/contract.md` and returns 2. `surface` is a section like any other
here: its code is the package's top level with the other sections excluded.

### `hooks/gate_on_stop.py`

```python
def check_shape(pkg: str, section: str) -> list[str]:
    """The shape check, `status.py --shape <pkg> --section <section>`: its PASS, FAIL and
    MEASURED lines as printed."""
    code, out = _run([sys.executable, str(STATUS_PY), "--shape", pkg, "--section", section], status.ROOT, 60)
    lines = [ln.strip() for ln in out.splitlines() if ln.split(" ", 1)[0] in ("PASS", "FAIL", "MEASURED")]
    if code not in (0, 1) or not lines:
        return [f"FAIL shape: status.py --shape {pkg} --section {section} exited {code}: {_tail(out)}"]
    return lines
```

- `run_checks`: `own += check_shape(pkg, sec)` on the line after the surface check.
- `run_checks_legacy`: `own += check_shape(pkg, section)` for every target, after the surface
  checks.
- `_retry_message`: when any line of `fails` starts `FAIL shape:`, this is appended before the
  "A FAIL you cannot clear" sentence:

  ```
  A `FAIL shape` line names a definition this run added that `python-style-guide` "Function
  shape" forbids. Fix the code as that section says: inline the helper into its one caller, or
  give the phase a seam the section's list names. Never clear it with a rename, a second call
  site or a suppression.
  ```

- Docstring step 5: after "for every section but `surface`;" add "then the shape check,
  `status.py --shape <pkg> --section <section>`, for every section, its lines copied as
  printed;". The numbered lists under "The record's lines, in order" are untouched: the shape
  lines are **checks** lines whose first word is `PASS`, `FAIL` or `MEASURED`.
- Step 4 of the docstring says where the diff parser now lives: "(`status.diff_lines`)".
