# 01 — lint floor and cap

Phase 01. The lint block stops counting keyword-only parameters: `PLR0917` (positional only)
replaces `PLR0913`, which is what pushed an implementer at five arguments into a `**options`
bag. It also gains a version floor, because a ruff too old to run `PLR0917` without preview
skips it with a warning and exits 0. `project-structure` §2 names the new rule and says how a
limit is met. Six fixture cases that depend on ruff's default rules are repaired so both
fixture suites pass on the ruff the block now requires. This is step 1 of the design's
**Build order**; with phase 02 it is the design's smallest end-to-end slice.

`V` below is the version PF-1 logged (`2.5-readability-00-overview.md`, **Phase 0 evals**).
Do not start before PF-1 and PF-2 are logged and the ledger's phase-0 row is `done`. If PF-2
came out otherwise, stop and ask the user before any edit.

## Decisions

- **The fixture suites run on ruff ≥ V, through a shim.** The `ruff` on this machine's PATH
  is 0.12.0 (`/opt/anaconda3/bin/ruff`), and nothing here upgrades the user's tools. Create
  `evals/workspace/bin/ruff` (gitignored), mode 755:

  ```sh
  #!/bin/sh
  exec uvx ruff@0.16.9 "$@"
  ```

  and run both suites as `PATH="$PWD/evals/workspace/bin:$PATH" python3 evals/fixtures/<suite>/check.py`.
  Every later phase runs them the same way; the ledger's **Standing facts** says so.
- **`0.16.9` in the shim, `V` in the floor.** The shim is the version the design verified;
  the floor is the lowest version that works, so a repo is not forced to the newest ruff.
- **The seam sentence names no gate check.** The gate fails a trivial helper from phase 02 and
  an options bag from phase 05; `project-structure` is preloaded into four agents, so it
  states the rule once and is not edited again as the checks arrive.
- **A new `forbid` claim holds the old rule's name out of the prompts.** A prompt that still
  says `PLR0913` sends an agent to a check that no longer runs.
- **A repaired case keeps its meaning.** A case that fails under ruff ≥ V because ruff's
  default rules changed is repaired in its planted files, so the same thing is tested; its
  `expect` block changes only where a string quotes ruff's own output.

## Specification

### `pyproject-lint-config.toml`

Under `[tool.ruff]`, after `line-length = 88`:

```toml
# PLR0917 (below) is preview-only before this version: an older ruff prints a warning, skips
# the rule and exits 0, so a repo would lose its argument cap without anyone noticing. With
# this line an older ruff refuses to run and says why.
required-version = ">=V"
```

`select` becomes:

```toml
select = ["E", "F", "I", "B", "C901", "PLR0917", "PLR0915", "S", "D"]
```

The comment above the `tests/**` ignores becomes:

```toml
# Asserts and undocumented tests are fine. So is a test or fixture with many arguments: pytest
# injects one per fixture and one per parametrize name, so PLR0917's cap (project-structure's
# limit on a function's design) would force contorted fixtures, not better code.
```

and each of the four lines that lists `"PLR0913"` lists `"PLR0917"` instead. The pylint table
becomes:

```toml
[tool.ruff.lint.pylint]
max-positional-args = 5      # project-structure §2 hard limit; keyword-only parameters are free
max-statements = 50          # project-structure §2 hard limit
```

```
| Positional parameters (keyword-only ones are free) | 4 | 5 | ruff `PLR0917` |
```

After the paragraph that starts **Soft means plan the split; hard means split before
finishing the task.**, one new paragraph:

```
**A limit is met with a seam, never with a dodge.** A function past a limit is split where
`python-style-guide` "Function shape" says a split buys something. A parameter past the
positional cap becomes keyword-only (after `*`), which the cap does not count. A `**options`
bag, a tuple packed to carry two parameters as one, and a helper that only moves three
statements out of sight all pass the linter and cost the reader more than the limit saved.
```

### Fixture cases

`fmt-no-config.json`: `expect.stderr_lacks` becomes `["PLR0913", "PLR0917"]`. Its test
function still takes six arguments under `tests/intent/`, where the cap is off.

`fmt-positional-cap.json`: modelled on `fmt-no-config.json` (`"script": "format"`, `"repo":
"arch"`, the same event with `agent_type` `dev-team:implementer`), writing and naming
`packages/data/src/data/ingest/wide.py`:

```python
"""Module for the positional-cap case."""


def wide(a, b, c, d, e, f):
    """Take six positional parameters.

    Args:
        a: One.
        b: Two.
        c: Three.
        d: Four.
        e: Five.
        f: Six.
    """
    return a, b, c, d, e, f
```

`expect`: `"exit": 2`, `stderr_contains` `["PLR0917"]`.

`fmt-keyword-only-free.json`: the same, the file `packages/data/src/data/ingest/free.py`:

```python
"""Module for the keyword-only case."""


def free(a, b, c, *, d, e, f, g):
    """Take three positional parameters and four keyword-only ones.

    Args:
        a: One.
        b: Two.
        c: Three.
        d: Four.
        e: Five.
        f: Six.
        g: Seven.
    """
    return a, b, c, d, e, f, g
```

`expect`: `"exit": 0`, `stderr_lacks` `["PLR0917", "PLR0913"]`.

The six cases that pass on ruff 0.12.0 and fail under the shim (seen 2026-10-01, 177 of 183
passing): `fmt-repo-config`, `gate-diff-before-review`, `gate-guarded-decision-constant`,
`gate-guarded-exception`, `gate-report-fail`, `gate-xfail-wrapped-pass`. In each, a planted
file trips a rule that ruff's defaults gained (`fmt-repo-config`: `PLW0129` on an assert of a
string literal; the gate cases: one fixable finding at line 3 of the planted file, which
turns `PASS lint` into `FAIL lint`). Repair the planted file so ruff's defaults at 0.16.9
pass it and the case still plants what its note says it plants.

`README.md`, a new paragraph before **The 2.2 layout here.**:

```
**The 2.5 lint floor** (`site/notes/2.5-readability-01-lint-floor-and-cap.md`). The plugin's
lint block requires ruff V or later, so both suites run with such a ruff first on PATH; the
plan's shim is `evals/workspace/bin/ruff`. `fmt-positional-cap` (six positional parameters:
`PLR0917`) and `fmt-keyword-only-free` (three positional, four keyword-only: clean) pin the
cap; `fmt-no-config` now lacks both the old and the new code. Six cases whose planted files
tripped a rule ruff's defaults gained were repaired without changing what they test:
`fmt-repo-config`, `gate-diff-before-review`, `gate-guarded-decision-constant`,
`gate-guarded-exception`, `gate-report-fail`, `gate-xfail-wrapped-pass`.
```

with `V` written as the number, and the last line of the file becomes `Needs ruff V or later
on PATH and `pytest` importable by `python3`.`
