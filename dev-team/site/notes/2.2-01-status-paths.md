# 01 — status-paths

Phase 1. Teaches `status.py`, the one state derivation every hook and the driver import, the
2.2 layout: the per-section inbox, and `deviations/`, `reviews/<section>/` and `changes/` under
`docs/packages/<pkg>/`, with every old location still read. It adds what the hooks will need
in phases 2 to 4 — `inbox_path`, `section_from_transcript`, `cached_section` — and the parser
changes the audit asked for: the optional `— <k>` on a ledger heading (F13), the full item name
in `clause_key` (W3), `--rounds` printing the section's last commit (F12), and the run gate's
inbox check. It writes nothing new anywhere; every writer changes in a later phase. The gap it
closes: no later phase can write to the new paths until the readers read them.

## Decisions

- **Read fallback, never a write fallback.** Every reader lists the new path first and the old
  paths after it; the only function that *returns a write path* is `inbox_path`, and the
  writers' paths live in the templates (phase 5). Reason: the design's docs-layout decision —
  old locations read, never written.
- **`section_from_transcript` takes the first line that starts `Section: `**, anywhere in the
  first `user` record, and returns `None` when a line starts `Scaffold:` or when no `Section:`
  line exists. Reason: the eval harnesses prepend a `Repo:` line to spawn prompts, so "first
  line" would fail exactly where the plan is tested.
- **`cached_section(event)` lives here, not in a hook**, and derives the transcript path per
  F1 when the event has no `agent_transcript_path`. Reason: two guards and the gate share it,
  and the design's Cost table puts the cache under `${CLAUDE_PLUGIN_DATA}/section/<agent_id>`.
- **`--rounds commit:` covers the section's code, unit tree, intent tree and README**, not its
  design. Reason: it is the commit the reviewer reviewed; a design commit after the code would
  otherwise make the REVIEW rule see code "newer than" a review of the same code.
- **The run gate's inbox check reads every inbox of the repo**, not only the package's.
  Reason: a stub lost in another package's inbox is still a stub lost.
- **The heading regex accepts a 2.x heading without `— <k>`** and stores `k` as `""`.
  Reason: **What must not break**, repos built under 2.0 or 2.1.

## Specification

### `status.py` docstring

Add, after the paragraph that begins "The **ledger** is one file per section":

> Since 2.2 the section's ledger is `docs/packages/<pkg>/deviations/<section>.md`; the 2.0
> location `docs/deviations/<pkg>/<section>.md` and the pre-2.0 `docs/deviations.md` are still
> read, and an entry is edited in the file that holds it. Review reports are
> `docs/packages/<pkg>/reviews/<section>/<date>-r<n>-<a|b|s>.md`; the 2.0 names
> `docs/reviews/<date>-<pkg>-<section>-r<n>-<letter>.md` are still read as round `n`. Change
> files are `docs/packages/<pkg>/changes/<slug>.md`, one per affected package; a
> `docs/changes/<slug>.md` is still read as naming every package its **Affected sections**
> name. A ledger heading may end `— <k>`, the entry's 1-based sequence in its file; a heading
> without it is a 2.x ledger and `k` is absent. The **inbox** is
> `docs/packages/<pkg>/decisions/<section>.md`: `## D? — <question>` stubs and `## D<n>` entries
> holding `Applied:` lines, merged into `docs/decisions.md` by `hooks/sync_decisions.py`. This
> script never writes it; `--run-gate` fails on an inbox holding anything the central ledger
> does not.

Under `Rounds:` add: `--rounds <pkg>/<section>` prints a third line, `commit: <short sha>`,
the newest commit touching the section's path, `tests/unit/<section>`, `tests/intent/<section>`
and its README, or `commit: none` — the reviewer copies it as its report's `Commit:` (F12).

The `--inputs` list: field 9 **Review** and field 11 **Change file** each say "from either
location". The `Usage:` line is unchanged (`--rounds` keeps its arguments).

- `deviation_entries`: heading regex becomes
  `` `?([\w.-]+)/([\w.-]+)`?\s+[—–-]+\s+(\S+)\s+[—–-]+\s+`?([\w:-]+)`?(?:\s+[—–-]+\s+(\d+))?\s*$ ``;
  the entry dict gains `"k": m.group(5) or ""`.
- `entry_rev`: the `-S` search runs over `docs/deviations.md`, `docs/deviations`, and
  `docs/packages/*/deviations` (pass `docs/packages` as a pathspec limited by `-- 'docs/packages/*/deviations/*.md'`),
  so an entry moved between any two locations keeps its first commit.
- `_reports(pkg, section)`: also globs `DOCS/packages/<pkg>/reviews/<section>/*.md` with the name
  regex `\d{4}-\d{2}-\d{2}-r(\d+)-([abs])\.md`; a file there that does not match is ignored. Old
  names as today.
- `change_files()`: `docs/changes/*.md` (key `"pkg": None`) then `docs/packages/*/changes/*.md`
  (key `"pkg": <dir name>`); `open_changes(pkg, section)` treats a per-package file as naming
  only that package's sections (an `Affected sections` line naming another package in a
  per-package file is ignored), a flat file as today.
- `clause_key(text)`: `(n, item)` where item is the text after `§<n>\s+` up to the first of
  `:`, `;`, `,`, a closing backtick, or end of line, then backticks and `*` stripped, whitespace
  collapsed, lowercased. `design §5 load trades from csv: one dict` → `("5", "load trades from csv")`.
- `section_from_transcript(path)`: read the file; for each line, `json.loads`; the first record
  whose `type` is `"user"`: take its text (`message.content` as a string, or the concatenated
  `text` of its list items); if any line of the text starts `Scaffold:` return `None`; else the
  first line matching `^Section:\s+([\w.-]+)/([\w.-]+)\s*$` gives `(pkg, section)`; none →
  `None`. An unreadable or malformed file → `None`.
- `subagent_transcript(event)`: `event.get("agent_transcript_path")` when present; else, with
  `transcript_path` and `agent_id` both present,
  `Path(transcript_path).with_suffix("") / "subagents" / f"agent-{agent_id}.jsonl"`; else `None`.
- `cached_section(event)`: cache file `${CLAUDE_PLUGIN_DATA}/section/<agent_id>` (else
  `<cwd>/.dev-team/section/<agent_id>`), holding `<pkg>/<section>`, `scaffold`, or `none`; on a
  miss, read the transcript, write the cache, return. `none`/`scaffold` → `None`.
- `unsynced_inboxes()`: for every inbox file, every entry: `n == "?"` → `"<path>: D? stub not
  yet numbered"`; a numbered `n` with no `## D<n>` in `docs/decisions.md` → `"<path>: D<n> not
  in docs/decisions.md"`; an `Applied:` line (stripped, exact) absent from the central `D<n>`
  entry → `"<path>: D<n> Applied: line not in docs/decisions.md"`.
- `run_gate(pkg)`: after the dirty-tree check, `for r in unsynced_inboxes(): fails.append(f"unsynced
  inbox — {r}; run python3 <plugin>/hooks/sync_decisions.py --all and commit it")`, where
  `<plugin>` is `Path(__file__).resolve().parents[3]`.
- `implementer_inputs`: **Review** and **Change file** values come from `_reports` and
  `open_changes`, which now cover both locations; no other change.
- `main()`: `--rounds` prints `commit: {section_commit(pkg, sec) or 'none'}` as a third line.

### State-cases

`build.py` macros: `review` and `deviation` take `"layout": "new" | "old"` (default `new`):
`new` writes `docs/packages/data/reviews/<section>/<date>-r<n>-<letter>.md` and
`docs/packages/data/deviations/<section>.md` with heading `## data/<section> — <date> — <kind> — <k>`
(`k` the entry's 1-based sequence); `old` writes the 2.0 paths and heading as today. The
`legacy: true` flag keeps writing `docs/deviations.md`. `+ change` macro:
`{"do": "change", "slug", "sections", "status", "layout"}` writes `docs/packages/data/changes/<slug>.md`
(`new`) or `docs/changes/<slug>.md` (`old`). `+ inbox` macro: `{"do": "inbox", "section",
"entries": [...]}` writes `docs/packages/data/decisions/<section>.md` verbatim from the given
entries. Existing cases keep passing without edits: their macros default to `new` only where
they set no layout — so every existing case that uses `review` or `deviation` gains
`"layout": "old"` **or** stays as is and is checked to pass under `new`. Choose the second:
existing cases run under the new layout and one new case per rule covers the old layout.
