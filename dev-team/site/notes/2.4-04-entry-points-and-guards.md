# 04 — entry points and guards

Phase 04. What an agent may write, and through what. Today a section that owns an entry
point (a `pytest11` plugin, a migrations group) cannot register it: the write guard refuses
the package `pyproject.toml` to every section but `surface`, and `locked.py` only lets `uv`
through, so three sections of one audited package each needed a hand edit by the user (open
item 1). This phase adds `entry_point.py`, which writes one entry-point line under the
dependency lock, and teaches the Bash guard to let it through for the caller's own package
only. The same two guards get the fixes the design groups with them: a `surface` implementer
can no longer write a sibling section's code, a suppression comment cannot be written into
an intent test, both guards switch on from `docs/brief.md` so `plan-repo`'s agents are
guarded, and a researcher may redirect to its scratch outside the repo. No agent is told
about `entry_point.py` yet: phases 6 and 7 do that. Until then it can be run by hand.

## Decisions

- **The command line is `entry_point.py <pkg> <group> <name> <target>`,** run as the command
  `locked.py deps` wraps. Positional, like `locked.py` itself.
- **The edit is a text insert, checked with `tomllib`.** The script stays standard-library
  only; it never re-serialises the file, so comments and order survive, and it parses the
  result before it keeps it.
- **`uv sync --all-packages` runs only when the repo root has a `uv.lock`,** the same test the
  gate uses to pick its runner. A repo without one is not a uv workspace, and the fixture
  suite needs no `uv`.
- **`console_scripts` and `gui_scripts` are refused.** Those are `[project.scripts]`, the
  `surface` section's.
- **The Bash guard refuses `entry_point.py` unless `locked.py deps` wraps it and the caller's
  `Section:` names the same package.** A caller with no readable `Section:` line (a scaffold
  run, a lost transcript) is refused: nothing but a section implementer has an entry point to
  add. The main thread is not guarded, so a user or `/dev-team:pair` can run it.
- **"Adds a suppression" is a count.** A Write is refused when its text holds more matches
  than the file on disk does; an Edit when `new_string` holds more than `old_string`. An edit
  that keeps an existing comment in place passes.
- **A missing text field fails open.** If the event has no `content` or `new_string`, the
  suppression check is skipped and the path rule decides alone.
- **The sibling rule generalises nesting.** A section may not write under any other
  section's path that lies inside its own, which for `surface` is every sibling and for a
  parent section its nested ones. `status._paths` already excludes them the same way.
- **The suppression patterns are the gate's three:** `# noqa`, `# type: ignore`, `# pragma:
  no cover`. `skip` and `xfail` stay the gate's to judge, since an `xfail` naming a `D<n>` is
  allowed.

## Specification

### `skills/status/scripts/entry_point.py`

A script, not a registered component (`plugin-anatomy` has no reference for one; its tests
are mechanical). Module docstring, in full:

```
"""Add or replace one entry-point line in a package's pyproject.toml.

Usage:  python3 locked.py deps -- python3 entry_point.py <pkg> <group> <name> <target>

Run from the repo root, under the `deps` lock (locked.py): parallel implementers share the
package `pyproject.toml`, and only the lock serialises them. Writes the line
`<name> = "<target>"` under `[project.entry-points."<group>"]` in `<package root>/pyproject.toml`,
creating the table when it is absent, then runs `uv sync --all-packages` when the repo root
has a `uv.lock`. Standard library only; the file is edited as text and parsed with `tomllib`
before it is kept, so comments and order survive.

Refused, exit 2 with the reason on stderr: a `<target>` whose module is not `<pkg>` or under
it; a module whose file does not exist yet (`<top>/<path>.py` or `<top>/<path>/__init__.py`,
`<top>` the directory holding the package's import root); the groups `console_scripts` and
`gui_scripts`, which are `[project.scripts]` and the surface section's; a `<pkg>` with no
`pyproject.toml` at its root; a `<group>` or `<name>` outside `[A-Za-z0-9_.-]+`.

Exits 0 printing `entry point: [<group>] <name> = <target> in <path>`, or `entry point
unchanged: …` when the line is already there (no sync); 1 when the edited file does not parse
or does not hold the entry, with the file restored; else `uv sync`'s exit code.
"""
```

Behaviour the docstring does not spell out:

- `<target>` is `module` or `module:attr`. The module is checked, the attribute is not.
- The package root and the import root come from `status.py` (`set_root(cwd)`,
  `package_root(pkg)`, and the `surface` row's path as `surface_check` resolves `top`).
- A table header is found as `[project.entry-points."<group>"]` or, for a group that is a
  bare TOML key, `[project.entry-points.<group>]`. A new header is always written quoted.
- Inside the table, a line whose key is `<name>` or `"<name>"` is replaced in place;
  otherwise the line is inserted after the table's last non-blank line.
- A new table goes after the `[project.scripts]` table when the file has one, else before
  `[build-system]`, else at the end, with one blank line before and after.
- `<name>` is written bare when it matches `[A-Za-z0-9_-]+`, else in double quotes.

### `hooks/guard_bash.py`

- **Scope.** The guard acts when `agent_type` starts `dev-team:` and `<cwd>/docs/brief.md`
  or `<cwd>/docs/architecture.md` exists.
- **`entry_point.py`.** `_refusal` and `_locked` take the event. A command whose program is
  python and whose script's basename is `entry_point.py`:
  - not wrapped by `locked.py` → refusal `entry point: run it through locked.py deps`;
  - wrapped, the lock name not `deps` → the same refusal;
  - wrapped under `deps`, and `status.cached_section(event)` returns `(pkg, section)` with
    `pkg` equal to the script's first argument → let through;
  - otherwise → refusal `entry point: <pkg> is not this run's package`, or `entry point: no
    Section: line names this run's package` when the section cannot be read.
  `status` is imported as `guard_writes.py` imports it, inside a `try` whose failure refuses.
- **The researcher's scratch.** `_allowed_target(target, cwd, agent)`: for
  `dev-team:researcher`, a target whose real path is outside the repo root is allowed. Inside
  the repo the rule is the same for every role.
- **The refusal's wording.** A refused redirect prints

  ```
  dev-team bash guard: <agent> may not redirect to <target>: it is outside .dev-team/tmp/. <RULE>
  ```

  Every other refusal keeps `may not write a repo file from the shell (<found>)`.
- The docstring's first paragraph says all four. `RULE` gains "an entry point goes through
  `locked.py deps -- python3 …/entry_point.py`".

### `hooks/guard_writes.py`

- **Scope.** As the Bash guard: `docs/brief.md` or `docs/architecture.md`.
- **Sibling paths.** `section_scope` also returns `nested`: the `path` of every other section
  of the package that starts with this section's path plus `/`. In `main`, a scoped
  implementer's path under any `nested` entry is refused before the scope globs are tried,
  with

  ```
  dev-team write guard: <agent> (<pkg>/<section>) may not write <path>: it is <pkg>/<other>'s. <SHARED>
  ```

- **Suppression comments.** After the path is found allowed and before `return 0`, for a path
  matching `**/tests/intent/**`: with `SUPPRESS` the three patterns the gate's `ADDED` uses
  for `# noqa`, `# type: ignore` and `# pragma: no cover`, count matches in the new text
  (`tool_input.content` for Write, `tool_input.new_string` for Edit) and in the old
  (the file on disk for Write, `0` when it does not exist; `tool_input.old_string` for Edit).
  More in the new than in the old is refused, exit 2:

  ```
  dev-team write guard: <agent> may not add `<item>` under tests/intent/ (<path>). Write the assertion the design supports; a check that still fires is a `Not written:` line, and an Exceptions row is the user's call.
  ```

  The field names are PF1's result. If PF1 found other names, use those and say so in the
  log.
- `SHARED` becomes `"Shared edits — pyproject.toml (dependencies, entry points), uv.lock,
  .gitignore — go through locked.py."`
- The docstring: its scope sentence; the sibling rule in the **Section scope** paragraph
  ("a path under another section's `path` is that section's, whatever the globs say; for
  `surface` that is every sibling"); the suppression rule; and that an entry point in the
  package `pyproject.toml` goes through `locked.py` and `entry_point.py`, so no section but
  `surface` has the file in scope.

```

```

## Deviations

- **The entry-point fixture writes two more files.** The note's `evals/fixtures/entry-point/`
  paragraph names `packages/core/src/core/testing/plugin.py` only. The `dotted-name` case
  targets the module `core.testing`, whose file under the script's own rule is

  `check.py` also writes `packages/core/src/core/__init__.py` and
  `packages/core/src/core/testing/__init__.py` (both empty), and says so in its docstring and
  README. No behaviour of `entry_point.py` was changed for it.
