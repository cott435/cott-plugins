# 07 — Docs, end to end, and the release proposal

Phase 7. The user-facing documents say what 2.6 does — the README, `site/flow.md`, the
workflows, the CHANGELOG's unreleased section — the forbid claim from phase 4 widens to them,
one end-to-end eval drives a package from its contract through the early surface design to a
paths review against the contract, and the release is proposed in chat. It closes the plan: a
reader of the README learns the new order before meeting it in a run.

## Decisions

- **Minor bump, 2.6.0.** New heading, new flag, new readiness rule, new line in `--fields`; every
  pre-2.6 contract keeps its behaviour until its close writes the heading (design, **What must
  not break**). Nothing a user typed before stops working.
- **The e2e eval runs with real spawns from a seeded contract that already has Call paths.**
  The architect's writing of the heading is phase 2's eval; here the question is whether the
  driver, the designers, the tester, the implementers and the paths reviewer together honour
  it. The seed's contract carries a hand-written **Call paths** in the template's form.
- **The flow chart's `surf` node is the one chart edit.** `site/flow.md:30` reads "surface
  section — design from every sibling README"; it becomes "surface section — designed from
  the contract after PLAN, built last from every README", and the PLAN node gains "+ Call paths".

## Specification

### `README.md`

Every sentence that says the surface is designed last or from the sibling READMEs is rewritten
to the phase-4 wording: designed and tested right after PLAN from the contract, built last from
the shipped READMEs. The package-contract description gains:

> **Call paths** (item 5 of the contract) fixes, per command, the frames from `cli.py` to each
> external effect and a depth budget (8 unless a decided `D<n>` says more), before any section
> is designed. The surface's design and intent tests are written right after PLAN from the
> contract; every section's design carries a skeleton for each entry point a path names, with
> `frames to effect`; the paths review runs `status.py --paths <pkg> --against-contract` and
> fails a frame the contract does not list, or lists and the code lacks, as a break. A contract
> written before 2.6 has no heading: the `surface` row keeps waiting for every section, the
> review runs as in 2.5, and the next close writes the heading as built, with a change file for
> each command deeper than 8.

The `status.py` flag list: `--paths <pkg> [--against-contract]`; `--fields` "seven lines", the
seventh `dependency readmes:`.

### `site/flow.md`

Line 30: `surf["surface section<br/>design from every sibling README"]` →
`surf["surface section<br/>designed from the contract after PLAN<br/>built last from every README"]`.
The PLAN node's label gains `<br/>+ Call paths`. Line 49: "it sends one reviewer (`Focus:

### `CHANGELOG.md`

close writing the heading as built with `paths-<command>` change files; `--fields` line 7
`dependency readmes:`. Each line names the file or flag a user sees.

`files: ['agents/*.md', 'skills/**/*.md', 'README.md', 'site/flow.md', 'site/workflows/*.md']`.

## Steps

1. README, flow, workflows, CHANGELOG. 2. The claim's `files:`.
3. `check-contracts`: all PASS (the widened claim now sweeps the docs; a leftover "from every
   sibling README" in a workflow fails it, which is the point). `build-site`.
4. Evals; `log-eval`.
5. Commit: `dev-team 2.6-spine (phase 7): README, flow, workflows and changelog for 2.6`.
6. In chat: propose `bump-version` at **minor** (2.6.0), with the CHANGELOG section as the
   release line's source, and wait. `bump-version` runs only on a yes; this note, `run-phase`
   and `plan-phases` never bump, tag or push.

## Deviations

- **The README has no package-contract description or `status.py` flag list.** The note put
  the **Call paths** paragraph "under the package-contract description" and the flags in a
  flag list; the README has neither (the contract appears only as a row of the **Contents**
  and `docs/` trees, the flags in the prose that uses them). Done: the paragraph, verbatim
  from the note, sits in **Running a package** right after its opening sentence, where a
  reader meets the order before the loop; `--paths <pkg> --against-contract` is in **Reviews**'
  paths-review paragraph, and the seven `--fields` lines in the existing **Gotchas** bullet,
  rewritten from six. The README keeps its upgrade notes in **Gotchas** ("A package shipped
  under 2.x may now …"), so the overview's five breaking changes are there: the `--fields`
  bullet carries item 5, and items 1–4 are four new bullets headed "Upgrading from 2.5:". Line
  232–235's **shipped** sentence gains "against the contract's **Call paths**"; the ready-set
  step 3 gains the `surface` exception and where **Dependency READMEs** come from.
- **`site/flow.md` has no PLAN node.** The loop chart's only PLAN-step node is the architect
  reached through a `spec-change: contract` (`ARCH`, "architect: plan-package pkg (edit)"); it
  gains `+ Call paths`, and so does the hand-offs chart's plan-package return. Also edited in
