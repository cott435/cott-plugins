## Deviations

- **`sync-plan` description spells `{pkg}`, not `<pkg>`.** The Specification quotes the new
  description as "`docs/packages/<pkg>/deviations/`". A skill description must hold no
  XML-style tag (plugin-anatomy `references/skills.md` **Descriptions**; `contracts.yml`'s
  "no skill or agent description contains an XML-style tag"), so it reads
  `docs/packages/{pkg}/deviations/`. The body keeps `<pkg>`.
- **Row 10.2's grep.** As written, `grep "docs/deviations/\$pkg\|…"` passes `$pkg` to grep,
  where macOS grep reads `$` as an anchor, so it misses every `docs/deviations/$pkg` line. The
  row was run as three `grep -nF` fixed-string searches instead (quoted in the eval log). One
  hit in `sync-plan`'s Constraints had its `older` on the line above, as the Specification's
  wording wraps; the line was rewrapped so the qualifier sits on the matched line. No word
  changed.
- **Row 10.3's baseline reads the 2.1.0 skills.** `run-evals` snapshots only the target's
  directory (`agents/`), but this phase changes `skills/sync-plan/SKILL.md`, which the eval's
  prompt reads through `${CLAUDE_PLUGIN_ROOT}`. The baseline snapshot was extended with
  `skills/` from `ba2ba38` (dev-team 2.1.0; `S init` resolved `previous` to `4ca9fea`, whose
  `dev-team/` tree is identical), and the `old_skill` executor read every skill from there.
