# 02 — status.py and the driver: a `stage:` source at PROBE

Phase 2. `status.py` learns the source kind `stage`: a section whose `source` cell holds
`stage:<token>` is at PROBE until its profile's round 0 is closed, and
`status.py --profile <pkg>/<section>` prints the profiler's spawn block, whole. `run-package`
spawns `dev-team:profiler` with that block at PROBE and counts it in the summary. This
completes the design's smallest end-to-end slice: on a contract row marked by hand,
`/dev-team:run-package <pkg> <section> --step PROBE` produces a round-0 profile, and the
unchanged designer then reads it as a source probe. It closes the gap that a cleaning section,
which names no external source, is never probed (`skills/run-package/SKILL.md:100-105`).

The after-build round (a second PROBE condition) is phase 5, the cap phase 6, the run-gate
checks phases 4 and 7. This phase adds none of them.

## Decisions

- **The newest round line decides.** `status.py` reads the last line matching
  `^Round (\d+) — \S+ — commit (\S+) — (.+)$` under the profile's `## <pkg>/<section>`
  heading. No line (or no doc, or no heading) → a `profile` run at round 0. `pending verify` →
  a `verify` run at that round. `revise: …` → a `profile` run at that round with the listed
  kinds as `Revise:`. Any other verdict → nothing is due at rule 3.
- **Nothing due, `--profile` still prints a block** (design, **Decisions taken**, planning):
  `Mode: profile`, `Round: 0`, `Revise: none`, `Commit: none`. Phase 5 changes this to the next
  round once the section has built code.
- **One block per `stage:` source of the row**, blank line between, in the cell's order. With
  the state at PROBE only the sources that need a run are printed; under `--step PROBE` with
  nothing due, every `stage:` source is.
- **`Source probes:` in the block is the dependencies' probes**: `docs/sources/<t>.md` for each
  `api:` or `dataset:` source of each section in the row's `depends on`, in table order,
  deduplicated; `none` when there are none. The row's own `stage:` profile is `Profile:`.
- **`Skills to invoke:` drops `dev-team:data-quality`.** That skill is for the designer and the
  implementer; the profiler gets the row's other `builds with` entries, or `none`.
- **`Data:` is the line as written**: the **Package conventions** line that starts
  `` `stage:<token>` — `` with its leading `- ` removed; `none` when the contract has no such
  line (the profiler then returns `blocked`).
- **The driver's paragraph has no heading and no bold.** It sits at the end of
  `### Researcher — PROBE`, inside the span `contracts.yml` reads for the researcher's fields,
  so a bolded word there would be read as a field.
- **The README's states table changes here**, not in phase 8: it is one row, and a README that
  describes PROBE wrongly for a release cut at this boundary is a defect.

## Specification

### `status.py` docstring

- Usage gains `[--profile <pkg>/<section>]`.
- Rule 3 becomes:

  > 3. **PROBE** — a source in the row's `source` column needs probing: an `api:` source whose
  >    `docs/sources/<token>.md` lacks a `## <pkg>/<section>` heading, or a `dataset:` source
  >    with no `docs/sources/<token>.md` at all; or a `stage:` source whose profile
  >    `docs/sources/<token>.md` has no round line under its `## <pkg>/<section>` heading
  >    (**Sections served**), or whose newest round line ends `pending verify` or `revise: …`.

- **Evidence** gains item 7:

  > 7. **stage** — `stage:<token> lacks ## <pkg>/<section>`; `stage:<token> r<n> pending
  >    verify`; `stage:<token> r<n> revise: K<a>, K<b>`: the profiler's next run, which
  >    `--profile` prints.

- A new paragraph placed immediately before the one that starts
  `` `--inputs <pkg>/<section>` prints ``:

  > `--profile <pkg>/<section>` prints the profiler's spawn block, the one place its values are
  > resolved: run-package sends it verbatim. One block per `stage:` source of the row that
  > needs a run (every `stage:` source when none does), a blank line between blocks; one
  > `<Field>: <value>` line per field, in this order, `none` for a field with nothing to hold:
  >
  > 1. **Mode** — `profile`, or `verify` when the newest round line ends `pending verify`.
  > 2. **Section** — `<pkg>/<section>`.
  > 3. **Stage** — the token.
  > 4. **Round** — the newest round line's round; `0` with none.
  > 5. **Revise** — the kinds after `revise:` on the newest round line.
  > 6. **Commit** — `none`.
  > 7. **Contract** — `docs/packages/<pkg>/contract.md`.
  > 8. **Repo contract** — `docs/architecture.md`.
  > 9. **Dependency READMEs** — as line 7 of `--fields`.
  > 10. **Source probes** — `docs/sources/<t>.md` per `api:` or `dataset:` source of each
  >     section in the row's `depends on`.
  > 11. **Skills to invoke** — the row's `builds with`, less `dev-team:data-quality`.
  > 12. **Data** — the contract's **Package conventions** line for the stage.
  > 13. **Profile** — `docs/sources/<token>.md`.
  > 14. **Store** — `.dev-team/data/<token>/`.
  > 15. **Run** — `run-package <pkg>`.
  >
  > It prints `profile: no stage source in <pkg>/<section>` for a row with none, and exits 0;
  > 2 on a target without `/` or a section the contract lacks, with the `--inputs` messages.

### `status.py` code

- `_round_lines(text, pkg, section) -> list[tuple[int, str, str]]`: `(round, commit, verdict)`
  per round line inside the `## <pkg>/<section>` block (from that heading to the next `## `
  heading or the end), in file order.
- `profile_due(pkg, section, token) -> dict | None`: `{"mode", "round", "revise", "evidence"}`
  by the first decision above, or `None` when nothing is due.
- `section_state`, rule 3: inside the existing loop, `if kind == "stage" and (due :=
  profile_due(pkg, section, token)): return "PROBE", due["evidence"]`. `api` and `dataset`
  keep their two branches unchanged. Rule 4's probe-newer loop already covers every kind, so a
  profile that only gained lines re-opens nothing.
- `profiler_inputs(pkg, section) -> list[str]`: the blocks, as the docstring lists them.
- `main`: `--profile` parsed with `_flag_value` beside `--inputs`, and added to the final
  `if has_rounds or …` test.

## Deviations

- **The `Data` item of the `--profile` docstring list.** The note gave it as "the contract's
  **Package conventions** line for the stage", with the heading in bold. What was done:
  "the contract's `## Package conventions` line for the stage". Why: the new `headings` claim
  reads every capitalized bold name in its reader span as a field, so a bold
  **Package conventions** inside the list is read as a sixteenth field the profiler's
  **Inputs** does not number, and the claim fails on a line that is not a field. The code
  prints the same `Data:` line either way.
- **Step 1, "see the new ones FAIL".** Ten of the fourteen new cases failed on the unchanged
  `status.py`; four passed: `stage-round0-closed`, `stage-round0-blocked`,
  `stage-design-kept-on-append` and `inputs-stage-source-probes`. 2.6.0's `status.py` reads a
  `stage:` source as neither `api` nor `dataset` and skips it at rule 3, so a section whose
  round 0 is closed already lands where these four expect (DESIGN, BLOCKED by its decision,
  TEST, and the profile listed under `Source probes:` like any source). They stay as
  regression cases: they pin that a closed round 0 leaves the row to the older rules. The
  state-cases README says so.
