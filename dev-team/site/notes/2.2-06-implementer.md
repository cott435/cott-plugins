# 06 — implementer

Phase 6. Rewrites the implementer for a batch where N of it run at once, on the hooks phases
2 to 4 shipped: `Applied:` lines go to the section's inbox, the marker is per section, the
two shared edits run through `locked.py`, a gate retry follows the 2.2 commit rule, no file is
written from the shell, tool results are read with Read and scratch lives under
`.dev-team/tmp/`, a FIX round or delta build restates step 1's reads (E3), the section's unit
suite is in the gate, the `(name)` unwrap moves to the `surface` build list, and the audit's
E10 (design **Skills used** never invoked), E11 (a bug fixed before its failing test) and E12
(unbacked claims in the return) get their sentences. The gap it closes: the implementer is
the one agent the design's parallelism depends on, and every mechanism it uses now exists.

## Decisions

- **The return form is unchanged in its lines** (the design: "the implementer's and
  reviewer's forms are unchanged"); E10 and E12 are wording in the steps and one rule under
  **Return message** about where a fact with no line goes. A second commit shows in the
  existing `Commit:` line as `Commit: <sha> (second commit; HEAD was <its summary>)`.
- **`blocked` and `spec-change` returns fill `Gate:` as `not run (marker)` and `Intent tests:`
  as the last run's count**, since neither the gate nor an end-of-run suite runs on a marker
  return (the audit's U20 F7). Reason: a closed form has to say what every line holds on every
  path.
- **A `spec-change:test` met mid-build stops the build there**, as the spec-change rule says;
  the return's `Files` line lists what was built. Reason: the audit's U20 F6 asked for the
  timing to be stated; the design's route ("build nothing further") decides it.
- **An `Applied:` line is written for every decision whose behavior this run built** — a
  `decided` one, or an `open`/`deferred` one built under its assumption (with its marker);
  a binding decision that touches no line gets no `Applied:` line, only the return's
  sentence. Reason: `Applied:` records where a decision landed in code.
- **"Seen red" goes in the existing review-findings bullet** of the return (`Review findings
  addressed: <finding> (test seen red: <test>)`), not a new line. Reason: the form is closed.
- **In an eval harness `.dev-team/tmp/` is the scratch copy's own `.dev-team/tmp/`**; the
  harness names the copy. Reason: the rule forbids the harness's scratchpad, not a copy.
- **The scaffold marker is `.dev-team/stop/scaffold`.** Reason: scaffold mode has no section
  and runs alone; the gate (phase 3) deletes it and exits 0.
