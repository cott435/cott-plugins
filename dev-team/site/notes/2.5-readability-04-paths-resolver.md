# 04 — `status.py --paths`

Phase 04. Nobody in the loop sees a whole path: every agent is scoped to one section, and
`data-build` in `quant` reaches its first vendor download 17 frames down, across six modules.
This phase adds the script that does see it. `status.py --paths <pkg>` follows each
`[project.scripts]` command through the package's own code with a static resolver and prints
the call tree, marking the frames an editor cannot jump through and the calls that leave the
package. The paths reviewer (phase 06) is handed this output so it judges paths rather than
rediscovering them, and `--shape`'s depth measure (phase 05) reuses the resolver. Step 4 of
the design's **Build order**.

## Decisions

- **What the resolver follows** is the design's list and nothing more: imports inside the
  package, `self.` and `cls.` methods, module attributes. A method call on a local variable
  or on an attribute of `self` is a leaf marked `[unresolved]`; the design's "Never claims: a
  resolved call it could not resolve" outranks a cleverer tree.
- **What an effect is** is the design's **Decisions taken** row *What an external effect is*:
  a resolved call into a module outside the package that is neither standard library nor a
  logging library, plus the stdlib I/O callables. A call into the rest of the standard
  library, into a logging library, or to another builtin is not printed at all.
- **A callable passed to a package function is a frame under that function.** `guarded(lambda:
  step())` prints `guarded`, then the lambda under it marked `[indirect]`, then `step`: the
  order the calls happen in, and the count the design's evidence used (`guarded → lambda →
  _ingest_steps`).
- **Depth is counted from the command function at 0**, and an effect's depth is the depth of
  the frame whose body makes the call. A command that calls a pipeline that calls an entry
  point that calls `requests.get` has `depth to first effect: 2`.
- **The footer has three lines.** The design gives two; the *What an external effect is*
  decision adds `deepest effect`.
- **`indirect frames` counts the command's whole tree.** Which of them lie on a main path is
  the reviewer's call (P2), made with each one marked in front of it.
- **A function met again is not expanded again.** It prints once in full and afterwards as
  `[seen]`, or `[recursive]` when it is on the current path, so the output stays bounded. The
  footer's numbers come from the call graph, not from the printed tree.
- **`build.py` gains a `commands` macro**, the fixture package below, because phases 05, 06
  and 07 build on the same five files.

## Specification

### The resolver

A module index over every non-test `.py` under the package's source root (the `surface`
row's path, else `<package root>/src/<pkg>`; a module's name is its path from the root's
parent, dotted, `__init__.py` giving the package's own name). Per module:

- its module-level functions, its classes with their methods and base-class names;
- its imports: local name → module, or module and attribute, with relative imports resolved
  against the module's package;
- its module-level dict literals whose values are all names (`_RUNNERS = {"market":
  load_market}`).

Inside one function, every `ast.Call` in source order, the bodies of nested functions and
lambdas left out (they are frames of their own):

| The call | Becomes |
|---|---|
| `f(…)`, `f` a module-level function of the same module, or imported from a module of the package | a frame |
| `C(…)`, `C` a class of the package | a frame `C.__init__` when the class defines one, else nothing |
| `f(…)`, `f` a function nested in the current function | a frame |
| `self.m(…)` or `cls.m(…)` in a class that defines `m`, or whose base class in the package does | a frame `Class.m` |
| `mod.f(…)` or `pkg.mod.f(…)`, the dotted root an imported module of the package | a frame |
| `C.m(…)`, `C` a class of the package | a frame `C.m` |
| `NAME[key](…)`, `NAME` a module-level dict literal of package functions | one frame per distinct value, in the dict's order, each marked `[indirect]` |
| a lambda, a nested function's name, or a package function's name passed as an argument to a call that resolved to a package function | a frame under **that callee**, after the callee's own calls, marked `[indirect]`; a lambda's frame is named `lambda` |
| the same, passed to a call that did not resolve to a package function (`sorted(key=…)`, `executor.submit(…)`) | a frame under the **current** function, marked `[indirect]` |
| a call whose dotted root is imported from outside the package, or a builtin | an effect leaf when the effect rule holds, else nothing |
| a call on a module-level name assigned from a logging library's call (`log = logging.getLogger(__name__)`, then `log.info(…)`) | nothing, as a call into the logging library itself |
| anything else: a parameter called, a local variable's method, `self.x.m(…)`, a subscript of something unknown | a leaf `<source text> (<file>:<line>) [unresolved]` |

An `[indirect]` frame for a lambda or nested function whose own subtree holds no frame and no
leaf is not printed: a `key=lambda row: row.ts` adds nothing to a path.

A frame's children print in the source order of their calls, frames and leaves interleaved;
the callables passed to a callee print under it after the callee's own calls. A callee
printed `[seen]` does not print its own calls again, but a callable passed to it at this call
site still prints under it, marked `[indirect]`: two steps handed to one wrapper are two
frames.

**The effect rule.** A resolved outside call is an effect when its root module is not in
`sys.stdlib_module_names`, is not `loguru`, `logging` or `structlog`, and is not the package
itself; or its root module is one of `subprocess`, `socket`, `urllib`, `http`, `sqlite3`,
`shutil`; or it is the builtin `open` or `print`. The leaf reads `[effect: <callee as
written>] (<file>:<line>)`.

### `--paths <pkg>` output

Commands come from the `[project.scripts]` table of `<package root>/pyproject.toml`
(`tomllib`), in the table's order. Per command:

```
command: data-load = data.cli:load
load (packages/data/src/data/cli.py:6)
  run_load (packages/data/src/data/pipelines/load.py:6)
    read_trades (packages/data/src/data/ingest/reader.py:7)
      [effect: shutil.copy] (packages/data/src/data/ingest/reader.py:9)
      [effect: open] (packages/data/src/data/ingest/reader.py:10)
depth to first effect: 2
deepest effect: 2
indirect frames: 0
```

- One line per frame, two spaces of indent per level, `name (<file>:<line>)`, the line the
  `def` (or the lambda) is on; a method is `Class.method`. Marks follow the parenthesis:
  `[indirect]`, `[seen]`, `[recursive]`.
- `depth to first effect: <n>` is the smallest depth of a frame that makes an effect call, or
  `none` when the command's graph has no effect leaf. `deepest effect: <m>` is the largest,
  back edges ignored, or `none`. `indirect frames: <k>` is the number of `[indirect]` frames
  in the command's tree, each counted once.
- A command whose target module is not in the package prints `command: <name> = <target>` and
  `target outside the package`, with no footer.
- Blocks are separated by one blank line. With no `[project.scripts]` table, or an empty one,
  or no package `pyproject.toml`: the one line `paths: no commands`.
- Exit 0. Exit 2 with `--paths needs a package: status.py --paths <pkg>` when none is given,
  and with `<pkg>: missing docs/packages/<pkg>/contract.md` when the package has no contract.

The docstring's usage line gains `[--paths <pkg>]`, and a **Paths.** paragraph, placed after
**Shape.**, states the resolver's table in prose, the effect rule and the output above. It
uses dashes, not a numbered bold list.

### `skills/status/SKILL.md`

`argument-hint` gains `[--paths <pkg>]`. A new paragraph after the `--shape` one:

```
`--paths <pkg>` prints one call tree per `[project.scripts]` command of the package, followed
statically through the package's own code: a frame per line, `[indirect]` on a frame reached
through a lambda, a closure or a mapping, `[effect: <callee>]` on a call that leaves the
package for a third-party module or for I/O, `[unresolved]` on a call the script could not
follow, then `depth to first effect`, `deepest effect` and `indirect frames`. The paths
reviewer reads it. With no commands it prints `paths: no commands`.
```

### `build.py`: the `commands` macro

`{"do": "commands"}` makes one commit, summary `data/surface: commands`, of five files, and
takes `"files": {<path>: <text>}` to replace or add any of them in the same commit:

`packages/data/pyproject.toml`:

```toml
[project]
name = "data"
version = "0.0.0"

[project.scripts]
data-load = "data.cli:load"
```

`packages/data/src/data/cli.py`:

```python
"""Commands."""

from data.pipelines.load import run_load


def load(path: str) -> None:
    """Load the trades at path."""
    run_load(path)
```

`packages/data/src/data/pipelines/__init__.py`: empty.

`packages/data/src/data/pipelines/load.py`:

```python
"""The load pipeline."""

from data.ingest.reader import read_trades


def run_load(path: str) -> int:
    """Read the trades at path and return their count."""
    # Read the file into rows.
    rows = read_trades(path)
    return len(rows)
```

`packages/data/src/data/ingest/reader.py`:

```python
"""Read trades."""

import csv
import shutil


def read_trades(path: str) -> list[dict[str, str]]:
    """Copy path to a scratch file and parse the copy."""
    shutil.copy(path, path + ".bak")
    with open(path + ".bak") as handle:
        return list(csv.DictReader(handle))
```

The macro goes before any `done` step in a case, so each section's review covers these files.

### `state-cases`: nine cases

Each is `base`, then `commands` with the replacement named, and runs `--paths data`.

| Case | Replaces | Expected |
|---|---|---|
| `calltree-direct` | nothing | the whole block above, line for line; exit 0 |
| `calltree-lambda` | `pipelines/load.py`: a module function `guarded(step)` whose body is `return step()`, and `run_load` calling `rows = guarded(lambda: read_trades(path))` | a `guarded (…load.py:6)` frame; under it `step() (…load.py:8) [unresolved]` and `lambda (…load.py:13) [indirect]`; under the lambda `read_trades`; `depth to first effect: 4`; `indirect frames: 1` |
| `calltree-mapping` | `pipelines/load.py`: `_RUNNERS = {"trades": read_trades}` and `rows = _RUNNERS["trades"](path)` | `read_trades (…reader.py:7) [indirect]`; `indirect frames: 1`; `depth to first effect: 2` |
| `calltree-unresolved` | `pipelines/load.py`: `reader = make_reader()` from an added package function returning an object, then `rows = reader.read(path)` | a line ending `[unresolved]` holding `reader.read(path)`; `depth to first effect: none` |
| `calltree-logging-not-effect` | `cli.py`: `from loguru import logger`, `import re`, and `logger.info("x")`, `re.compile("x")` before `run_load(path)` | absent `[effect: logger.info]` and `[effect: re.compile]`; `depth to first effect: 2` |
| `calltree-third-party` | `ingest/reader.py`: `import requests` and `requests.get(path)` in place of the copy and the open | `[effect: requests.get]`; `depth to first effect: 2` |
| `calltree-self-method` | `ingest/reader.py`: a class `Reader` with `read` calling `self._copy(path)`, `_copy` calling `shutil.copy`, and `read_trades` calling `Reader().read(path)` written as `Reader.read(Reader(), path)` | frames `Reader.read` and `Reader._copy`; `depth to first effect: 4` |
| `calltree-recursive` | `pipelines/load.py`: `run_load` calls itself under an `if` before `read_trades` | a `run_load (…) [recursive]` line; `depth to first effect: 2` |
| `calltree-no-commands` | `packages/data/pyproject.toml` without the `[project.scripts]` table | the one line `paths: no commands`; exit 0 |
