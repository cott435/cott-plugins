# 02 — Architect at PLAN

Phase 2. The architect writes **Call paths** when it writes a package contract, adds the
heading to a planned contract that lacks it, and turns a path that cannot fit its budget into a
question through the interview rule. After this phase every contract `/dev-team:plan-package`
writes fixes each command's frames before a designer runs; the designers that build to them
arrive in phase 4. It closes the first half of the design's smallest slice (template →
architect).

## Decisions

- **A planned contract without the heading is an EDIT item; a built one is the close's.** The
  change list already classifies by whether a section is built. A missing **Call paths** on a
  contract whose sections have no code is an EDIT written from **Pipelines** and **Section
  interfaces**; once any section has code the frames are facts of the code, so the item is left
  to the close (phase 6), which writes them as built. The architect at PLAN names the item in its
  return as `| Call paths | left to the close (built) |` so the omission is visible.
- **The budget question uses the interview rule, not a new mechanism.** A command that needs a
  depth past 8 is a `D<n>` stub with the architect's recommendation (raise this command's
  budget to `<k>`, or move a responsibility so the path fits) and a stop. The rule's cost test
  already says when to ask: a wrong budget invalidates every design on the path.
- **Frames are chosen from what the contract already names.** The architect writes no new
  **Section interfaces** entry only to have a frame; when a path needs a second function of a
  section, that function is added to **Section interfaces** marked `(path only)` (template item
  3), in the same WRITE or EDIT.

New section, inserted after **Packages and sections** and before **Decisions**:

> ## Call paths
>
> At package scope you fix every command's path before a designer runs: the template's item 5,
> **Call paths**, read from `references/package-contract.md` with the rest. One entry per
> command in **Public surface (intent)**; per entry, one path per kind of external effect the
> command reaches, its frames numbered from the command function. Each frame is a name the
> contract defines — `cli.<function>`, `pipelines.<function>` for a **Pipelines** entry's
> function, `<section>.<function>` for a **Section interfaces** entry — and nothing else: a
> frame with no owner is a frame nobody will build. When a path has to pass through a second
> function of a section after its entry point, add that function to **Section interfaces**
> marked `(path only)`; never leave a frame unnamed.
>
> The budget is 8, the hard **Main-path depth** of `project-structure` §2, on `--paths`'
> `depth to first effect` (the command at 0, so a path of `n` frames has depth `n − 1`). A
> command whose path cannot fit — the brief, a `decided` `D<n>` or a provider's protocol
> demands a frame the budget has no room for — is a question under the interview rule: stub a
> `D<n>` with `Scope: <pkg>`, your recommendation (`budget <k>` for that command, or the
> responsibility to move so the path fits) and the assumption you would write, and stop. A
> budget above 8 is written only with a `decided` `D<n>` cited on the command's line.
>
> A contract that exists and has no **Call paths** heading is an item of the change list,
> `Call paths` (**Edits**): EDIT when no section of the package is built, written from
> **Pipelines** and **Section interfaces** as above; when any section is built, the frames are
> the code's, and the item is the close's (**sync-plan**, step 8), so you write nothing for it
> and the return row reads `| Call paths | left to the close (built) |`.
