# 12 — run-fixes

Phase 12. The fixes phase 11's end-to-end build pointed at
(`evals/2026-09-30-2.2-docs-and-release.md`, its misses and findings), then the same build
again as the release's evidence. Added after phase 11 on the user's call; the design is not
edited. Where a fix revises a design decision, the note says which one, and the fix is written
down as a Deviation-in-advance here rather than a silent change.

The gap it closes: under 2.2, three mechanisms 2.2 itself added can stop a headless run that
2.1 finished, and two guards 2.2 added have holes a real run walked through.

1. **The gate fails an implementer on the tester's lines.** 2.1 marked a failure in an
   intent-test file the run did not touch `ELSEWHERE`; 2.2's `ELSEWHERE` is only "outside the
   section's paths", and `tests/intent/<section>/` is inside them. In phase 11 the
   `analysis/surface` gate FAILed three attempts on twelve **Guarded** `xfail` lines the tester
   wrote (`reason=` citing a constant `D5_OPEN`, which `\bD\d+\b` does not match), the
   implementer could edit none of them, and it stopped at attempt 3 mid-investigation, its last
   turn not a `Result:` hand-back, so the driver stopped (eval 4 #7).
2. **The root config the first consumer needs is nobody's.** The `workspace-scaffold` consumers
   contract lacks `allow_indirect_imports = true` (a lazy top-level `__init__.py` makes
   `consumer -> pkg -> pkg.section` a chain in every legal import) and the root has no
   `[tool.mypy] mypy_path` (a repo-root directory named like a package shadows it). Under 2.2's
   section-scoped guard only the scaffold and `surface` implementers may edit the root
   `pyproject.toml`, so a `features` implementer can only stop (the baseline's phase-11 stop).
3. **The one-way sync keeps an `Applied:` line its inbox later changed** (eval 4 #12).
4. **The driver reads files to resolve spawn fields** that `status.py` could print (eval 4 #9:
   `ls` of code directories for `Mode:`, `grep "Status: open"` over change files).
5. **`guard_bash.py`** lets a `python3 - <<'EOF'` script write (the baseline's documenter wrote
   `docs/index.md` three times) and lets anything through `locked.py` (a `sed -i` of a package
   `pyproject.toml` ran).
6. **`plan-package` fails its own run gate on a new package** (`--run-gate <pkg>` requires the
   contract it is about to write; in 2.1.0 too).
7. **Eval 4 #6's bar is eval L's**, measured on an older model and CLI: `reviewer.md` grew
   about 2.6k characters since 2.1.0, while the measured reviewer fixed cost sits about 2.6k

8. **F4** was not observable on a strict-chain fixture; eval 5's two independent sections are.

## Decisions

- **`ELSEWHERE` also covers `tests/intent/**`, restoring 2.1's rule beside 2.2's.** A located
  failure (a check's `path:line` or `path::test`, or a Guarded hit) whose every location is
  under the section's `tests/intent/` is `ELSEWHERE`: the implementer may never edit there.
  An intent *test* failing is still the intent suite's FAIL (the code is what it tests); what
  moves is a lint, type or Guarded failure located in an intent-test file. Revises the design's
  **ELSEWHERE** row ("any located failure outside the section's paths") by one clause. Reason:
  the tester owns those lines; phase 11's stall.
- **`DECISION` matches `D<n>` followed by a non-digit**, `\bD\d+(?!\d)`, so `D5_OPEN` and `D5:`
  cite `D5`; and `tester.md` says a `skip`/`xfail` reason cites the decision as literal text
  (`reason="D5: …"`), never through a constant. Reason: both halves; the regex alone lets any
  identifier starting `D<digit>` through, which is what the tester did.
- **Every turn an implementer ends is a hand-back.** `implementer.md`: a turn that ends — the
  first stop, a gate retry, or the investigation of a failure it cannot fix — ends with the
  return form, first line `Result:`; a gate failure in a file it may not edit is `Result:
  blocked` with the gate lines, not prose. **And the driver re-derives before it asks**: a
  return whose first line is not `Result:` → re-run `status.py <pkg>`; if the row moved past
  the step's state (IMPLEMENT/FIX → REVIEW, DESIGN → TEST, TEST → IMPLEMENT, REVIEW → DONE/FIX),
  record it in the summary as `<role> <section>: no Result: line; state advanced` and go on;
  else **Asking**, as today. Reason: the state is on disk; a malformed last turn after a good
  commit is not a question for the user.
- **A section's `Applied:` lines mirror its inbox.** For each `## D<n>` entry of
  `docs/packages/<pkg>/decisions/<section>.md`, `sync_decisions.py` makes the central entry's
  `Applied: <pkg>/<section>, …` lines equal the inbox entry's (inbox order, at the position of
  the first such line, else after the last `Applied:`); other sections' lines and every other
  field are untouched, and an inbox with no `## D<n>` entry changes nothing for `D<n>`. The run
  gate FAILs a central `Applied: <pkg>/<section>` line absent from that section's inbox when
  the inbox holds the entry. Revises the design's "one direction of flow" only for the lines the
  section itself owns; `Decision:` and `Status:` still never flow. Reason: eval 4 #12.
- **`status.py --fields <pkg>/<section>`** prints the spawn fields the driver resolves today by
  reading files: `mode: new | document | delta`, `change file: <path> | none`,
  `design mode: <word after Mode:> | none`, `diff base: <sha> | none` (round `r-1`'s `-s`, else
  `-a`, `Commit:`). The skill's **What you never do** then permits the driver `status.py`, the
  Read tool on the listed files, and the two git commands — no `ls`, `grep`, `find`, `cat`,
  `head`. Reason: eval 4 #9 on both drivers; one derivation, not a driver's guess.
- **The scaffold owns all root config.** `workspace-scaffold` §3: contract 2 carries
  `allow_indirect_imports = true`, and the **consumer's** scaffold writes (or uncomments) the
  provider's contract 2 once its own source module exists — the provider's `surface`
  implementer writes it only when a consumer already exists; §1: `[tool.mypy] mypy_path` holds
  every built package's `src/`, grown by the scaffold like `root_packages`. §3's stale "each
  section's implementer unwraps its own name" becomes the `surface` implementer's unwrap
  (phase 6 moved it). Reason: finding 2; the design's `(name)` unwrap decision already puts
  root edits with the scaffold and `surface`.
- **`guard_bash.py`**: (a) a simple command whose program is python with `-` as the script, or
  no script and a here-document, has the here-document body checked with `PY_WRITE`; (b) the
  `locked.py` exemption applies only when the command after `--` is `uv add`, `uv remove`,
  `uv lock` or `uv sync`, or `sh -c` whose script is a `printf … >> .gitignore` — any other
  wrapped command is checked as if unwrapped. Reason: finding 5.
- **`plan-package` step 1 is `status.py --run-gate`** (branch and tree only); `sync-plan`,
  `pair` and `run-package` keep `--run-gate <pkg>`. Reason: finding 6.
- **Eval 4 #6 is re-baselined, not relaxed.** Row 12.5 measures the fixed cost of the
  **2.1.0** reviewer and tester and the working tree's, same model, same CLI, same fixture
  state; #6 then reads: the 2.2 mean is at most the 2.1.0 mean plus 1,000 tokens for each
  role (the E1 rule and closed return forms cost about 650). Reason: the bar must measure the
  prompt, not the platform.
- **Headless sessions name the model in full**, `--model claude-sonnet-5-5`: `site/notes/CLAUDE.md`
  says so, and phase 9's log gets one correction line (its `--model sonnet` sessions were
  `claude-sonnet-5`, Sonnet 5).
- **§Project convention: paths are listed literally.** `P="a b" && git add $P` does not split
  under zsh (phase 11: exit 128, then a retry, in about a dozen runs); rule 2 says to write
  each path out.
- **MINOR, `2.2.0`, proposed at the end of this phase** instead of phase 11's. Nothing here
  renames what a user types; `--fields` is a new flag.

## Specification

### The gate

Step 5's ELSEWHERE paragraph gains: "A located failure whose every location lies under
`<pkg>/tests/intent/` is `ELSEWHERE` too, whether or not the run touched it: the tester owns
those lines. The intent suite's own failures stay `FAIL` (or tolerated by a deviation), since
what fails there is the code." `check_guarded`'s hits under `tests/intent/` become
`ELSEWHERE guarded <item> at <path>:<n> (the tester's file)`. `DECISION =
re.compile(r"\bD\d+(?!\d)")`.

### The sync hook

`merge()`: for an inbox entry `## D<n>` that exists centrally (question equal when given),
compute `own = [l for l in central Applied lines if l starts "Applied: <pkg>/<section>,"]` and
`want = the inbox entry's Applied lines`; if they differ, replace `own` by `want` in place and
report `D7: Applied: lines for <pkg>/<section> set to the inbox's (<k>)`. The `D?` path is
unchanged. The run gate: for each inbox entry `## D<n>` with a central `D<n>`, a central
`Applied: <pkg>/<section>,` line not in the inbox entry → FAIL `stale Applied: line — D<n>:
<line>; run sync_decisions.py --all`.

### `status.py --fields <pkg>/<section>`

Four lines, in this order, `key: value`, exit 0; exit 2 on a section the contract lacks. `mode`
is the run-package **Mode** row's rule (an open change file naming the section, or the row's
evidence `open <heading>` for a `spec-change:design` → `delta`; code at the path and no design →
`document`; else `new`); `change file` the open change file under
`docs/packages/<pkg>/changes/` (or a pre-2.2 `docs/changes/`) naming the section; `design mode`
the word after `Mode:` on the design's first line; `diff base` the **Diff** row's rule.

### run-package

**What you never do**, the read bullet becomes: "Read only with the Read tool, and only: the
Sections table of `docs/packages/<pkg>/contract.md`, the `<pkg>` row of `docs/architecture.md`
and its **Shared conventions**, and the `docs/legacy/inventory.md` row for a source token.
Every other spawn field comes from `status.py --fields <pkg>/<section>`. Never `ls`, `grep`,
`find`, `cat` or `head` a repo file." The designer table's **Mode** and **Change file**, the
tester's **Design mode** and the reviewer's **Diff** cite `--fields`. Step 5's last bullet:
"a first line that is not `Result:` → re-run `status.py <pkg>`: if the row has moved past the
step's state, note `<role> <section>: no Result: line; state advanced` for the Summary and go
on; else **Asking**, with the return as the question."

### workspace-scaffold


### Eval 4's set

spawn's first assistant-turn `usage` in the subagent transcripts (`input_tokens +
cache_creation_input_tokens + cache_read_input_tokens`), with min, max and mean per role; the
tester's mean is at most `<12.5's 2.1.0 tester mean> + 1,000` and the reviewer's at most
`<12.5's 2.1.0 reviewer mean> + 1,000`" — the two numbers written in from 12.5's log, with a

## Deviations

- **run-package's read rule keeps one listing.** The note's **What you never do** bullet
  names only the Read tool on three files and `status.py --fields`, but a round-2 reviewer's
  **Previous round** field is round `r-1`'s report paths, which neither `--fields` nor any of
  those files prints. The bullet also lets the driver find those file names with the Glob tool
  under `docs/packages/<pkg>/reviews/<section>/` (or the older `docs/reviews/`); `ls`, `grep`,
  `find`, `cat` and `head` stay forbidden. Eval 4 #9 is worded to the same rule.
- **Step 6's `grep` word.** Row 12.4's bar is that every `ls|grep|find` hit in run-package is
  inside **What you never do**; step 6 said its `status.py` output is "never piped through
  `grep`, `head` or `tail`". Reworded to "a filter such as `head` or `tail`"; the prohibition
  is unchanged.
- **`guard_bash.py` checks every `sh -c` script.** "Any other wrapped command is checked as if
  unwrapped" is empty for `locked.py x -- sh -c "sed -i …"` unless a shell's `-c` script is
  checked at all, and 2.2's guard never looked inside one. `sh`, `bash` and `zsh -c` scripts
  are now split and checked like a command line of their own, wrapped or not
  (`bash-locked-sh-refused`).
- **`--fields` details the note left open.** `mode: document` needs a `.py` file under the
  section's path other than, for `surface`, the package's own `__init__.py` (the scaffold
  writes it, so every `surface` would otherwise read `document`); `design mode` reads the
  first `Mode:` line within the design's first five lines, since a title line may precede it
  (the state-case designs start with one); `diff base` is printed as a short sha.
- **The sync mirror and other sections' lines.** The note's `want` is every `Applied:` line of
  the inbox entry. A line in the inbox naming another section (`sync-applied-dedupe` has one)
  is not the section's to mirror: it is copied once when the central entry lacks it and never
  removed, as before; only the inbox's own section's lines are mirrored. A pure addition still
  reports `D<n>: <k> Applied: line(s) added`; `set to the inbox's (<k>)` is reported when a
  line of the section's was edited or removed.
- **ELSEWHERE for a mix.** A failure located both in the section's intent tests and outside
  the section is `ELSEWHERE` too (no location is one the implementer may edit); the gate's
  `ELSEWHERE` text says "outside <section> or in intent tests". The Guarded `ELSEWHERE` applies
