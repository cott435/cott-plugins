# dev-team 2.5-readability — overview

Branch: `dev-team-2.5-readability`. Release at the end: `2.5.0`, a minor bump, proposed to
`bump-version` in the last phase. Nothing here bumps or tags anything. Date: 2026-10-01.

This is the index of the phase notes. Each numbered note after this one is one phase, done
in the order listed under **Phases**, one chat and one commit each, by
`/plugin-dev:run-phase 2.5-readability`. Nothing in a later phase is required by an earlier
one, so the branch is mergeable at any phase boundary.

The why, the workflows and their charts, the decisions and the non-goals are in
`2.5-readability-design.md`, approved before this was written. This note does not repeat them;
it says what the design turns into, file by file and phase by phase.

## Phase 0 evals

Two facts the design's **Platform facts** table marks *assumed (planning)*. The first
`run-phase` chat runs them before phase 1, logs them with `log-eval`, and sets the ledger's
phase-0 row `done`. Both are about ruff, not about a plugin component, so neither has a place
in `plugin-anatomy`: each is written back to the design's **Platform facts** row (its status
becomes `verified`, with the log's name) and used by phase 1 as `V`.

| ID | Kind | Target | Baseline | Set evals | Pass bar |
|---|---|---|---|---|---|
| PF-1 | platform-fact | ruff | — | — | V is logged: the lowest of `0.13.0`, `0.14.0`, `0.15.0`, `0.16.0` at which `PLR0917` flags `wide` and not `kw` with no `--preview`; `0.16.9` when none of the four does. Written back: the design's Platform facts row |
| PF-2 | platform-fact | ruff | — | — | `uvx ruff@0.12.0` refuses to run under `required-version = ">=V"`, both forms, with a non-zero exit and output naming the requirement. Written back: the design's Platform facts row |

Method, in a scratch directory outside the repo:

- `m.py`:

  ```python
  """M."""


  def wide(a, b, c, d, e, f):
      """W."""
      return a, b, c, d, e, f


  def kw(a, b, c, *, d, e, f, g):
      """K."""
      return a, b, c, d, e, f, g
  ```

- `pyproject.toml`:

  ```toml
  [tool.ruff.lint]
  select = ["PLR0917"]
  [tool.ruff.lint.pylint]
  max-positional-args = 5
  ```

- **PF-1.** Assumed answer: V is at or below `0.16.9` and above `0.12.0`. Seen on 2026-10-01:
  `ruff 0.16.9` prints one `PLR0917` at `m.py:4` and exits 1; `ruff 0.12.0` prints `Selection
  PLR0917 has no effect because preview is not enabled` and exits 0. Run `uvx ruff@<v> check
  m.py --no-cache` for the four versions in order; V is the first that flags `wide` only. No
  patch-level search: the floor has to be safe, not tight.
- **PF-2.** Assumed answer: it refuses. Add `[tool.ruff]` with `required-version = ">=V"` to
  that `pyproject.toml` and run `uvx ruff@0.12.0 check m.py --no-cache`. Then the format hook's
  form: copy the file to `other/pyproject.toml`, delete the first, and run `uvx ruff@0.12.0
  check --config other/pyproject.toml m.py --no-cache`. If either run exits 0, the decision
  "a ruff too old for `PLR0917` refuses to run" cannot be met by configuration: phase 1 stops
  before its first edit and asks the user.

## Breaking changes to list in `CHANGELOG.md`

1. `shipped:` needs the paths review. A package shipped before 2.5 that has commands reads
   `shipped: no (paths needed)` after the upgrade. Run `/dev-team:run-package <pkg>` once: the
   driver spawns the paths review, and its findings re-open the sections they name as FIX
   rounds. A package with no `[project.scripts]` commands reads `paths: approved (no
   commands)` and stays shipped.
2. The lint block caps positional parameters, not all of them. An existing repo keeps its
   root `pyproject.toml`: replace `PLR0913` with `PLR0917` and `max-args` with
   `max-positional-args` by hand, add the `required-version` line, and upgrade ruff to V or
   later. An older ruff now refuses to run instead of skipping the rule.
3. The stop gate fails a run that adds a trivial single-use helper or an options bag
   (`FAIL shape: …`). Code already reviewed, and adopted code, is measured and never failed.
4. `paths` is a reserved section name.
5. `status.py --fields` prints six lines, and a review report directory `reviews/paths/`
   holds reports with letter `p`.
