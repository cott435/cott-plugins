# 05 — `--paths --against-contract` and the paths review against the contract

Phase 5. `status.py --paths <pkg> --against-contract` prints, after each command's tree, the
contract's frames beside the code's, each `match`, `extra` or `missing`, with the command's
budget; the paths reviewer reads **Call paths**, runs that flag, fills a `contract` column in
its **Paths** table, judges P1 against the command's own budget, and writes a break for every
`extra` or `missing` frame under the section that holds it. It completes the design's smallest
slice (template → architect → the review against the contract) and closes the gap the 2.5 paths
review left: it could say a path was too deep, not that it differed from what was planned.

## Decisions

- **Matching walks the printed tree.** The command block's frames are matched top-down: frame 1
  must be the root; each next contract frame is the first frame found depth-first below the last
  matched one whose owner and name agree (owner by `section_for_path` on the frame's file,
  `cli`/`pipelines` for the surface's two places; name by `fn.name`). Frames on the tree path
  between two matched frames are `extra`; a contract frame with no such descendant is
  `missing`, and matching continues from the last matched frame. `[seen]` and `[recursive]`
  frames are not expanded, exactly as printed, so the comparison and the tree agree line for
  line.
- **The effect is `reached`, not matched by name.** After the last matched frame: `reached`
  when an `[effect: …]` leaf is its direct child; `reached through <k> extra frame(s)` when an
  effect leaf lies below it, the frames on the first path down to one listed `extra`; else
  `not reached`.
- **`missing` is a break, like `extra`.** The design names `extra` as the break; a frame the
  contract lists and the code does not pass through contradicts the contract just as much, and
  Severity item 1 already says so. Both are written under the section that owns the frame
  (`cli`/`pipelines` → `surface`).
- **With no entry for a command, or no heading, the review runs as 2.5's.** The comparison
  block says so in one line; the Paths table's `contract` cell is `—`; P1 uses the hard
  **Main-path depth**.
- **Depth is reported against the budget in the block**, so the reviewer copies `depth <d> of
  budget <b>` or `depth <d> past budget <b>` and never computes it.

## Specification

### `status.py` docstring

Usage line: `[--paths <pkg> [--against-contract]]`. New paragraph after **Paths.**:

> **Call paths.** `--paths <pkg> --against-contract` prints, after each command's block and its
> footer, the contract's **Call paths** entry for the command beside the tree. The first line is
> `contract: <command> (budget <n>)`, or `contract: no entry for <command>` when the heading
> has no entry for it, or `contract: no Call paths heading`; the last two end the block. Then,
> per path of the entry, its kind on a line of its own (`  <kind>:`), then one line per
> contract frame — `    <k> <owner>.<name>  match  <name> (<file>:<line>)` or `    <k>
> <owner>.<name>  missing` — with every tree frame between two matched frames printed as `    -
> <padding>  extra  <name> (<file>:<line>)` in tree order; then the effect line, `    effect
> <callee>  reached`, `reached through <k> extra frame(s)` (those frames printed `extra` above
> it) or `not reached`; then, once per command after its last path, `  summary: <k> match, <e>
> extra, <m> missing; depth <d> of budget <n>` (`past budget` when `d > n`; `depth none` when
> the block has no effect), the three counts counting the lines printed above it, so a frame on
> two paths counts once per path. The frame column (`<k> <owner>.<name>`, or `-` on an `extra`
> line) is padded to the entry's longest frame, then two spaces, then the word. A frame matches
> when its file's section (`section_for_path`; `cli` for `cli.py` or `cli/` and `pipelines`
> for `pipelines/` under the surface's path) is the frame's owner and its printed name is the
> frame's name after the owner. Matching walks the printed tree depth-first from the root,
> which must match frame 1, and never expands a `[seen]` or `[recursive]` frame. With no
> command the line after `paths: no commands` is `contract: <as above>`. Exit codes as for
> `--paths`.

Parsing, in `call_paths`: the body of `_item(text, "Call paths")`; a command line matches
`` ^- `(?P<cmd>[^`]+)` \(budget (?P<n>\d+)(?:, D\d+)?\)`` ; a path line is an indented `- ` line
whose frames are ``re.findall(r"(\d+) `([^`]+)`", line)`` and whose kind is the text before the
first `:`; the effect is the last backticked token on the line when it is not preceded by a
digit and a space. `- none (no commands)` yields `{}`.

`paths_report(pkg, against)` appends `against_contract(...)` lines after each block's footer
when `against` is true; `main` reads `has_against = "--against-contract" in argv` (removed from
`argv` before the unknown-flag check) and refuses it without `--paths`
(`--against-contract needs --paths <pkg>`, exit 2).

## Deviations

1. **The frame column is padded, so two case strings became regexes.** The docstring
   paragraph says the frame column is "padded to the entry's longest frame, then two spaces",
   but the cases table expects `1 cli.load  match  load (…)` and `4 ingest.parse_rows  missing`
   with two spaces, which only an unpadded column prints (the longest frame there is `2
   pipelines.run_load`, 20 characters). The script pads, as the docstring says, and those two
   expectations are regexes with `\s+` (`^    1 cli\.load\s+match  load \(…cli\.py:6\)$`,
   `^    4 ingest\.parse_rows\s+missing$`), as the `extra` case's already was. The reviewer eval
   prompts written in phase 0 (evals 12 and 13) show the block unpadded; the reviewer copies the
   summary line, which padding does not touch, and the prompts were left as written.
2. **What the note left open, decided in the script and its docstring.** With no command and
   `--against-contract`, the line after `paths: no commands` is `contract: no Call paths
   heading`, `contract: none (no commands)` when the heading says so, or `contract: entries for
   <command>, …, no command built`. The no-effect summary reads `depth none of budget <n>`. A
   command whose target is outside the package or not found prints its entry with every frame
   `missing`. When frame 1 does not match the root, it is `missing` and later frames are looked
   for from the root down, the root counted `extra` above the first match.
3. **`--paths` builds its tree once as nodes.** `_CallGraph.tree` now prints from a node tree
   (`_CallGraph.node`), which `against_contract` walks, so the comparison and the printed tree
   cannot disagree. The printed output is unchanged (every `calltree-*` and `paths-*` case passes).
4. **One fix to `reviewer.md` beyond the Specification.** Iteration 1 missed row 5.3's and
   5.4's bar on one expectation in each eval: the supplied block's `[unresolved]` leaf was not
   reported (the 2.5.0 baseline missed it on eval 10 too). The one fix allowed by `run-phase`,
   inside this note's Files: **Focus: paths** now says every `[unresolved]` leaf of a block is a
   WARNING or a SUGGESTION, one bullet each with its `file:line` and the call, never left out.
   Iteration 2 met both bars.
5. **Two expectations corrected in `evals/sets/reviewer.json`.** Eval 10 expectation 5 named
   the five 2.5 columns; it now accepts the six with `contract` `—` (and still the five from a
   reviewer before 2.6). Eval 12's break-line expectation now allows the ` (also P4)` that
   **Focus: paths** puts after the frame when it is also a P-item (its grader's critique).
