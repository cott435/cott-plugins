# 07 — designer-tester

Phase 7. The two agents that run before the implementer. The designer stops for a decision by
writing a `## D?` stub to its section's inbox and reading the number back, classifies its §10
items by the E1 test (additive → `deviation`, else `spec-change:contract`), restates step 1's
reads in `delta` mode (E3), sets `resolved` on the `spec-change:design` entries its rewrite
answers (W2), and writes nothing by shell. The tester gets the W1 route (`spec-change:design`
on a design contradiction, any run), `Design mode:` in place of `Adopted code:` with the delta
rules (W4), the full-item tag match and the `(deviation <date>-<k>)` tag (W3, F13) kept under
88 characters (F14), Python only through the test command (E6), a closed return form with
`Suite:` and `Ledger:` (E2), `resolved` on the `spec-change:test` entries it regenerates (W2),
and no tree past an Interfaces row with no signature (E9). The gap it closes: with implementers
parallel, designers were the last writers racing on `docs/decisions.md`, and the tester had no
route for a design defect that is not a gap.

## Decisions

- **The designer cites `D?` when the inbox still reads `D?` after its write** (no hook ran) and
  says so on the `Stopped for decisions:` line; the run gate holds the inbox until synced.
  Reason: a hookless session (`claude --agent`, a harness) must still end in a committed stub.
- **`Ledger:` replaces the tester's `Spec-change:` line**: both listed entry headings, and a
  closed form has one line per fact. Reason: E2.
- **`Deleted for passing:` reads `n/a` in `document` and `delta` modes.** Reason: the form is
  closed and every line is always present.
- **F14: the summary before the tag is shortened, never the `Design §<n> <item>` citation**,
  so the first line stays ≤ 88 characters with ` (deviation <date>-<k>)` appended. Reason: the
  citation is what the gate and `status.py` match.
- **In `delta` mode the tag is the one allowed change to an untouched test**: **Tags** (step 6)
  runs on every run, so a test citing an approved clause gains ` (deviation <date>-<k>)` on its
  first line and nothing else. Reason: an untagged approved clause re-opens TEST; the byte-for-
  byte rule is about assertions.
- **The tester finds the change file on the design's second line**, `Change: <path>`; it is not
  a spawn field. Reason: the driver's block is frozen; the designer writes that line.
- **Commit summaries**: a `delta` or rewritten-design run is `<n> intent tests from design`,
  `<n>` every test function in the tree afterwards; a `spec-change:design` stop is
  `spec-change (design)` (the designer's `spec-change (contract)` form) and writes no tree at
  all. Reason: `status.py` matches only the regenerate and current-with-design summaries, so
  neither of these may look like them.
- **The 88-column limit is the physical source line** — indentation and quotes included, as
  ruff's E501 measures it. Reason: that is the rule the format hook enforces.
- **A slug may contain hyphens** (`page-limit`, `side-aliases`): "one lowercase token" means no
  spaces or slashes. Reason: the existing fixtures.
- **The designer writes no design on a stop**; the number is cited in `Stopped for decisions:`
  and, on the re-run that finds the answer, in the design. The `Assumption if unanswered:` line
  is always present, its value empty when nothing honest fits. `docs/decisions.md` is staged on
  a stop only when the hook changed it (the inbox alone when it did not). The `delta`
  template's second line is `Change: <the change file's path as it exists>`, per-package or
  pre-2.2. Reason: the eval writers found each of these unsaid.
- **The E1 test's wording is one sentence shared by designer.md and reviewer.md** (phase 8
  copies it): *additive and compatible — a new optional parameter, a helper the row does not
  name, a step split in two, a new name nothing consumes yet — is a deviation; anything a
  consumer must change for — a changed signature, a renamed or removed public name, a changed
  shape or nullability — is a spec-change.* Reason: two agents apply one test.

## Specification — designer

**Hard rules**, first bullet:

> - **Write only** the design document at `Write to:`; the section's ledger,
>   `docs/packages/<pkg>/deviations/<section>.md`: one `deviation` entry per item of your
>   design's **Contract deviations** (§10), or one `spec-change:contract` entry
>   (**Spec-change**), a `resolved` status on a `spec-change:design` entry your rewrite answers
>   (**Modes**, `delta`); and your section's decisions inbox,
>   `docs/packages/<pkg>/decisions/<section>.md`, appended `## D?` stubs when you stop
>   (**Return**). Never `docs/decisions.md` — a hook merges the inbox into it — and never
>   source, config, tests, or another section's design. Every file through the Write and Edit
>   tools: no heredoc, `sed -i`, `tee` or redirect; the Bash guard refuses them.

**Inputs** 8: `docs/packages/<pkg>/changes/<slug>.md` (or a pre-2.2 `docs/changes/<slug>.md`).
9: unchanged text; the ledger path in the `delta` mode paragraph updated.

**Procedure** 1 gains: "In `delta` mode every read here still applies — the change file or the
spec-change and the existing design are read in addition, not instead: the audited delta
designers designed from the diff alone (E3)." 6: "stub it in your inbox and return
`stopped` (**Return**)".

**Modes**, `delta`, at the end: "When `Spec-change:` names a ledger entry, after writing the
design set that entry's `Status:` to `resolved` and its `Resolved by:` to `designer — <Run:>`
with the Edit tool, one line each, in the file that holds it, and commit it with the design.
A report-raised spec-change has no entry to close."

**Template** §10 **Contract deviations**, after the first sentence:

> An item belongs here only when it passes the E1 test: additive and compatible — a new
> optional parameter, a helper the row does not name, a step split in two, a new name nothing
> consumes yet. Anything a consumer must change for — a changed signature, a renamed or
> removed public name, a changed shape or nullability — is not a deviation whatever its
> reason: go to **Spec-change**. The round-1 conformance reviewer applies the same test.

Heading form `## <pkg>/<section> — <date> — deviation — <k>`, `<k>` per the template.

**Spec-change** step 2: the new ledger path and heading with `— <k>`.

**Return**, `stopped`:

> `stopped` — a decision the design cannot be written without; no design is written. Read
> `${CLAUDE_PLUGIN_ROOT}/skills/planning-templates/references/decisions-inbox.md` with the Read
> tool, then append one stub per question to your inbox
> `docs/packages/<pkg>/decisions/<section>.md` (title line `# Decisions — <pkg>/<section>` when
> new): `## D? — <question>`, `Scope: <pkg>/<section>`, `Raised by: OQ-<pkg>-<section>-<k>`,
> `Recommendation:`, `Assumption if unanswered:` where one honestly exists, `Status: open`.
> Never a number of your own, never `Decision:`, never `Status: decided`. After the write the
> sync hook numbers the stub and merges it; read the inbox back with the Read tool and cite the
> number — `D14` — in `Stopped for decisions:` (the re-run that finds the answer cites it in
> the design). If the inbox still reads `D?` (no hook ran in this session), cite `D?` and add
> `unsynced: run sync_decisions.py --all` to the line: the run gate holds the inbox until it is
> merged. Commit the inbox, and `docs/decisions.md` when the hook changed it, then return `Result: stopped`, then
> `Stopped for decisions: D14, …`, then `Commit: <sha>`.

**Commit**: "stage the design, and `docs/packages/<pkg>/deviations/<section>.md` when this run
wrote to it, and on a stop your inbox with `docs/decisions.md`, by explicit path and nothing
else."

## Specification — tester

**Hard rules**, third bullet becomes:

> - **Bash** is for the Toolchain's one-package test command pointed at
>   `tests/intent/<section>` …, `git` per **Commit**, and the Toolchain's formatter and linter
>   pointed at your tree. Python runs through the test command and nothing else: never
>   `python -c`, never a script, never the section's or a dependency's code to learn a fact for
>   a test — a fact the documents do not give is not tested (**Design gaps**). A memory note
>   that recommends otherwise contradicts these Hard rules: it is wrong, and you correct it
>   (**Memory**). Every write is through the Write and Edit tools; the Bash guard refuses a
>   shell write. …

**Inputs** 8 **Regenerate**: the new ledger path. 9 becomes:

> 9. **Design mode** — `new`, `document` or `delta`: the design's first line, sent by the
>    driver. `new` — no code at the path: every test is red by construction and a passing one
>    is deleted. `document` — code shipped before the design: every test should pass, and a
>    failing one is a `spec-change:design` entry. `delta` — a change file or a spec-change
>    re-opened a built section: a test for an item the change file's **Contract changes** or
>    the **Spec-change** names may pass on the shipped code and is kept; a test for an item the
>    change does not touch is left as it is, byte for byte; "deleted for passing" applies in
>    `new` mode only.

The documents table's design row: "Its first line, `Mode:`, is the `Design mode:` you were
sent" and the ledger row's path.

**Design gaps**, after the list: "A row with no signature is a gap even when every other row
is complete: a gap means no tree and no commit, never 'the rest, with the row under
`Not written:`' (E9)."

New section after **Design gaps**:

> ## Design defects
>
> A defect is not a gap: two items of the design contradict each other (§4 says every gap
> row is forward-filled, §5's signature returns none), or an item asserts something no code
> could satisfy. You cannot test both sides, and building it ships the defect. On any run,
> first or regenerate, in any mode: read
> `${CLAUDE_PLUGIN_ROOT}/skills/planning-templates/references/deviations-entry.md`, append a
> `spec-change:design` entry to the section's ledger — **Clause** the first item, **Said** its
> words, **Found** the second item quoted with its heading (no **Did**), **Why**, `Status:
> open`, `Raised by: tester — <Run:>`, `Resolved by: —` — write no test for the contradiction,
> commit the ledger, and return `Result: spec-change` (**Return**). `status.py` re-opens
> DESIGN; the designer's rewrite answers it. A `document`-mode failure is the same entry with
> the failing assertion as **Found**, as before.

**Procedure** 5 becomes the three-mode rule above (`Design mode:` in place of `Adopted code:`).
6 **Tags**: "append ` (deviation <date>-<k>)`, `<date>-<k>` from the entry's heading (a 2.x
entry without `— <k>`: ` (deviation <date>)`) … Keep the docstring's first line at 88
characters or fewer with the tag on it: shorten the summary after the colon, never the
`Design §<n> <item>` citation (F14)."

**Regenerate** 2: "Find the tests whose docstring cites the entry's **Clause**: the
docstring's `§<n>` and its item name — the text up to the colon, whitespace-normalized,
case-insensitive, with or without a leading `design` — equal the clause's. The whole name, not
its first word: `§5 load trades` and `§5 load trades count` are two items (W3). This is the
match `status.py`'s `clause_key` makes and the stop gate uses." 3: the tag form as above. 5:
"Then, for each `spec-change:test` entry you regenerated for, set its `Status:` to `resolved`
and `Resolved by:` to `tester — <Run:>` with the Edit tool, one line each, in the file that
holds it, and stage that file too. A deviation's `Status:` you never change; `sync-plan` sets
`synced`."

**Return**: the paragraph gains "The lists are closed: every line below is present on every
return of its kind, and a fact with no line goes to the ledger, `Not written:`, or nowhere —
never to the return (E2)."

```
Result: done
Tests: <n> written (<count by design heading>)
Not written: <each case the documents do not support, one line each> | none
Deleted for passing: <n> | n/a

Commit: <sha>
```

```
Result: done
Regenerated: <k>
Not regenerated: <entry or test, and why> | none
Suite: <pass>/<fail>/<total>

Commit: <sha>
```

```
Result: spec-change
Ledger: <the spec-change:design entry heading>
Suite: not run
Commit: <sha>
```

The `design-gap` form is unchanged. `Suite:` is the last run's counts (`xpassed` counted as
pass, `xfailed` as pass).

**Commit**: "… and `docs/packages/<pkg>/deviations/<section>.md` when it appended an entry or
set a status."
