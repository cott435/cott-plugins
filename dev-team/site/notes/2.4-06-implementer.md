# 06 — the implementer

Phase 06. Every rule the design changes for `agents/implementer.md`, in one edit of the
file, plus the gate's retry text, which must say the same thing. The driver receives an
implementer's first hand-back and nothing after it, so the amendment block reached nobody,
and a block or a third red attempt after the hand-back was lost (open item 14). The return
carried check results no command printed (items 4, 17). A section with an entry point could
not register it (item 1). An assumption copied into a default or a fixture shipped with no
marker (item 5). The kind table had no row for a test that fails in its own helper, nor for
a contract-stated signature that is not public (items 7, 12). A departure from the design was
described in the README with no ledger entry (item 19). And a gate FAIL the implementer could
not honestly clear had no route but two more attempts (item 16). After this phase the
implementer hands back once, without check lines; commits and marks a block it meets after
that; registers its entry points through the lock; and writes a README the gate's name check
passes. This is also the first run of the implementer set against `1e81553`'s edits.

## Decisions

- **One phase, one file.** The design spreads these edits over six build-order steps. Each
  edit of this file costs a run of an eighteen-eval set, so they are made together, after the
  scripts they describe (phases 2, 4 and 5).
- **The implementer ends a retry with `Result: done` and a block with `Result: blocked`.**
  One line each. Nothing reads them; they exist so a turn never ends in prose.
- **A block after files were written uses the same commit message as a finished run.** The
  commit holds what was built; the gate's record, not the message, says the section is
  blocked.
- **`no item affected`,** not `no line affected`: the design's words, and what the tester and
  designer write.
- **A new `forbid` claim covers agents and hooks only.** `skills/run-package/SKILL.md` still
  says the driver takes the last hand-back until phase 9, which widens the claim.
- **The report's cap drops from 25 lines to 20.** Six kinds of line are gone.

**E10 — Procedure, step 14,** replaced whole:

```
14. **Finish.** Hand back your return message (**Return message**); the stop gate runs. That
    hand-back is the only report your caller receives: the hand-back tool
    (`SubagentHandback`) delivers one report per run, and nothing you say after it reaches
    anyone. From then on your channel is the disk: your commit, the stop marker, and the
    gate's record `.dev-team/gate/<pkg>/<section>.txt`, which `status.py` reads.

    When the gate exits 2 you are not done: fix what it names, stage the fix, then look at
    `git log -1 --format=%s`. When the summary starts with your scope, `<pkg>/<section>:`,
    `HEAD` is your commit: `git commit --amend --no-edit -- <paths>` with every path this run
    has written. Otherwise a parallel run committed after you, and amending would rewrite its
    work: make a second commit with the same summary and the same trailer, by the same
    pathspec. Then end your turn with the one line `Result: done`. Nothing depends on that
    line being delivered: the gate's next record is the result. No amendment, and no summary
    of what you fixed.

    A gate `FAIL` you cannot clear is a block, not another attempt:

    - one located in a file you may not edit (another section's, an intent test's, the root
      config's); or
    - one located in your own file that is false — the check reports something your change
      did not do, and no honest edit clears it. Never bend the code to satisfy it.

    Write your marker — first line `blocked`, second line the gate's `FAIL` line, quoted
    whole — commit what you built (**Blocking rules**), and end your turn with the one line
    `Result: blocked`. The gate copies the marker's line into the record, `status.py` shows
    the section BLOCKED, and the user is asked with the gate's lines in front of them. Do not
    spend the remaining attempts first: a third red attempt reaches the user the same way,
    with less to go on.

    Every turn you end has `Result:` as its first line, never prose: a turn that ends
    mid-thought reaches the driver as a question for the user.
```
