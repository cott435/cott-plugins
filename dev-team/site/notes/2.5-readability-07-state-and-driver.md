# 07 — state and driver

Phase 07. The paths reviewer of phase 06 exists and nothing runs it, and its report blocks
nothing. This phase makes the review part of what `/dev-team:run-package <pkg>` does:
`status.py` prints a `paths:` line for the package, re-opens the sections a paths report
names as `FIX n`, and holds `shipped:` until the review approves; the driver spawns the
review when every section is DONE, asks at round 3, and closes the package only on `paths:
approved`. State and driver ship together because either alone loops: a `status.py` that says
`shipped: no (paths needed)` to a driver that cannot spawn the review would close, re-run and
close again. Step 6 of the design's **Build order**.

## Decisions

- **The `paths:` line carries the sections and the cap.** The design gives `paths: round <n>
  (<verdict>)`. The driver may not open the report, and at the cap it needs the section
  names to grant *one more round*, so the verdict reads `request changes: <section>, …` and a
  capped round ends ` (cap)`.
- **The cap is round 3 or later saying `request changes`.** At the cap no section is
  re-opened: the driver asks first, as it does at a section's cap.
- **A report is stale when any section's code moved after its `Commit:`**, the design's
  *Stale when*. A stale or missing report is `paths: needed`.
- **The line is printed once it can mean something**: when every section row is DONE, or a
  paths report exists. A package still being built has no `paths:` line.
- **The re-opened section's evidence names the report**, `paths r<m> request changes
  (<report path>)`, and the state is `FIX n` with `n` the section's own newest round: the
  design's "A re-opened section shows as `FIX n`, an existing state".
- **`--fields` gains a sixth line, `paths report:`**, so the `full` reviewer after a paths FIX
  is handed the paths report as a previous round (the design's "with the paths report as its
  previous round") without the driver reading a report.
- **`--inputs`' `Review:` carries the paths report whenever it names the section and no
  section review has covered a fix made after it**, at the cap too, so *one more round* sends
  the implementer the findings.
- **A `request changes` that names no section** cannot re-open anything: the driver asks,
  with *run the paths review again* and *stop here*.
- **No `--step` value is added.** The paths review has no section, and the design adds none.
- **The README's shipped sentence and FIX row change here**, not in phase 09: they would
  otherwise state something false at this boundary.

## Specification

### `status.py`: the package's paths state

`paths_state(pkg) -> dict` with `kind`, `n`, `verdict`, `report`, `sections`, `cap`:

1. No `[project.scripts]` entry in `<package root>/pyproject.toml` (no file, no table, an
   empty table) → `kind: approved`, printed `paths: approved (no commands)`.
2. No paths report (`paths_reports`) → `kind: needed`.
3. The newest report `R`. It is **stale** when its `Commit:` is unreadable, or when
   `_code_after_review(pkg, s, R's Commit)` is not `None` for any section `s`. Stale →
   `kind: needed`.
4. `R` current and its verdict (`_verdict`) is `approve` → `kind: approved`, printed `paths:
   approved (<R's path>)`.
5. `R` current, otherwise → `kind: round`, `n` its round, `sections` the package's section
   names that start a line under its **CRITICAL** heading (a line matching
   `^\s*(?:[-*]\s+)?`?<name>`?:\s`, `<name>` a row of the Sections table), in the Sections
   table's order; `cap` when `n >= 3`. Printed `paths: round <n> (request changes: <s>, <s>)`,
   with ` (cap)` appended at the cap, and `request changes: no section named` when the list
   is empty.

### `status.py`: rule 8

The docstring's rule 8 becomes:

```
8. **FIX n** — the newest round `n` says `request changes`, the cap is not hit, and the code is
   not newer than its `Commit:`; or the newest round approves, the code is not newer than its
   `Commit:`, and the package's newest paths report is current, says `request changes`, is
   below its cap (round 3), and names the section on a line under **CRITICAL**.
```

In `section_state`, after the `request changes` branch and before DONE: when `paths_state`
is `kind: round`, not `cap`, and the section is in its `sections`, return `FIX {n}` (`n` the
section's newest round) with evidence `paths r<m> request changes (<report path>)`.

The **Evidence.** list gains:

```
6. **paths** — `paths r<m> request changes (<report path>)`: the package's paths report
   re-opened the section.
```

and a **Paths review.** paragraph goes after **Shape.** and **Paths.**, stating the five
steps of `paths_state` in prose and the three line forms. It uses dashes, not a numbered bold
list. The sentence that starts "Shipped:" becomes:

```
Shipped: the `surface` section is DONE, `--surface <pkg>` passes, and the paths review
approves; otherwise the block prints `shipped: no (surface <STATE>)`, `shipped: no (surface
check FAIL)`, `shipped: no (paths needed)` or `shipped: no (paths round <n>)`.
```

### `status.py`: the other outputs

- **`paths report`**, a helper both flags use: the newest paths report's path when its
  verdict is not `approve`, a **CRITICAL** line names the section, and the section's newest
  review round's `Commit:` is not newer than the report's `Commit:`; else none.
- **`--inputs`** item 9: `Review:` is the list it was, then the `paths report` when there is
  one. At a paths FIX the section's own newest round approved, so the list it was is empty and
  the line holds the paths report alone. `Round:` is unchanged, the section's newest round plus one. The docstring's item 9
  gains "and the package's paths report while it names the section and no review round of the
  section is newer than it".
- **`--fields`** prints a sixth line, `paths report: <path> | none`; the docstring's list
  gains item 6 and "five" becomes "six".
- **`shipped_line`**, after the surface check passes: `shipped: yes` on `kind: approved`;
  `shipped: no (paths needed)` on `needed`; `shipped: no (paths round <n>)` on `round`.
- **`package_report`** prints the `paths:` line after the `scaffold:` line (when there is
  one) and before `shipped:`, when every row is DONE or `paths_reports(pkg)` is not empty.
- **`next_command`**, after the surface-check branch and before `_to_sync`: on `needed`, and
  on `round` without `cap`, `/dev-team:run-package <pkg>`; on `round` with `cap`,
  `/dev-team:run-package <pkg> or /dev-team:run-package <pkg> --defer`.
- **`repo_report`**: a package whose line is `shipped: no (paths needed)` or `shipped: no
  (paths round <n>)` reads `<pkg>: building (<done>/<total> DONE, paths needed)` or `…, paths
  round <n>)`.
