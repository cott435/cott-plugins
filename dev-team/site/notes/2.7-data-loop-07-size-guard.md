# 07 — the size guard on a profile's example rows

Phase 7. A profile commits real rows as fixtures, up to five per kind. The write guard now
refuses a Write or Edit that would leave a profile's `docs/sources/<token>.sample.json` over
200 KB, for any guarded role, and `status.py --run-gate` fails on one already on disk. It
closes the gap that the five-row limit is otherwise an instruction only, and a row committed by
mistake stays in the repo's history.

## Decisions

- **Profile example rows only** (design, **Decisions taken**, planning). A file is covered when
  the writer is `dev-team:profiler`, or its sibling `docs/sources/<token>.md` exists and its
  first line matches `^# Source probe — .+ — stage — `. A researcher's api sample is not
  covered, so no package without a `stage:` source sees a change.
- **200 KB is 204 800 bytes of UTF-8.**
- **The size of an Edit is computed, not read**: the file's size on disk, less `old_string`'s
  bytes, plus `new_string`'s. `replace_all` is not modelled; the run gate catches what that
  misses.
- **No text, no refusal.** An event with neither `content` nor `new_string` passes the size
  rule; the path rule still decides. A guard fails open, as the suppression rule does.
- **The size rule runs before the role's path rule**, so a role that may not write the file at
  all gets the path refusal's message only when the size is fine. Either way the exit is 2.
- **Large test content is generated.** A case file holding 210 KB of text is unreadable, so
  both fixture runners expand `{"repeat": ["<string>", <n>]}` to the string repeated `n` times.

## Specification

### `hooks/guard_writes.py`

```python
SAMPLE = "docs/sources/*.sample.json"
SAMPLE_CAP = 200 * 1024
STAGE_TITLE = re.compile(r"# Source probe — .+ — stage — ")
```

- `profile_sample(agent, path) -> bool`: true when `agent == "dev-team:profiler"`, or the file
  `path` with `.sample.json` replaced by `.md` exists and its first line matches `STAGE_TITLE`.
- `new_size(event, path) -> int`: for a Write, `len(content.encode())`; for an Edit, the size
  on disk (0 when absent) minus `len(old_string.encode())` plus `len(new_string.encode())`;
  0 with no text.
- `main`, after `rel`, `outside` and `shown` are computed and before `scoped`:

  ```python
  if not outside and _match(SAMPLE, rel) and profile_sample(agent, path) and (size := new_size(event, path)) > SAMPLE_CAP:
      print(f"dev-team write guard: {shown} would be {size // 1024} KB. A profile's example rows stay under 200 KB: "
            "five rows per kind, and the full failing set under .dev-team/data/.", file=sys.stderr)
      return 2
  ```
- Docstring, a new paragraph after **Suppression comments**: "Example rows: a Write or Edit
  that would leave a data profile's `docs/sources/<token>.sample.json` over 200 KB is refused
  for every guarded role, exit 2. A profile's file is one the profiler writes, or one whose
  sibling `<token>.md` has a `— stage —` title line; a researcher's api sample is not one."

### `hooks/hooks.json`

In `description`, "a per-role write guard, section-scoped for an implementer" becomes "a
per-role write guard, section-scoped for an implementer, that also refuses a data profile's
example rows over 200 KB".

### `status.py`

`run_gate`, last check, whatever `pkg` is:

```python
for f in sorted((DOCS / "sources").glob("*.sample.json")):
    doc = f.with_name(f.name.removesuffix(".sample.json") + ".md")
    if doc.exists() and STAGE_TITLE.match(doc.read_text().splitlines()[0] if doc.read_text() else "") \
            and f.stat().st_size > 200 * 1024:
        fails.append(f"{_rel(f)}: {f.stat().st_size // 1024} KB, over 200 KB; keep five rows per kind")
```

with `STAGE_TITLE` defined beside `_sources`. The docstring's run-gate sentence and
`skills/status/SKILL.md` gain: "and a data profile's `<token>.sample.json` over 200 KB".

## Deviations

- **The `guard_writes.py` docstring paragraph.** The note gave two sentences. What was done:
  those two, plus two more stating the note's **Decisions** the code follows (an Edit's size is
  computed and `replace_all` is not modelled, the run gate catching the rest; an event with no
  text passes the size rule, which runs before the path rule). Why: the docstring is the
  hook's one statement of its rules, and those two were otherwise only in this note.
- **`status.py`'s run-gate check.** The note's snippet reads the sibling `.md` twice. What was
  done: the same test with the text read once into `text`, and `STAGE_TITLE` carries a comment
  naming the copy in `hooks/guard_writes.py`. Why: same behaviour, one read.
- **`guard-sample-edit-over-refused`.** The note's table expects exit 2. What was done: exit 2
  and `200 KB` on stderr, as the other two refusing cases. Why: exit 2 alone would also pass
  if the path rule refused the write, so it would not show the size rule fired.
