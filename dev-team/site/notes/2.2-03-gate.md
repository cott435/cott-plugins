# 03 — gate

Phase 3. Makes the stop gate section-aware, so N implementers finishing at once each get a
verdict on their own section and nobody else's: the section comes from the implementer's spawn
prompt in the subagent transcript, the diff is the section's paths since its last review, the
marker is per section, the section's unit suite runs beside its intent suite, `repo`-scope
pytest rows are `SKIPPED` instead of timing out, a located failure outside the section that the
run did not touch is `ELSEWHERE` whatever file it is in, and the retry message states the 2.2
commit rule. `--report --base <rev>` is unchanged for `pair`. The gap it closes: today the gate
finds "the run" as `HEAD~1..HEAD` plus the working tree, which under parallel implementers is a
sibling's commit and a sibling's half-built files.

## Decisions

- **Fallback when the transcript cannot be read or holds no `Section:` line and no
  `Scaffold:`**: the 2.1 discovery (`_base()` and `gated_sections` over `HEAD~1..HEAD` plus the
  working tree), one record per section found, header suffixed ` (from diff)`. Reason: the
  design gives the write guard a role-wide fallback for the same case and leaves the gate's
  unsaid; `--report` keeps this code path alive anyway. A `Scaffold:` transcript: delete
  `.dev-team/stop/scaffold` if present, clear the counter, exit 0, run nothing (as a no-section
  run does today).
- **Touched paths** = the section diff's paths ∪ `git status --porcelain` paths ∪ the files of
  `HEAD` when `git log -1 --format=%s` starts with `<pkg>/<section>:`. Reason: the design's
  ELSEWHERE rule says "outside the section that the run did not touch"; the run's shared edits
  (`.gitignore`, `pyproject.toml`, fixtures) live outside the section's paths and are visible
  only there.
- **Section paths** = `status._paths` `code` (with its `:(exclude)` nested sections), `unit`,
  `intent`, `readme`; for `surface` also `docs/packages/<pkg>/interface.md` and
  `docs/api/<pkg>.md`. Reason: what the reviewer reviews and `--rounds commit:` covers (phase 1).
- **A `repo`-scope row is "a pytest row" when its command contains `pytest`.** Other `repo`
  rows (`lint-imports`, `ruff`, `mkdocs`) still run once within the budget. Reason: the design
  skips only pytest.
- **A missing unit tree is `FAIL unit <pkg>/<section>: no <path>/ to run`.** Reason: the
  implementer writes unit tests on every build (its step 8) and the design says "section
  intent and unit suites always". The fixture's built section gains one unit test.
- **The header's `<stamp>` is the time the record is written** (the end of the gate run), as today. Reason: F4 in phase 11 reads it as the run's end.
- **The hook-mode header is `dev-team gate — attempt n — <stamp> — section <pkg>/<section>`**
  (singular); `--report` keeps `sections a, b`. Reason: the design's Outputs; report mode is
  "unchanged" and may span several sections.

## Specification

### Docstring (steps rewritten)

> 2. Section: `agent_transcript_path` → `status.section_from_transcript`: `Section:
>    <pkg>/<section>` names the one section this run is gated on; `Scaffold:` runs nothing
>    (the marker `.dev-team/stop/scaffold` is deleted if present); an unreadable transcript or
>    no `Section:` line falls back to 2.1's discovery — `HEAD~1..HEAD` when `HEAD` carries a
>    `Dev-Team-Run:` trailer, plus the working tree, mapped to sections — with ` (from diff)`
>    in the record header.
> 3. Marker: `<cwd>/.dev-team/stop/<pkg>/<section>` whose first line is `blocked` or
>    `spec-change` is deleted with the counter; exit 0 with nothing run. A sibling's marker
>    is never read.
> 4. The run's diff: the section's paths (its code, `tests/unit/<section>`,
>    `tests/intent/<section>`, its README; for `surface` also `interface.md` and
>    `docs/api/<pkg>.md`) since the section's newest review round's `Commit:`
>    (`status.newest_round`), else since the empty tree — so Guarded sees only what was added
>    since the last review, and no commit ordering is assumed. Untracked files under those
>    paths count as added in full.
> 5. Checks, every one run: the section's intent suite and its unit suite (`tests/unit/<section>`)
>    first, then the Guarded grep of the diff, then `status.py --surface` for `surface`; then
>    the Floor and Enforced rows of `docs/constraints.md` for the section's package — a `repo`
>    row once, except a `repo` row whose command runs `pytest`, which is CI's and is written
>    `SKIPPED <row>: repo-scope pytest is CI's` (never run: it never finished inside any
>    audited gate) — else the Toolchain commands; Measured rows printed, never failed on.
>    ELSEWHERE: a row whose every located failure (a `path:line` or `path::test` its output
>    names) lies outside the section's paths and outside what the run touched (the diff, the
>    dirty working tree, and `HEAD`'s files when `HEAD`'s summary starts with the section's
>    scope) is `ELSEWHERE`, not `FAIL`: the implementer may not edit those files either. Budget
>    and TIMEOUT as before.
> 6. Every line goes to `<cwd>/.dev-team/gate/<pkg>/<section>.txt`, header `dev-team gate —
>    attempt n — <stamp> — section <pkg>/<section>`.
> 7. … exit 2 text names the 2.2 retry rule (below) …

### The retry message (stderr on exit 2)

```
dev-team gate: not done — fix these, stage the fix, then commit per §Project convention rule 4: when `git log -1 --format=%s` starts with `<pkg>/<section>:` run `git commit --amend --no-edit -- <paths>`, otherwise make a second commit with the same summary and trailer — and finish again (attempt n of 3):
<FAIL lines>
```

followed by the existing `debugging-and-error-recovery` and hand-back sentences unchanged.

### Line kinds

`PASS`, `FAIL`, `ELSEWHERE`, `TIMEOUT`, `MEASURED`, `TOLERATED`, and new `SKIPPED`. A unit
row: `PASS unit <pkg>/<section>: <n> passed` / `FAIL unit <pkg>/<section>: pytest exited <c>:
<tail>` / `FAIL unit <pkg>/<section>: no <rel path>/ to run`. An ELSEWHERE row:
`ELSEWHERE <label>: <cmd> exited <c>, every failure outside <pkg>/<section> in files this run
did not touch (<paths>): <tail>`. The outcome note counts `SKIPPED` rows too: `result: pass
(2 checks skipped)`.

### Functions

- `review_base(pkg, section) -> str`: `newest_round(...)[2]` when it is an ancestor of `HEAD`
  (`git merge-base --is-ancestor`), else `EMPTY_TREE`.
- `section_paths(pkg, section) -> list[str]` as decided; `diff_paths(base, paths)` and
  `diff_lines(base, paths)` gain a pathspec argument (`--` then the paths; untracked files
  filtered to those under the paths).
- `touched_paths(pkg, section, diff) -> set[str]` as decided.
- `_elsewhere(out, touched, section_paths)`: located files; `[]` when none located, or any is
  under a section path, or any is in `touched`; else the sorted located paths.
- `check_unit(pkg, section)`: `pytest <unit tree> -q -p no:cacheprovider --tb=line` under the
  same runner rule as `check_intent`; one line.
- `check_rows(pkgs, touched, deadline, section_paths)`: the `SKIPPED` branch before `_timed`.
- `run_checks(base, section)` returns `([(pkg, section)], lines)`; `run_checks_legacy()` is the
  2.1 body, used by the fallback and by `report()`.
- `gate(event)`: scope; `cached = status.section_from_transcript(status.subagent_transcript(event))`
  (no cache: the gate runs once); `None` with a `Scaffold:` line → scaffold exit; `None`
  otherwise → legacy path; else the section path.

### Fixture: the transcript

`check.py` `setup.transcript` (string): written to the file the event's `agent_transcript_path`
names (after `{cwd}` substitution) as one line
`{"type":"user","message":{"role":"user","content":"<the string>"}}`, its parent created. The
first line of the string is the spawn block's first line. Once F2 has recorded a real
transcript, `evals/fixtures/hook-events/transcripts/agent-implementer-ingest.jsonl` is the
shape to copy; a case may instead give `setup.transcript_file: "transcripts/<name>.jsonl"`.

## Steps

1. `build.py`: the unit test in commit 2; `{RUN_SHA}`.
2. `check.py`: `setup.transcript`, `setup.transcript_file`, `SKIPPED` in `gate_only`.
3. `gate_on_stop.py` per **Specification**; run `check.py` after each function lands.
4. The existing gate cases' `setup.transcript` and marker paths; the new cases; README.
5. `check-contracts` (the `docs/constraints.md headings` claim reads this file's citations of
   Floor, Enforced, Guarded, Exceptions — keep the words); `build-site`.
6. Evals; `log-eval`.
7. Commit: `dev-team 2.2 (phase 3): the gate is section-aware`, body naming the ELSEWHERE and
   `SKIPPED` decisions and `W3` (the gate's `_tolerating` uses phase 1's `clause_key`).
