Write the package READMEs, `docs/index.md` and the root `README.md`.

> **Guard.** If you can see earlier conversation turns, or you have an `AskUserQuestion` tool, you are
> running in the main conversation rather than as the `documenter` subagent — the agent is not
> registered, usually because the dev-team plugin was installed or updated after Claude
> Code started. Stop, tell the user to run `/reload-plugins` (or restart Claude Code),
> verify with `/agents`, and re-run.

This has to work on a half-finished repo — one package shipped, one building, one not yet
planned. Reporting a gap is useful; failing on a missing file is not.

## Run gate

`python3 ${CLAUDE_PLUGIN_ROOT}/skills/status/scripts/status.py --run-gate`. FAIL → return
`Result: blocked` with its lines, and write nothing.

## Procedure

1. **Find the documents** per your instructions: packages from the repo contract, sections from
   each package contract, never by sweeping the tree. Read each package's `interface.md` (if
   any), its section READMEs, its contract, `docs/architecture.md` and `docs/decisions.md`.
   Then run `python3 ${CLAUDE_PLUGIN_ROOT}/skills/status/scripts/status.py --repo` and keep its
   output: it is the head of every **Known gaps** you write and the source of every package
   status. If `docs/architecture.md` is missing, infer the packages from `packages/*/` or
   `src/*/` and say so under **Known gaps** — `/dev-team:plan-repo` or `/dev-team:map-repo` is
   the fix.

2. **Preserve hand-written READMEs.** For every README you are about to write — root or
   package — if the file exists and does not carry the marker line this skill writes, it was
   written by a person and may hold things no generated document knows. Copy it to
   `docs/readme-previous.md` (root) or `docs/packages/<pkg>/readme-previous.md` before replacing
   it, and say so in your return.

3. **Write each package README** — `packages/<pkg>/README.md` (or the root's `README.md`
   section for a single-package repo). Start with `<!-- generated by /dev-team:finalize-project -->`,
   then:

   - **What it is** — from the package contract's Purpose, and which repo shapes it provides.
   - **Public surface** — the **Public names** table from `interface.md`, one line each with the
     signature. With no `interface.md`, the package is *not shipped*: say so, name
     `/dev-team:run-package <pkg>` as what ships it, and list the section READMEs' `Public: yes`
     rows as *intended*. No public name is ever taken from code.
   - **Pipelines and CLI commands** — from `interface.md`; exact commands with their arguments.
   - **Sections** — the Sections table, each row linking to that section's README.
   - **Configuration** — env prefix and every env var from `interface.md` and the section
     READMEs, deduplicated; conflicting defaults shown both ways, each with its section, and
     marked *conflict*.
   - **Running and testing** — the Toolchain's one-package commands.
   - **Consumers** — `interface.md`'s **Consumers (computed)**, copied with its date.
   - **Key decisions** — `decided` entries scoped to this package, one line each.
   - **Known gaps** — the script's lines for this package, then this package's share of the
     document checks.

4. **Write `docs/index.md`** from the root README you are about to write — same content,
   site-relative links. Then, if `mkdocs.yml` exists, run the Toolchain's
   `uv run mkdocs build --strict`. A failure is a **Known gaps** entry naming the page or
   module; so is a shipped package with no API page, which is the surface section's to write
   and never this skill's.

5. **Write the root `README.md`.** Start with the marker line, then:

   - **What it is** — two paragraphs from the repo contract's Goal and Non-goals.
   - **Packages** — the Packages table in dependency order, each row linking to that package's
     README, with its status copied from the script's `packages:` group: `planned`,
     `building (<n>/<total> DONE)` or `shipped`; `no contract` is written `planned`.
   - **How the packages connect** — one paragraph per boundary from the repo contract, naming
     the shapes that cross it and the public names that carry them.
   - **Quick start** — install, configure, run, test, build docs. Exact commands from the
     Toolchain; every env var from every package, deduplicated by prefix.
   - **Entry points** — CLI commands and pipelines collected from the `interface.md` files.
   - **Key decisions** — every `decided` entry scoped `repo`, one line each; package-scoped
     ones are in the package READMEs.
   - **Documentation map** — links to `docs/architecture.md`, `docs/decisions.md`,
     `docs/deviations/` (and a pre-split `docs/deviations.md`) and `docs/followups.md` where they exist, `docs/reviews/`, each
     `docs/packages/<pkg>/`, and each package README.
   - **Known gaps** — the script's output verbatim as one block, then every document check
     from your instructions.

6. Modify no file but the READMEs above, `docs/index.md`, and the `readme-previous.md` copies
   from step 2.

## Return

First commit per your **Commit** section — scope `docs`, trailer
`Dev-Team-Run: finalize-project`. Then return, starting `Result: done`: the paths of every
file written, whether any previous README was preserved, the docs build result if run,
`Commit:`, and the Known gaps list — the script's block, then the document checks — so the
user sees what is outstanding without opening a file.
