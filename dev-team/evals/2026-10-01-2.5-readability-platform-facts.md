# 2.5-readability platform facts — the first ruff that runs `PLR0917`, and `required-version`

**Tested against:** ruff, run through `uvx` (uv 0.11.27); no plugin file is under test, branch `dev-team-2.5-readability` at `cd52b8d` · model: none (shell commands, run by Claude Opus 5.5 in the phase-0 chat) · 2026-10-01
**Set:** none — platform-fact rows PF-1 and PF-2 of `site/notes/2.5-readability-00-overview.md` **Phase 0 evals** · **Baseline:** — · **Pass rate:** 2/2

## What was tested

- **PF-1** — V, the lowest of `0.13.0`, `0.14.0`, `0.15.0`, `0.16.0` at which `PLR0917` flags
  `wide` (six positional parameters) and not `kw` (three positional, four keyword-only) with no
  `--preview`; `0.16.9` if none does. Phase 1 writes V into the lint block's
  `required-version` and the scaffold's `ruff` pin.
- **PF-2** — `ruff 0.12.0` refuses to run under `required-version = ">=V"`, both in the repo's
  own `pyproject.toml` and through `--config` (the format hook's form), exiting non-zero with
  output naming the requirement.

## Method

Real runs, in a scratch directory outside the repo (the session scratchpad, `…/scratchpad/pf`),
with the overview's `m.py` and `pyproject.toml` verbatim (`select = ["PLR0917"]`,
`max-positional-args = 5`). No cost beyond the downloads.

- PF-1: `uvx ruff@<v> check m.py --no-cache` for `0.12.0` (control), the four candidates in
  order, and `0.16.9` (control).
- PF-2: `[tool.ruff]` `required-version = ">=0.16.0"` added to that `pyproject.toml`, then
  `uvx ruff@0.12.0 check m.py --no-cache`. Then the file moved to `other/pyproject.toml` and
  `uvx ruff@0.12.0 check --config other/pyproject.toml m.py --no-cache`. Controls: the same two
  forms under `ruff@0.16.0`.

## Verdict

Both facts hold. V is `0.16.0` (no patch-level search, per the overview: the floor has to be
safe, not tight). `required-version = ">=0.16.0"` makes `ruff 0.12.0` refuse with exit 2 and a
message naming the requirement, read from a repo's `pyproject.toml` and through `--config`
alike, so the design's decision "a ruff too old for `PLR0917` refuses to run" is met by
configuration and phase 1 proceeds. Written back: both rows of the design's **Platform facts**
are `verified`, citing this file.
