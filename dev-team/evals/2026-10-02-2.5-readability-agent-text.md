## What was tested

The implementer meets a size limit only at a seam the style guide names (keyword-only past the
positional cap, no bag, no packed tuple, no trivial single-use helper); in a FIX round from the
package's paths report it fixes only the CRITICAL lines that name its section, after reading
`references/pipelines.md`, and a fix that needs another section is a `spec-change:contract`
with the paths line as `Found:`. The 2.4 implementer evals (return shape, gate retry, false
gate FAIL, entry point through the lock, decision markers, broken intent helper) still hold.

## Method

- Row 8.1: `python3 <plugin-dev 0.15.0>/scripts/contract_sweep.py`.
- Row 8.2: `claude --plugin-dir . -p "List the agents you have from dev-team. …"` from the
  plugin directory.
- Rows 8.3 and 8.4: run-evals' executor loop, one run per configuration, each executor a
  general-purpose subagent following the agent file as a proxy over the eval's fixture tree.
  Row 8.4 ran as its own iteration with `--baseline dev-team-v2.4.0`, overriding the evals'
  `dev-team-v2.3.0`. All 18 executors ran at once, then 18 graders, then 9 comparators.
- The executor and grader prompts are run-evals' templates filled verbatim, staged as one file
  per run in the session scratchpad; each subagent was told to Read its file and follow it (so
  the target file was its second Read, not its first). The manifests' expectations were not in
  the scratchpad while executors ran.
- No run was rerun or voided. Eval 16 `old_skill` disclosed one edit of `loader.py` through a
  `python3` heredoc, which the agent forbids; no expectation grades it, and the run stands.
- Cost: 18 executor runs (115k–183k tokens, 80–383 s), 18 grader runs, 9 comparators.
- **After the first review** (the user: yes to the eval 21 fix, option (a) for eval 13):
  - One fix inside the note's Files: implementer step 7 now says the paths line is "quoted
    whole, as it stands in the report, as `Found:`" (the note's Deviations). Row 8.3 reran

  - Set correction in `evals/sets/implementer.json`, eval 13 #3 and #6: a second proposed

    the manifest and `eval_metadata.json` copies carry the new text.
  - Rows 8.5 and 8.6 ran as designer iterations 1 and 2 (16 executors with 8.3's rerun).
    Two designer executors ended on a Sonnet 5.5 safeguard API error (`reasoning_extraction`):
    eval 9 `old_skill` and eval 10 `with_skill` in iteration 1. Each was emptied and rerun once
    with the same prompt; both reruns finished. Eval 10 `with_skill`'s rerun and eval 8
    `with_skill` (iteration 2) each said one of its own turns was stopped by the safety

## Verdict

After the review: rows 8.3 (23/23 vs 16/23), 8.4 (40/41 vs 39/41, set corrected) and 8.6
(42/42 vs 38/42) meet their bars. Row 8.5 misses its bar (with_skill must pass every
expectation; 24/27 vs 23/27). Every reader's-test expectation passes for with_skill and fails
for the baseline in both evals (module per step, `pipelines.md` read); the three misses are a
run that wrote no `commit.txt` and summarised its final message (eval 9 #12, #13, where the
baseline's run wrote both) and an §6 that names the error type once instead of per code
(eval 10 #7; `designer.md` item 6 already asks that every error case name its type). No fix
inside the note's Files addresses either, so none was made; stopped to ask (the note's
Deviations). The user: "commit as is".

The first verdict, before the review: Row 8.3 misses its bar (with_skill must pass every expectation): eval 21 #2 is the new
text's own target — "with the paths line as `Found:`" was read as "cite the paths line", and
the entry retells it. Eval 20 #9 is the commit rule (`git-workflow-and-versioning`), not this
phase's text. Row 8.4 misses by one expectation (38 vs 39): both of eval 13's misses come from
the implementer now refusing the design's one-statement `_sort`, which 2.5's shape rule fails;
the set's "exactly one entry" predates that rule. Stopped for review before any fix.
