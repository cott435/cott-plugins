## What was tested

8.1: the bundle's contracts after the two edits. 8.2–8.3: the reviewer writes its report under
`docs/packages/<pkg>/reviews/<section>/`, takes `Commit:` from `status.py --rounds` rather than
HEAD (F12), judges designer-raised contract-row entries by the E1 test (additive → `approved`;
consumer-breaking → `rejected` plus an appended `spec-change:contract` and a `spec-change`
verdict), and returns the closed form (E2). 8.4–8.6: the architect keeps its 2.1 behavior,
writes one change file per affected package for a repo-level change, and at the close sweeps

## Method

8.1: `python3 ../plugin-dev/scripts/contract_sweep.py`. It failed once, at
`agents/reviewer.md:3`, because the new description's `<pkg>/<section>` read as an XML tag.
After switching to the `{pkg}/{section}` spelling, 37/37 passed. `build-site` exited 0.

8.2–8.6 used `run-evals`: 20 proxy executors (general-purpose subagents given the agent file,
with each set's harness rules), one message, `with_skill` and `old_skill` together. Each
executor prompt said to read the target file first and to read every file with the Read tool.
One grader ran per run, and blind comparators ran on the evals whose two sides tied or came
within 10 points. All agents ran on Sonnet 5.5. Two executors (reviewer eval 2 `with_skill`,
reviewer eval 5 `old_skill`) ended on an API safeguard error (`reasoning_extraction`) before
writing anything useful. Their run directories were cleared and they were rerun once with the
same prompt. One run, n=1 per configuration.

The `old_skill` executors read the 2.2 templates and skills from the working tree, as in
earlier phases. Only the agent file came from the snapshot.
