## Verdict

The docs, the six stale-path claims and the mechanical rows hold (11.1, 11.2). The end-to-end build under 2.2 ships both packages headless with every 2.2 mechanism visible and working — per-section review directories, section-named gate records, `SKIPPED` repo pytest, the decisions inbox, the Bash guard refusing live writes, batches that hold every ready row's step — but **misses the pass bar at 10/14**, against 9/14 for the 2.1 driver on the same agents and a blind preference for 2.2. No fix inside this phase's Files could answer any miss: #6 is the reviewer prompt's size, #7 an implementer return-form slip (one of twelve runs), #9 the driver's read discipline, #12 the one-way sync hook's design. So there is no rerun; the misses are recorded in the note's Deviations and as *noticed* lines in the ledger. F4 was not observable on this fixture. Findings outside the pass bar, for later changes: `plan-package` step 1's `--run-gate <pkg>` fails an unplanned package (both configurations' architects hit it, one refused itself in the aborted attempt; the line is in 2.1.0 too); the `workspace-scaffold` consumers contract lacks `allow_indirect_imports` and a `mypy_path`, which under 2.2's section-scoped guard no non-surface implementer can add; `guard_bash.py` misses `python3 - <<EOF` writes and lets any command through `locked.py` (a `locked.py deps -- sed -i … pyproject.toml` ran); `--model sonnet` in this CLI is Sonnet 5, so phase 9's headless runs were likely Sonnet 5, not 5.5 as its log says.
