## What was tested

That `status.py` reads the new `docs/packages/<pkg>/{deviations,reviews/<section>,changes,decisions}/` locations with the 2.0 ones still read; parses the ledger heading's optional `— <k>` (F13); matches clauses on the full item name (W3); prints `commit:` on `--rounds` (F12); fails the run gate on an unsynced inbox; and reads a section from a subagent transcript — without changing any 2.1 behavior the existing state cases and hook-events cases pin.

## Method

Mechanical, real runs. Each state case builds its own git repo and runs `status.py` there. The fifteen new cases were also run against the 2.1 `status.py` (swapped in, then restored) to see which fail without this phase. Hook-events was run against both `status.py` versions for the one case failing at the phase's start, and the outputs diffed. `section_from_transcript` ran on phase 0's recorded fixture; `cached_section` and `subagent_transcript` ran on phase 0's real `PreToolUse` event (extra, not in the note's table).
