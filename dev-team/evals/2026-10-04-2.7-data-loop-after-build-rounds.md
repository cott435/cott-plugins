## What was tested

Phase 5 (`site/notes/2.7-data-loop-05-after-build-rounds.md`): a marked section its reviewers
approved is PROBE again until a profile round over its built output is current; `status.py`
derives that and `--profile` prints round `n+1` on the section's commit; the profiler's
`Round 1 and later` procedure points the built section at `<Store>work/`, re-runs the checks,
appends a new kind or closes `clean`; its verify run at round 1 writes one
`spec-change:design` ledger entry and the round line `new kinds: …`. Plus: nothing changes for a
package with no `stage:` source, and round 0 is not regressed.

## Method

Rows 5.1–5.4 are shell runs from `dev-team/`. Rows 5.5–5.6 are `run-evals` behavioral runs,
proxy: a general-purpose subagent given `agents/profiler.md` (working tree, or the copy in the
iteration's `baseline-snapshot/` at `eb339b6`) and started with the spawn block
`status.py --profile` would print; its `tools:` list, the write guard and the decisions sync
hook are not reproduced. One run per configuration per eval; each seed is a git repo built by
`evals/sets/files/profiler/build.py case-<id>` in a `mktemp -d` copy (uv and duckdb were
available, so every store was built). The baseline is phase 1's commit, not `previous`: the
merge-base with `main` has no `agents/profiler.md`.
