## What was tested

That `status.py --surface <pkg> --section <s>` fails a README name cell that is not exactly one
backticked identifier (grouped, dotted) and a `Public: yes` name the contract's **Public surface
(intent)** does not name, passes a clean README and says `n/a` with no README; that the
package-wide `--surface` reports a grouped cell as its own reason without losing its second name;
that `shipped: yes` needs that check to pass, with `shipped: no (surface check FAIL)`, a matching
`next:` line and `--repo`'s `building (… surface check FAIL)` otherwise; and that the stop gate
runs the per-section check for every section but `surface`, counts removed asserts and
`pytest.raises` per file net of added ones, reads a wrapped `xfail(` call to its closing bracket,
and keeps ruff 0.15's ` --> path:line` lines in a FAIL's detail.

## Verdict

Holds. Three fixture adjustments the note did not spell out, under the note's **Deviations**: the
state-case README template's name cells are now backticked (the old bare cells fail the one-name
rule, which would have made `shipped` print `shipped: no`); the hook-event build's README had no
**Entry points and interfaces** table, so it gained one row and the contract the intent item; and
`gate-assert-rewritten-pass` rewrites to `load_trades(str(csv_file))`, not the note's
`load_trades(Source(p))`, so the unit suite stays green with no `Source` to import. The arrow case
builds the path from two strings so the FAIL line's echoed command cannot satisfy it; its first
draft passed against the 2.3 gate for exactly that reason. The ruff on PATH is 0.12, so the arrow
case stands a printing command in for ruff 0.15 rather than running it.
