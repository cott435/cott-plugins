**Tested against:** uncommitted — see working-tree diff (branch at `c0ca2a3`; `agents/architect.md`, `skills/plan-package/SKILL.md`) · model: executors and graders `claude-sonnet-5-5` (Agent tool `model: sonnet`); the chat that ran them was Opus 5.5 · 2026-10-02
**Set:** `evals/sets/architect.json` evals 1, 7, 8 · **Iteration:** `evals/workspace/architect/iteration-1`, `evals/workspace/architect/iteration-2` · **Baseline:** `dev-team-v2.5.0` (`e30927c`) · **Pass rate:** iteration 1 20/21 (95%) vs 9/21 (41%); iteration 2 20/21 (96%) vs 7/21 (31%) · **Blind:** not run (pass rates 55+ points apart)

## What was tested

That the architect at package scope writes **Call paths** when it WRITEs a contract (one entry
per command, frames the contract owns, the effect last, budget 8, no decision stub). That it
treats a planned contract with no **Call paths** heading as an EDIT item of the change list
instead of returning "current". And that the 2.4 WRITE regression (eval 1, now with nine
headings) still holds.

## Method

Rows 2.1 and 2.2 were shell runs. 2.1: `contract_sweep.py`, run after each architect edit.
2.2: `claude --plugin-dir ./dev-team --model claude-sonnet-5-5 -p "List the agents you have
from dev-team"`, run from the repo root. Rows 2.3 and 2.4 were behavioral, through `run-evals`.
Each executor was a general-purpose proxy subagent given `agents/architect.md` and the
`plan-package` skill body from its configuration's plugin root (working tree or the
`dev-team-v2.5.0` snapshot), with fixtures `write/` and `edit/` read in place. There was one
grader per run, using skill-creator's `grader.md`.

- **Iteration 1:** six runs, evals 1, 7 and 8, with each configuration run once.
- **Iteration 2:** run after one fix to `architect.md` and three corrected expectations. The
  three with_skill runs were fresh. The old_skill runs were copied from iteration 1, since the
  baseline is unchanged. Eval 1's old_skill grade was kept, since its expectations did not
  change. Evals 7 and 8 old_skill were regraded against the corrected expectations.

No run ended in an error or was voided.

## Fix and set corrections between iterations

- **Fix (in the note's Files): `agents/architect.md` `## Call paths`.** One sentence was added
  after "never leave a frame unnamed". A **Pipelines** entry that names no function gets its
  function's name and signature, so the `pipelines.<function>` frame has an owner. Those two
  additions are the only edits a path brings outside **Call paths**, and the contract carries
  no note that the heading was added.
- **Set: eval 8 expectation 5.** It forbade any change to Pipelines, while expectation 3 needs
  a `pipelines.<function>` named in Pipelines. The fixture's entry names no function, so the
  two contradicted each other (grader critique). It now allows the function's name and
  signature, and forbids a note of the edit.
- **Set: eval 8 expectation 6 and eval 7 expectation 5.** Graders found both satisfied by a
  run that wrote nothing. Each now requires the edited contract or the `## Call paths`
  section. This changed the old_skill verdicts (eval 8 #6, eval 7 #5: pass to fail), so those
  two runs were regraded.
- **Not changed, noted.** Graders also suggested:
  - eval 7: require a sub-bullet per effect the harness names (file read, database write,
    stdout);
  - eval 8: require the stdout path;
  - eval 1: expectation 7 is vacuous when the harness answers every question;
  - the no-Agent checks rest on the executor's prose transcript.

  These are additions, not corrections, and were left for a later phase.

## Verdict

Row 2.3 holds after one fix. Iteration 2 passes every expectation of evals 7 and 8 with the
working tree, and the 2.5.0 baseline fails the expectations each note names (eval 7: 1–4;
eval 8: 1 and 4).

Row 2.4's bar ("every expectation passes for with_skill") was met in iteration 1 and missed in
iteration 2. The miss is eval 1 expectation 3: the `storage` → `clean` edge, which the brief
gives as "ingest, clean, storage, in that dependency order". Phase 2 did not touch that part
of the architect, and the 2.5.0 baseline misses the same edge. Read as variance on a
pre-existing judgment, not a regression from this phase's text. No second fix was tried. The
outcome is a Deviation in `site/notes/2.6-spine-02-architect-plan.md`, and whether to commit
is the user's call.
