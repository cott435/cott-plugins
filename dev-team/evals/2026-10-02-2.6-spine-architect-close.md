## What was tested

That the architect's package close (`sync-plan`), on a contract with no **Call paths** heading,
writes the heading as built from `status.py --paths <pkg>` after an archive copy — every frame
of the tree named `<owner>.<name>`, `budget 8`, no `D<n>` — and, for a command past depth 8, an
open `changes/paths-<command>.md` proposing the cut and a pointer on the command's line; that
`sync-plan`'s "nothing to collect" exit no longer skips that; and that the 2.0-layout close
(eval 3) still applies, syncs and leaves open what it did before.

## Method

- **6.1** `python3 <plugin-dev>/scripts/contract_sweep.py` from the plugin directory.
- **6.2, 6.3** `run-evals` on `architect`, one run per configuration, the working tree
  (`with_skill`) against the 2.5.0 snapshot (`old_skill`), executors as general-purpose
  subagents given the agent file (proxy).
- **Set corrections before the first run.** Row 6.3's note says eval 3's harness "says what
  the command would print"; it did not, and the fixture does have code. `status.py --paths data`
  on a git copy of `evals/sets/files/architect/sync/` prints `paths: no commands` (no
  `pyproject.toml`); eval 3's prompt now says so, and expectation 8 admits the inserted
  `## Call paths` with `- none (no commands)`.
- **Iteration 3** (evals 9 and 3, four executors in one batch, no errors). Eval 3: both
  configurations 9/10, both failing expectation 1 the same way: `sync-harness.md` answered
  "What goes in `Resolved by:` when no commit sha exists" with
  `run-package data (sync-plan), <today>`, and both took it over the review's `Commit: 7b2f0a1`.
  The harness answer now points at the newest approving review's `Commit:` line. Eval 9's
  grader noted expectation 2's trailing colon on `data-verify` contradicts expectation 5's
  past-budget tail; reworded, no verdict changed.
- **Iteration 4** (eval 3 only, both configurations rerun). with_skill wrote
  `Resolved by: approve @7b2f0a1`; the grader failed it on the bare-sha wording, but
  `deviations-entry.md` item 8 names `approve @<sha>` as the synced form, so expectation 1 now
  accepts both and the run was regraded.
- **Graders' critique, then a regrade of all four kept runs.** Eval 3: expectation 8's
  "under 2.6 and later" read as optional (old_skill passed with no heading) and the return's
  **Call paths** row was unchecked; both are now required. Eval 9: nothing checked that the
  proposed cut keeps the `verify` pipeline's behaviour or names its frames as the path does;
  expectation 7 added. Not acted on: eval 9 #8 (no `decisions.md`) is vacuous on a no-op, but
  #5's positive pointer already fails one; the transcript-based checks rest on the executor's
  own narration, as in every proxy run.
- Blind comparison on eval 3 (iteration 4), one comparator, outputs only.

## Verdict

Rows 6.1–6.3 hold. The close's step 8 writes the as-built heading exactly as the template's
form and the phase note specify, with the change file for the one path past budget; the 2.5.0
close writes nothing on the same fixture. The regression close still does everything it did.
Every change after the first run was to the set (eval 3's prompt, its harness answer,
expectations 1, 8 and 9; eval 9's expectation 2 and a new 7); `agents/architect.md` and
`skills/sync-plan/SKILL.md` were not touched after the first run. The prompts that changed
were rerun (eval 3, iteration 4); the expectation-only changes were regraded.
