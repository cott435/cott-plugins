## What was tested

Iteration 4 (`2026-10-02-2.5-readability-docs-and-release.md`, row 9.4) stopped at batch 2. The surface implementer's
`Skill("security-review")` resolved to Claude Code's built-in `/security-review` command, which
reviewed the plugin repo's branch diff and replaced the implementer's return. The claim tested
here has two parts:

- With the skill named in full, the implementer's Skill call loads dev-team's knowledge skill
  and the built-in does not take over.
- The run then goes past batch 2: the FIX, the round-2 `full` review of `surface`, and the
  second paths review call. Iteration 4 never reached any of them.

## Noticed, not fixed

- **The executor's own records are condensed.** The harness asks `transcript.md` for every
  driver tool call and `status-log.txt` for each `status.py` run's full output. This executor
  summarised both. For example, the `--inputs` output appears as `(implementer block, Round: 2,
  Review: paths r1 report)`, and most table rows are left out. The grader had to use
  `stream.jsonl` to confirm expectations 3 and 4. This is how the executor wrote its records,
  not the target's behavior.
- **The round-2 `full` reviewer did not invoke `dev-team:security-review`.** Its `Scope:` says
  `security-review: no When to Activate condition matched (no input parsing beyond a local CSV
  path, no auth, network, secrets or SQL in the diff)`. That judgement was made without loading
  the skill. For round 2, `reviewer.md`'s item 6 asks for the call only when the diff touches
  matching code, but the implementer judged that this section did match. So the two agents
  disagree on the same diff. The run gives no sign that the name resolution failed.
- **The implementer recorded no security conclusion.** It ran the checks, but no file under
  `outputs/repo/` mentions security except the r2-s review. `agents/implementer.md` step 4 puts
  that conclusion in the README's **Implementation notes**. For the surface section the README is
  `interface.md`, whose headings (Public names, Pipelines, CLI commands, Configuration, Shapes
  provided, Deviations, Consumers) have no **Implementation notes**. So a surface section has
  nowhere to put it. This is worth a look; it is not fixed here.
- **Bare `security-review` mentions remain** in places that refer to the skill rather than
  invoke it: `agents/implementer.md:374` and `:521`, and `agents/reviewer.md:179` and `:257`.
  None of them is a Skill call, so they did not affect this run.
- Driver file access stayed within `run-package`'s rules. It made one Glob of
  `reviews/surface/` (for **Previous round**) and one Read of `contract.md` (the Sections table),
  and it made no Read, `cat` or `grep` of any report.
