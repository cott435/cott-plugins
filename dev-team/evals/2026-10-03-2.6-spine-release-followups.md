## What was tested

Three fixes found while running 2.6-spine's last phase, before the 2.6.0 bump:

1. `status.py --paths <pkg> --against-contract` compares a command with an open change file's
   **Call paths** entry (its `to`, after a `from`) when one gives it, and says so on the
   `contract:` line; a synced change file is not read. `reviewer.md` **Focus: paths** judges
   that comparison.
2. `run-package`'s reviewer block sends **Intent tests** as `<package root>/tests/intent/<section>/`,
   with a forbid claim that fails on the repo-root form in a skill's table cell.
3. `architect.md`'s close step 5 writes a synced deviation's `Resolved by: approve @<sha>`, the
   form `deviations-entry.md` item 8 gives; architect eval 3 expectation 1 accepts that form only.

## Method

Shell runs. State cases with `check.py`: the full set on the working tree, and the two new cases
against `07d69bc`'s `status.py` (a copy of `check.py` pointed at `git show HEAD:…/status.py`,
removed after). The contract sweep on the working tree, then with `skills/run-package/SKILL.md:208`
put back to `` `tests/intent/<section>/` ``, then restored. Eval 3 expectation 1 regraded on
iteration 4's existing ledger outputs, reading the `Resolved by:` line; no executor rerun. No
behavioural eval ran for the reviewer's new sentence: no set has a change-file paths review yet.
No API cost.

## Verdict

All three fixes hold on the mechanical checks. The change-file comparison is exercised by a case
that fails on the committed script and one that pins the synced behaviour. The reviewer's
judging of a `from <change file>` line is a prompt change with no behavioural eval yet; a
reviewer eval with an open change file that moves a frame between sections is the check to add.
