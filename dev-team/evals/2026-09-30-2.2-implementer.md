## What was tested

That the rewritten implementer handles a batch run correctly. Its `Applied:` lines go to the section's decisions inbox, not `docs/decisions.md`. Its shared edits go through `locked.py`, it makes no shell writes, and its scratch lives under `.dev-team/tmp/`. It invokes the design's skill first (E10). A FIX round restates step 0's reads (E3), keeps the Prove-It order (E11), and makes a second commit, not an amend, when `HEAD` is a sibling's. It states a `repo`-scoped `D<n>` as binding and makes no unbacked claims in its return (E12). The 2.1 behaviors covered by evals 1–10 must not regress.

## Method

- **6.1** `python3 ../plugin-dev/scripts/contract_sweep.py`: first `36/37` (see Results), then `37/37` after the fix.
- **6.2–6.4** `run-evals`, one run per configuration. Each executor was a general-purpose subagent given the agent file: `with_skill` read the working tree, `old_skill` read the snapshot. This is a proxy: the agent's `tools:` and `skills:` are not reproduced, and a skill counts as "invoked" when its `SKILL.md` was read. Plugin skills were read from the working tree in both configurations. The executor prompt named the eval's `eval_metadata.json` for the prompt text rather than inlining it, and told the executor to read no other copy of the agent file and nothing else under `evals/workspace/`. No hook ran. One grader per run (skill-creator's `grader.md`, from the cloud session's synced copy); graders read the expectations from `eval_metadata.json`. `aggregate_benchmark` wrote `benchmark.json` and `benchmark.md`; a static `review.html` was generated.
- **Concurrency:** the session caps running subagents at 20, and the 21st–24th spawns were refused (`Concurrent subagent limit reached. You can run 20 subagents at once.`). Evals 11 and 12 were started as slots freed, and graders were started as executors finished.
- **Shared scratch:** executors used the session scratchpad as "the system temp directory". Two runs (eval 12 `old_skill`, eval 11 `with_skill`) used the same `scratchpad/repo` copy, and the second ran `rm -rf` on it. Both then worked from uniquely named directories, and the results they quote come from those. Later grader prompts asked for a `mktemp -d` directory.
- **Blind comparison** (the pass rates are within 10 points): `S blind`, then one comparator per eval with skill-creator's `comparator.md`. Comparators see `outputs/` only, without `transcript.md`, so expectations that need the transcript failed for both sides there.
- Cost: about 3.4M executor tokens, 1.9M grader tokens and 0.9M comparator tokens.

## Iteration 2 (the one fix)

**What changed:** `agents/implementer.md` only.
- A behavior called tested names its test, a check called run or clean has its command and output from this run, and a library default is claimed only when observed. This applies in the return, the README and the ledger.
- Step 4 decides from the conditions the description lists; the body's **When to Activate** is read only after a match.
- Tool installs and converted configs count as throwaway and go under `.dev-team/tmp/`.
- Only the dependencies the design names are added; a tool a check needs goes under *needed from elsewhere*.
- The README's **Implementation notes** name the rules of each skill the code follows.
