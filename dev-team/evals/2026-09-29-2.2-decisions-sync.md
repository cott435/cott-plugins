## What was tested

That `sync_decisions.py` folds a section's inbox into `docs/decisions.md` one way under a mkdir lock: it numbers `D?` stubs (and renumbers self-numbered or mismatched ones), adds only missing `Applied:` lines, never lets `Decision:`/`Status:` flow, is idempotent, and fires in a real session only inside a dev-team repo. Also that `locked.py` serializes commands and breaks a stale lock, and that the new `contracts.yml` claim catches a renamed inbox field.

## Method

- **2.1**: `python3 evals/fixtures/hook-events/check.py`, real runs, 15 new `sync-*` cases (each builds a fresh repo and pipes a recorded `PostToolUse` event, or `--all`, into the script).
- **2.2 and 2.3**: run by hand in a scratch directory with the note's commands.
- **2.4**: plant **Applied** → **Applies** in the template, run the sweep, revert, and run it again.
- **2.5**: the note's `python3 -c` over `hooks/hooks.json`.
- **2.6**: `run-evals` with one executor per configuration and one grader per run, all on Opus.
  - Each executor ran two real `claude -p` sessions (in scope and out of scope) with a stub designer.
  - **Changed from the eval's command:** the container runs as root, and `claude` refuses both `--permission-mode bypassPermissions` and `--dangerously-skip-permissions` as root. Both configurations ran `--permission-mode acceptEdits --allowedTools "Agent Read Write"` instead, the same fallback phase 0 used. The first baseline executor stopped on the refusal, and it was rerun with the flags given up front.
- **Extra, not in the note:**
  - After a sync, `status.unsynced_inboxes()` returns `[]`, where the run gate's inbox check read two reasons before.
  - Two hook processes fired concurrently on two inboxes, 20 times over.

## Expectations corrected (run-evals step 7)

The with-hooks grader flagged five expectations of `hooks.json` eval 3, and they were rewritten in the set (`note_2_2_phase2`):
- **1** now checks the stream's `init` `cwd` and `plugins[].path`, not `commands.md` alone.
- **2** requires byte identity of every non-heading line.
- **6** reads the designer's own Read in the stream, not only its relayed report.
- **8** requires `.dev-team/locks` to exist, so it can tell a lock that was released from one that was never taken.
- **9** adds `no .dev-team` out of scope.

No with-hooks verdict changes under the rewrite. Each new clause was checked against its outputs:
- init `cwd` `in-scope`/`out-of-scope`, plugin path `eval-hooks3-with/P`;
- the tree lists `.dev-team/locks`;
- out of scope, `no .dev-team`.

So it was not rerun. The baseline was graded against the rewritten list. Both graders note that 7 and 9 cannot tell "silent by scope" from "no hook loaded". That is inherent to a baseline that deletes `hooks/`, and it was left as is.

## Verdict

Holds, and every row meets its pass bar. The sync hook numbers stubs in a real session, and the model sees the number before its next tool call. Out of scope it is silent, and concurrent firings do not collide. The one change to the eval's method: both configurations ran in `acceptEdits` rather than `bypassPermissions`, because the container runs as root.
