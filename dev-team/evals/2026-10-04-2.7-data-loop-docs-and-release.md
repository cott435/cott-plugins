**Expectation 9 corrected.** As first written it forbade `docs/decisions.md` in any commit
naming a `docs/sources/` path. The profiler's verify commit `442a8e6` staged
`docs/decisions.md` beside its inbox `docs/packages/data/decisions/clean.md`: the sync hook had
merged the two new `## D?` stubs into it as D2 and D3 (14 insertions, both `Status: open`, no
`Decision:`). That is `git-workflow-and-versioning` §Project convention **Staging** ("and so
does `docs/decisions.md`, which the sync hook merged it into: a `D<n>` a committed design cites
must exist in a commit"), which every committing agent follows; the profiler's hard rule
forbids *writing* `docs/decisions.md`, and it never wrote or edited it. The grader's critique
named the conflict. The expectation now allows `docs/decisions.md` only in a commit that also
adds the inbox's stubs, its diff no more than those entries as the hook merged them, and still
forbids any `Decision:` or `Status: decided` line from the profiler. Regraded alone in both
runs: `with_skill` fail → pass, `old_skill` stays fail (no store under `.dev-team/data/`).
