## What was tested

A colleague's review found no whole-repo test run before review or before a commit reaches
GitHub: the stop gate skipped the `repo`-scope pytest as "CI's", and no step wrote a CI
workflow. The claims: (1) `gate_on_stop.py --integration <pkg>` runs every check CI runs over
the whole repo, every failure a FAIL, and records which sections of the package each failure
lies in; (2) `status.py` re-opens those sections at FIX n below run 3, holds `shipped:` until
the record passes on the package's current code, and stops reading a record once anything
under the package root changes; (3) the stop gate runs the suites of finished packages that
depend on the section's package, FAIL when the failure traces into the section's files, else
ELSEWHERE; (4) `--scaffold` asks for `.github/workflows/ci.yml` and for every Floor and
Enforced command (else Toolchain line) it lacks.

## Method

Shell runs from `dev-team/`. Each new state case and hook-event case was run against the
working tree and against `c30588a`'s `status.py` and `gate_on_stop.py` (a scratch copy of the
plugin with those two files replaced), to see it fail before the change. Smoke runs by hand on
`state-cases/shipped` built repos: a passing run, a committed failing unit test re-reviewed so
the section is DONE (run 1 → `ingest · FIX 2`, `--inputs` Review the record), two more rounds
to the cap at run 3, a docs-only commit (record holds), an uncommitted and an untracked file
under the package root (record stale); and a second package `analysis` depending on `data`,
all DONE, with `data.ingest` broken in the working tree (`--report`: `FAIL regression
analysis … traced to …/ingest/__init__.py`; an `ImportError` traced the same way; an
analysis-only failure `ELSEWHERE`), then `--integration data` with analysis red (`reopens:
none`, two `unowned:` paths).

## Verdict

The mechanical claims hold: the integration record is written, read, re-opens the right
section, caps at run 3, holds across docs-only and other-package commits and goes stale on any
change under the package root; the regression check fails a traced consumer break and leaves an
untraced one ELSEWHERE; the scaffold check asks for the workflow and for each missing command.
What no row covers is the driver following the new step 7 and the implementer acting on an
integration record in a real run (row 8); that needs the end-to-end runner
(`evals/runners/run-package`) before the bump is trusted on agent behaviour.
