## What was tested

That the checks the 2.7-data-loop ledger and its eval logs named as weak now rest on raw
evidence in `outputs/` rather than on the executor's prose: which rows a verify run sampled,
what prompts the driver sent and what it read or wrote, whether the built `clean` honours the
decided treatments, and whether a later round's profile program still counts what round 0
counted. Then that the plugin, unchanged, still passes the strengthened profiler evals 1–3 and
run-package eval 19.

## What changed in the eval layer

1. **Prose → raw evidence.**
   - Profiler verify sheets (`case-2`, `case-3`, `case-6`) have the run record the
     `trade_id`s it drew per kind (`flagged`, `passing`, `misjudged`) in
     `outputs/sample-ids.json`, written before anything in the copy. `build.py collect` holds
     them against the seed commit — which kinds are `unverified` and their checks, the
     program's check ids and C3 predicate, the landed data, at round ≥ 1 the seeded section —
     and writes `outputs/sample-check.txt`: per kind `ok`/`FAIL` (≥ 20 or all flagged, ≥ 20
     passing, every id one the check puts there, every `misjudged` id one the check judges
     unlike the contract), and whether the file was written before the run's changes. Seed
     shas unchanged (all seven cases rebuilt before and after). Profiler eval 2 #5/#6, eval 3
     #7 and eval 6 #6 read it. Cases 1–3 also tell a run given no plugin root to read nothing
     in the plugin directory but its sheet (phase 1's baseline read `data-profile.md`); this
     iteration's three `without_skill` transcripts record no such read.
   - Run-package evals 13, 18 and 19 run their executors headless; after the session the
     runner runs `collect_stream.py`, which writes the driver's own tool calls from the stream:
     `agent-calls.md` (every Agent call, prompt verbatim, by batch), `driver-log.txt` (every
     Bash command with its output, Read/Write/Edit paths, and a `[[collect_stream]] batch <n>
     sent` line per batch), `reads.txt`, `writes.txt`, `bash.txt`. Eval 19's prompt checks
     (#5, was #2) and order checks read these. Harness 19's `spawns.md` must copy prompts
     whole; its one collect command, `collect_19.py`, writes `git-log.txt` with
     `--name-status`, `git-log-docs.patch` (the `docs/` patch), the store listing, the final
     status and `treatment-check.txt`. Evals 13 and 18: #6 split into the git state, the
     writes (`writes.txt`, `bash.txt`) and, for 13, the reads (`reads.txt`, `bash.txt`); a
     run with no stream fails those rather than resting on `transcript.md`.
2. **Conjunctions and vacuous passes.** Eval 19's ten expectations became 46 (#1, #3, #4,
   #5, #7, #9, #10 split one fact each; three new). Preconditions added: architect eval 1 #7
   (a `D<n>` exists), profiler eval 1 #11 and eval 2 #4 (the profile was written), profiler
   evals 4 #9, 5 #4, 6 #4, 7 #4, run-package eval 17 #6 and eval 18 #6/#7 (the cap path or
   the call exists). Profiler eval 1 #7 split, and its conflict with `data-profile.md` item 8
   resolved: either count of Unexplained passes as long as the in-no-kind count is stated.
   `validate` exits 0 on all three sets.
3. **The built code against the decided treatments.** `check_treatments.py` runs the built
   `clean_trades` (found by searching the section for `def clean_trades`; the contract fixes
   its signature and the rejects columns) on the stage's 409 rows and checks by row: one copy
   of each repeat kept, the lowercase symbols upper-cased, the price ≤ 0 and size 0 rows out,
   every other row — the out-of-order ones among them — kept unchanged (`output`); every row
   removed or altered in the rejects file with its kind id, the kind found from
   `rawtrades.sample.json` and the design's kinds-table treatment (`reject record`); and it
   reruns the newest `rawtrades.profile.py` as at round 0 in a clean clone and compares each
   check's count with the profile's `### Round 0` block (`round 0 reproduced`). Tried before
   the runs on phase 8's kept copy: output PASS, reject record **FAIL** (its reasons were
   `duplicate`, `non-positive price`, … with no kind id), round 0 PASS; and on two broken
   copies of it (a `clean_trades` that keeps everything fails `output`).

`check-contracts` 53/53 after the edits; `build_site.py` wrote 118 pages (no agent or skill
changed, so no workflow page is affected).

## Method

- Profiler (proxy, as in phases 1 and 5): one `with_skill` and one `without_skill` run per
  eval, general-purpose subagents given run-evals' executor prompt; one grader per run.
- Eval 19: as phase 8 — each executor a headless `claude -p --model claude-sonnet-5-5
  --plugin-dir <plugin_root> --permission-mode acceptEdits --allowedTools "Bash Read Write
  Edit Glob Grep Agent Skill" --output-format stream-json --verbose` session from a scratch
  project whose `.claude/settings.json` disables `dev-team@cott-plugins`, `--add-dir` for the
  run directory, the plugin directory and the run's scratch directory. The sessions' init
  events list nine `dev-team:` types (profiler among them) for the working tree and eight for
  the snapshot. Then `collect_stream.py` on each stream.
- **One run voided and rerun.** The first `with_skill` session was killed when the session
  driving this work was interrupted by an API 529 overload: it had sent 8 agent runs in 7
  batches, ended `clean` DONE and run `collect_19.py` (treatment check exit 0), but died
  while writing `transcript.md`, with no result event. Partial outputs are not graded; it was
  set aside in the scratchpad and rerun once, detached. The rerun is the graded run.
- Cost: `with_skill` 2439 s, 60 turns, 13 agent runs in 12 batches, $17.47; `old_skill`
  1089 s, 30 turns, 5 agent runs in 4 batches, $8.55. No permission denial in either result
  event. Profiler executors 81k–102k tokens each, 107–247 s.
- No blind comparison: both pass-rate gaps exceed 10 points and no row asks for one.

## After review: two corrections and a regrade

On the user's decision both proposed corrections were applied, and only those two items were
regraded, on the existing iteration-6 runs, both configurations, one Sonnet 5.5 grader each;
no executor was rerun. `validate` exits 0 on both sets; the iteration's manifest and
`eval_metadata.json` copies carry the new text.

- **Profiler eval 1 #11** no longer asks `transcript.md` to show the `uv run` command; it
  requires the round-0 `counts.json` the program writes (copied into `outputs/` by collect) to
  name every check id of the Checks table, beside `rawtrades.profile.py` holding each check as
  a query and `store-files.txt` listing `failing.parquet` and `counts.json`. `with_skill` fail
  → pass (its `counts.json` keys `checks` C1–C12, counts matching the table); `without_skill`
  stays fail (no program under `docs/sources/`, no `rounds/0/`). Profiler 30/30 vs 4/30.
- **Run-package eval 19 #28** now asks for a designer before the first tester, a tester before
  the first implementer, and two round-1 reviewers in one batch after the last round-1
  implementer, with `spec-change` detours as well as FIX rounds free to add calls between.
  `with_skill` fail → pass. `old_skill` fail → pass too: its five calls are designer, tester,
  implementer and two reviewers in one batch; it made no verify call, so the expectation's
  "after the verify call" holds over all its calls. The baseline still fails #1–#3 and every
  profiler expectation. Eval 19 45/46 vs 9/46.

**Known issue, not fixed here (eval 19 #42).** The driver's Summary block counts agent runs
from its own memory (`run-package` §Summary: "your own memory only: agent runs per role"): this
run's summary says `tester 3` where the stream shows four tester calls (batches 4, 6, 8, 11).
A fix likely means counting from records rather than memory — e.g. from what `status.py` or the
commits record — and is a candidate for 2.7.1. The expectation stays as written and fails.

## What still cannot be made strong, and what is untested

- **Untested in their new form** (expectations rewritten, not rerun): run-package evals 13,
  17 and 18 — 13 and 18 now need headless runs with `collect_stream.py`; profiler evals 4–7;
  architect eval 1.
- **Transcript-only checks that remain:** run-package eval 8 #4 and eval 17 #5 run as
  executor subagents with no stream, so their no-read clauses rest on `transcript.md`.
- **Self-reported sample record:** profiler `sample-ids.json` is still written by the
  executor; `build.py` checks every id against the data and the checks, and that the file came
  before the run's writes, but cannot prove the rows were judged rather than listed. The
  profiler proxy has no stream.

## Verdict

The three weaknesses are closed for the evals rerun: the sample checks pass on
`sample-check.txt` (eval 2 #6, which flipped on narration in phase 1, now passes on
evidence), eval 19's prompt and order checks read the stream, and the built `clean` is
checked row by row and its round-0 counts reproduced. As first graded, profiler 29/30 vs 4/30 and eval 19
44/46 vs 8/46. Of the three `with_skill` misses, two were checks still wrong (profiler 1 #11,
eval 19 #28), corrected after review and regraded: profiler 30/30 vs 4/30, eval 19 45/46 vs
9/46. The third, eval 19 #42, is a real driver miscount, recorded as a known issue for 2.7.1.
